## 第一课：分别调用 OpenAI 和 Claude

本课只完成一件事：用两种适配器分别发送一句话，并在终端看到回复。用户亲手执行安装、创建文件和编写代码，助手解释并检查结果。先理解模型调用；工具执行、会话历史、主备切换及 Agent 封装在后续课程加入。

### 1. 理解调用过程

```text
用户消息 → LangChain 模型适配器 → 对应模型服务 → 回复消息对象
```

| 服务协议            | 安装包                 | 创建的模型客户端 | 发送消息                  |
| ------------------- | ---------------------- | ---------------- | ------------------------- |
| OpenAI              | `@langchain/openai`    | `ChatOpenAI`     | `await model.invoke(...)` |
| Anthropic（Claude） | `@langchain/anthropic` | `ChatAnthropic`  | `await model.invoke(...)` |

适配器负责把统一的调用转换为对应服务的请求。模型客户端是一个服务调用对象，创建它不会把模型下载到本机；执行 `invoke()` 才会请求模型服务。

模型名称与协议分别确定。例如某个网关通过 OpenAI 兼容协议提供 Claude 模型，应按网关协议选择适配器；换一个模型名不会自动转换接口协议。本课分别演示 OpenAI 与 Anthropic 协议，不代表已验证所有兼容网关。

在 `template-agent` 根目录中手动创建 `.env.agent.local`，填写：


本课使用 Node 自带的 `--env-file` 读取文件，不需要另外调用 dotenv。后面的运行命令都在 `template-agent` 根目录下执行，环境文件与脚本路径相对于该目录解析；终端已设置的同名环境变量会优先于文件内容。

### 4. 手写 OpenAI 示例

创建 `scripts/agent-learning/` 目录，在其中创建 `openai.mjs`。使用 `.mjs` 是为了让 Node 直接运行 ESM 的 `import` 和顶层 `await`，暂时省去 TypeScript 执行配置；后续可以再迁入 TypeScript。

手写以下代码：

<!-- file: openai.mjs -->

```javascript
import { ChatOpenAI } from '@langchain/openai'

const apiKey = process.env.OPENAI_API_KEY
const modelName = process.env.OPENAI_MODEL

if (!apiKey || !modelName) {
  throw new Error('请配置 OPENAI_API_KEY 和 OPENAI_MODEL')
}

const model = new ChatOpenAI({
  apiKey,
  model: modelName,
})

const reply = await model.invoke('你好，请用一句话介绍自己。')

console.log(reply.content)
```

运行：

```powershell
vp node --env-file=.env.agent.local scripts/agent-learning/openai.mjs
```

逐段理解：

1. `process.env` 读取 Node 进程的环境变量；启动命令将本地配置加载进来。
2. 配置检查让缺少模型名或密钥时直接报错，避免误用适配器默认模型。
3. `new ChatOpenAI(...)` 创建 OpenAI 协议的模型客户端。
4. `invoke(...)` 发送这次用户消息，`await` 等待服务返回。
5. `reply` 是消息对象，`content` 保存回复内容，可能是字符串，也可能是内容块数组；本课先原样打印。

这里的字符串已经是 user prompt。下一课再加入 system prompt，区分“助手长期遵循的职责”和“用户这一次的问题”。

### 5. 手写 Claude 示例

在同一 `agent-learning/` 目录下创建 `claude.mjs`：

<!-- file: claude.mjs -->

```javascript
import { ChatAnthropic } from '@langchain/anthropic'

const apiKey = process.env.ANTHROPIC_API_KEY
const modelName = process.env.ANTHROPIC_MODEL

if (!apiKey || !modelName) {
  throw new Error('请配置 ANTHROPIC_API_KEY 和 ANTHROPIC_MODEL')
}

const model = new ChatAnthropic({
  apiKey,
  model: modelName,
  maxTokens: 1024,
})

const reply = await model.invoke('你好，请用一句话介绍自己。')

console.log(reply.content)
```

运行：

```powershell
vp node --env-file=.env.agent.local scripts/agent-learning/claude.mjs
```

与 OpenAI 示例相比，主要变化是适配器、配置变量以及 Claude 的最大输出 token 数。`maxTokens` 是输出预算，不等同于中文字数。先保持其余参数为默认值，部分较新的 Claude 模型会拒绝非默认的采样参数。

两种客户端都支持 `invoke()`，因此后续工具及编排可以围绕共同接口演进。本课先分开运行、分别观察，不加入选择服务的工厂或自动备用切换。每次运行会访问对应模型服务，按服务规则消耗额度；SDK 的默认重试也可能产生额外请求。

### 6. 需要自定义地址时再增加配置

使用官方默认服务时，可以跳过本节。使用自建服务或网关时，在环境文件中增加对应变量，地址以服务商提供的基础地址为准：

```dotenv
# 以下仅为地址格式示例，请替换为实际服务，不能原样调用
OPENAI_BASE_URL=https://openai-gateway.example.invalid/v1
ANTHROPIC_BASE_URL=https://anthropic-gateway.example.invalid
```

在 `ChatOpenAI` 的构造参数中增加：

```javascript
configuration: {
  baseURL: process.env.OPENAI_BASE_URL || undefined,
},
```

在 `ChatAnthropic` 的构造参数中增加：

```javascript
clientOptions: {
  baseURL: process.env.ANTHROPIC_BASE_URL || undefined,
},
```

这里填写基础地址，OpenAI 适配器默认使用 Chat Completions，通常由基础地址拼接 `/chat/completions`；Anthropic SDK 会拼接 `/v1/messages`。不要把完整调用端点填成基础地址；OpenAI 基础地址常包含 `/v1`，Anthropic 官方基础地址则不含该段，具体代理仍以其文档为准。

网关必须支持对应协议、认证方式与模型 ID。只支持 Responses API 的地址不能直接视为默认 Chat Completions 地址；这类差异在接入实际服务时单独核验。自定义地址是选择模型服务，自动 fallback 会在后续课程加入。

### 7. 本课完成标准与问题定位

- OpenAI 脚本独立运行，终端打印出回复内容。
- Claude 脚本独立运行，终端打印出回复内容。
- 能说明：适配器决定请求协议，模型 ID 决定请求哪个模型，密钥用于认证，`invoke()` 执行异步请求，`content` 是回复消息的一部分。
- 目前脚本每次只传入一句话，没有保存或重传前一轮消息，因此尚无连续会话记忆，也没有自主调用工具的循环。

常见错误：

| 现象                     | 优先检查                                                           |
| ------------------------ | ------------------------------------------------------------------ |
| `ERR_MODULE_NOT_FOUND`   | 是否在 server 包中安装依赖，以及脚本是否放在约定目录               |
| 缺少模型／密钥的本地错误 | 环境文件位置、变量名、占位值是否替换，以及终端同名变量是否覆盖文件 |
| 401／403                 | 密钥、账户权限及网关认证方式                                       |
| 404 或模型不可用         | 模型 ID、账户可用范围、基础地址及协议                              |
| 429                      | 服务限流或账户额度；以服务端错误说明为准                           |
| 400 参数错误             | 协议、模型能力及服务端指出的不支持参数                             |

练习后可以提供两条命令的运行结果或脱敏错误。不要粘贴密钥、完整环境文件或认证请求头；无需在本课启动 NestJS、数据库或 Redis。
