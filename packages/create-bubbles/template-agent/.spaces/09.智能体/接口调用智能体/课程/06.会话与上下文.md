# 第六课：threadId、消息历史与可信上下文

状态：完整教学资料。前置：[第五课](./05.MCP接入.md)。[返回课程入口](../学习教程.md)。

## 先回答之前的疑问

| 概念     | 在这个实例中的含义         | 例子                        |
| -------- | -------------------------- | --------------------------- |
| agentId  | 哪种助手                   | report-helper               |
| threadId | 同一个人的哪段连续对话     | report-chat-1               |
| runId    | 一次任务执行               | 每次提交生成的新 UUID       |
| context  | 宿主验证的调用者及业务信息 | 用户、租户、权限、当前项目  |
| messages | 实际发送给模型的历史消息   | 用户问题、AI 回复、工具结果 |

模型不会自动记住 Node 进程中上一轮的内容；连续对话是程序保存消息，再把相应历史传给模型。context 则首先给程序做身份和权限判断，不应自动全部拼进提示词。

## 1. 给已有循环加一个进程内会话层

文件：`common/memory-chat.mjs`，相对于 `scripts/agent-learning/`。

<!-- file: common/memory-chat.mjs -->

```javascript
import { randomUUID } from 'node:crypto'
import { SystemMessage, HumanMessage } from '@langchain/core/messages'
import { runLoop } from './loop.mjs'

/** 创建当前进程内的会话层；同一会话并发提交直接拒绝，失败不覆盖旧历史。 */
export function createMemoryChat({ models, tools = [], systemPrompt }) {
  const histories = new Map()
  const busy = new Set()

  /** 使用宿主身份加会话编号定位历史，避免用户之间复用同一 threadId。 */
  function sessionKey({ context, threadId }) {
    if (!context?.tenantId || !context?.userId) throw new Error('缺少可信身份')
    return JSON.stringify([context.tenantId, context.userId, threadId])
  }

  return {
    /** 追加一条用户消息；context 供程序使用，不自动发给模型。 */
    async say({ text, threadId = randomUUID(), context, signal }) {
      const key = sessionKey({ context, threadId })
      if (busy.has(key)) throw new Error('同一会话正在执行')
      busy.add(key)
      try {
        const result = await runLoop({
          models,
          tools,
          signal,
          messages: [
            new SystemMessage(systemPrompt),
            ...(histories.get(key) ?? []),
            new HumanMessage(text),
          ],
        })
        histories.set(key, result.messages.slice(1))
        return { runId: randomUUID(), threadId, reply: result.reply }
      } finally {
        busy.delete(key)
      }
    },

    /** 删除当前调用者自己的一段会话历史。 */
    forget({ threadId, context }) {
      const key = sessionKey({ context, threadId })
      if (busy.has(key)) throw new Error('执行中不能删除会话')
      histories.delete(key)
    },
  }
}
```

真实 HTTP 服务的 context 应来自已经验证的 Session／Token，再校验租户和项目权限；浏览器自报一个 userId 不能作为身份依据。本课还没有新增 HTTP 接口，下面的身份仅为本地虚构示例。

## 2. 连续提问并检查隔离

文件：`06-memory.mjs`。

<!-- file: 06-memory.mjs -->

```javascript
import { createModel } from './common/model.mjs'
import { createMemoryChat } from './common/memory-chat.mjs'
import { messageText } from './common/text.mjs'

const chat = createMemoryChat({
  models: [createModel()],
  systemPrompt: '你是报告助手。只引用本段对话已提供的事实，未知就说明未知。',
})
const context = { tenantId: 'demo-tenant', userId: 'demo-user' }
const first = await chat.say({
  text: '本月目标是完成 100 项工作。请记下这个目标。',
  threadId: 'report-chat-1',
  context,
})
console.log('第一轮：', messageText(first.reply))

const second = await chat.say({
  text: '刚才说的本月目标是多少？',
  threadId: 'report-chat-1',
  context,
})
console.log('同一会话：', messageText(second.reply))

const isolated = await chat.say({
  text: '刚才说的本月目标是多少？',
  threadId: 'report-chat-1',
  context: { tenantId: 'demo-tenant', userId: 'another-demo-user' },
})
console.log('另一用户：', messageText(isolated.reply))
```

## 3. 为什么不能把 context 直接当 prompt

假设 context 包含 `permissions: ['report:read']`。工具执行前应由程序检查这项权限；即使模型在回复中说“我有删除权限”，也不能允许删除。需要让模型理解当前项目时，只传项目显示名称等已筛选业务信息，鉴权仍在程序中完成。

同一个 Agent 可以处理许多 thread；不把聊天历史塞进 Agent 的全局 system prompt。子代理默认只接收父代理明确给出的任务和必要资料，后面再学习独立上下文。

## 观察、练习与排错

- 同一 context + threadId 第二轮应能引用 100；换 threadId 或 userId 后应没有这段历史。
- 程序重启后 Map 清空，这是当前进程内存方案的明确边界。
- 测试同一会话并发提交时应拒绝其中一个，避免两个请求同时覆盖历史。
- 工具循环失败后不会写入部分消息；真实写入工具已经发生的副作用不因此回滚。下一课采用检查点，将执行状态与消息历史一起管理。
- 历史会增长并消耗输入 token，长期运行需制定裁剪／摘要与保留策略，不能无限累加。

完成标准：能区分对话、一次执行和可信上下文；明白长期记忆、持久化数据库、聊天消息历史是不同能力。
