## 目标

看清“模型提出调用 → 程序校验并执行 → 把结果交回模型 → 模型继续”。模型只能提出结构化请求，真正执行函数的是你的后端程序。

## 1. 定义工具

文件：`common/math-tools.mjs`。所有示例文件都放在 `scripts/agent-learning/` 下。

<!-- file: common/math-tools.mjs -->

```javascript
import { tool } from '@langchain/core/tools'
import { z } from 'zod'

export const add = tool(({ a, b }) => JSON.stringify({ value: a + b }), {
  name: 'add',
  description: '计算两个有限数字的和，返回 value。',
  schema: z.object({ a: z.number().finite(), b: z.number().finite() }),
})

export const multiply = tool(({ a, b }) => JSON.stringify({ value: a * b }), {
  name: 'multiply',
  description: '计算两个有限数字的乘积，返回 value。',
  schema: z.object({ a: z.number().finite(), b: z.number().finite() }),
})

export const mathTools = [add, multiply]
```

`name` 是程序定位工具的标识，`description` 帮助模型判断何时使用，`schema` 描述并校验参数，函数体才是真正的执行逻辑。schema 不是鉴权，允许加法不意味着允许访问任意数据库。

## 2. 亲手实现循环

文件：`common/loop.mjs`。

<!-- file: common/loop.mjs -->

```javascript
import { ToolMessage } from '@langchain/core/messages'
import { invokeModels } from './invoke.mjs'

/** 执行有步骤上限的模型／工具循环，并返回包含工具结果的完整消息。 */
export async function runLoop({
  models,
  tools = [],
  messages,
  maxSteps = 6,
  signal,
  onTool = () => {},
}) {
  const history = [...messages]
  const directory = new Map(tools.map((item) => [item.name, item]))
  if (directory.size !== tools.length) throw new Error('工具名称重复')
  const boundModels = models.map((model) => (tools.length ? model.bindTools(tools) : model))

  for (let step = 0; step < maxSteps; step++) {
    signal?.throwIfAborted()
    const reply = await invokeModels({ models: boundModels, messages: history, signal })
    history.push(reply)
    if (!reply.tool_calls?.length) return { reply, messages: history }

    for (const call of reply.tool_calls) {
      signal?.throwIfAborted()
      const selected = directory.get(call.name)
      if (!selected || !call.id) throw new Error('无效或未授权的工具调用')
      onTool({ name: call.name, step })
      const value = await selected.invoke(call.args, { signal })
      history.push(
        new ToolMessage({
          content: typeof value === 'string' ? value : JSON.stringify(value),
          tool_call_id: call.id,
          name: call.name,
        }),
      )
    }
  }
  throw new Error('达到模型步骤上限，任务未完成')
}
```

每个工具结果关联 `tool_call_id`。缺少这层关联，模型无法可靠地把结果对应到自己发出的请求。不要把模型输出的任意函数名拿去执行，也不要使用 `eval`。

本课工具错误直接向上报告；以后若把参数错误反馈给模型自我修正，应返回明确的工具失败消息，并设置修正次数上限，不能把失败当成成功结果。

文件：`03-tools.mjs`。

<!-- file: 03-tools.mjs -->

```javascript
import { SystemMessage, HumanMessage } from '@langchain/core/messages'
import { createModel } from './common/model.mjs'
import { runLoop } from './common/loop.mjs'
import { mathTools } from './common/math-tools.mjs'
import { messageText } from './common/text.mjs'

const result = await runLoop({
  models: [createModel()],
  tools: mathTools,
  messages: [
    new SystemMessage('你是计算助手。算术必须调用工具，根据结果回答。'),
    new HumanMessage('先计算 12 + 8，再将结果乘以 3。'),
  ],
  signal: AbortSignal.timeout(30_000),
  onTool: ({ name, step }) => console.log('步骤', step, '执行工具', name),
})
console.log(messageText(result.reply))
```

```powershell
vp node --env-file=.env.agent.local scripts/agent-learning/03-tools.mjs
```

观察工具名称及最终值 60；工具调用顺序受模型规划影响。如果没有工具记录，说明这次模型没有遵循工具要求，需要检查提示词及模型是否支持工具调用，不能只看最终数字就判定调用成功。

## 3. 再认识 LangChain 的高层 Agent

文件：`03-agent.mjs`。

<!-- file: 03-agent.mjs -->

```javascript
import { createAgent } from 'langchain'
import { createModel } from './common/model.mjs'
import { mathTools } from './common/math-tools.mjs'
import { messageText } from './common/text.mjs'

const agent = createAgent({
  model: createModel(),
  systemPrompt: '你是计算助手。算术必须调用工具。',
  tools: mathTools,
})
const result = await agent.invoke(
  { messages: [{ role: 'user', content: '计算 (12 + 8) × 3。' }] },
  { recursionLimit: 20, signal: AbortSignal.timeout(30_000) },
)
console.log(messageText(result.messages.at(-1)))
```

```powershell
vp node --env-file=.env.agent.local scripts/agent-learning/03-agent.mjs
```

高层 `createAgent` 帮你管理循环。`recursionLimit` 限制图执行步数，与手写循环的“模型调用次数”不是一一对应。后面为了看清状态与预算，我们会显式搭建 LangGraph 图；不是每个项目都需要手写图。

## 练习与完成标准

1. 直接调用 `await add.invoke({ a: 1, b: 2 })`，确认工具脱离模型也可运行。
2. 把 a 改成字符串，观察 schema 校验失败；TypeScript 类型无法代替对运行时数据的校验。
3. 将 `maxSteps` 改成 1，观察任务可能因为尚需继续调用而失败。
4. 切换 OpenAI／Claude，验证同一个工具定义能被两种适配器使用；具体模型仍需支持 function calling。

完成标准：能说出“LLM 提议，程序执行”，并在消息历史中识别 human、ai 及 tool 消息。函数工具是行为入口，Skills 是任务做法，下一课把两者连接起来。
