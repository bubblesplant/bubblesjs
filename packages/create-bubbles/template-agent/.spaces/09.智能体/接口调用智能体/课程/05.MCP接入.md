# 第五课：通过 MCP 接入外部工具

状态：完整教学资料。前置：[第四课](./04.Skills目录.md)。[返回课程入口](../学习教程.md)。

## 目标

把一个独立进程提供的工具接入已有模型循环。MCP 解决工具发现和调用协议，模型是否调用、程序允许哪些工具，仍由 Agent 及宿主控制。

本课使用 `@langchain/mcp-adapters 2.0.3` 的 `MCPAdapter`。不要混用 1.x 教程中的 `MultiServerMCPClient/getTools`；2.x 使用 `MCPAdapter/listTools`。

```powershell
vp add -w -E @langchain/langgraph@1.7.4 @langchain/mcp-adapters@2.0.3 @modelcontextprotocol/sdk@1.32.2
```

SDK 1.32.2 用于本课自建的本地服务；适配器 2.x 自带客户端相关依赖。二者的角色不同。

## 1. 写一个本地 MCP 服务

文件：`mcp/math-server.mjs`，相对于 `scripts/agent-learning/`。

<!-- file: mcp/math-server.mjs -->

```javascript
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js'
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js'
import { z } from 'zod'

const server = new McpServer({ name: 'learning-math', version: '1.0.0' })
server.registerTool(
  'remote_add',
  {
    description: '在独立 MCP 进程中计算两个数字之和。',
    inputSchema: { a: z.number().finite(), b: z.number().finite() },
  },
  async ({ a, b }) => ({
    content: [{ type: 'text', text: JSON.stringify({ value: a + b, source: 'mcp' }) }],
  }),
)
await server.connect(new StdioServerTransport())
```

该进程通过 stdin/stdout 传 MCP 消息，不能用 `console.log` 写普通日志污染协议；需要日志时写 stderr。本课由适配器启动它，无需你手动开启第二个终端。

## 2. 封装连接与释放

文件：`common/mcp.mjs`。

<!-- file: common/mcp.mjs -->

```javascript
import { MCPAdapter } from '@langchain/mcp-adapters'

/** 建立本实例拥有的 MCP 连接；初始化失败时也释放已连接的资源。 */
export async function openMcp(servers) {
  const adapter = new MCPAdapter({ servers })
  try {
    const tools = await adapter.listTools()
    return { tools, close: () => adapter.close() }
  } catch (error) {
    await adapter.close()
    throw error
  }
}
```

## 3. 接入模型循环

文件：`05-mcp.mjs`。

<!-- file: 05-mcp.mjs -->

```javascript
import { fileURLToPath } from 'node:url'
import { createModel } from './common/model.mjs'
import { openMcp } from './common/mcp.mjs'
import { runLoop } from './common/loop.mjs'
import { messageText } from './common/text.mjs'

const connection = await openMcp({
  math: {
    command: process.execPath,
    args: [fileURLToPath(new URL('./mcp/math-server.mjs', import.meta.url))],
    transport: 'stdio',
  },
})
try {
  console.log(
    '发现工具：',
    connection.tools.map((item) => item.name),
  )
  const result = await runLoop({
    models: [createModel()],
    tools: connection.tools,
    messages: [
      { role: 'system', content: '遇到加法必须使用外部 MCP 工具。' },
      { role: 'user', content: '请计算 18 + 24。' },
    ],
    signal: AbortSignal.timeout(30_000),
    onTool: ({ name }) => console.log('执行', name),
  })
  console.log(messageText(result.reply))
} finally {
  await connection.close()
}
```

```powershell
vp node --env-file=.env.agent.local scripts/agent-learning/05-mcp.mjs
```

观察发现的工具名及结果 42，实际前缀以打印结果为准。适配器默认会为工具加服务名前缀，后续仍应检查名称冲突。

## 4. 远程 HTTP MCP 的配置形式

把服务列表中的一项换成实际、已授权的 HTTP 服务即可，例如：

```javascript
const servers = {
  knowledge: {
    url: process.env.LEARNING_MCP_URL,
    transport: 'http',
  },
}
```

这里的变量必须是 MCP 服务地址，不是普通 REST API 地址。带认证的服务还需按适配器文档配置对应请求头／凭证；不把认证信息写进 system prompt。旧 SSE 服务显式使用 `transport: 'sse'`，不能把任意 HTTP 响应视为 MCP。

`stdio` 会启动本地程序，命令只能来自可信后端配置，不让模型或普通用户任意指定。HTTP MCP 和本地进程各自的生命周期及权限需要分别管理。

## 观察、练习与完成标准

- 先用 `connection.tools.find(...).invoke({ a: 1, b: 2 })` 检查连接，排除模型能力问题。
- 在工具名输出中辨认服务前缀，比较本地函数与远程工具的来源。
- 在 `runLoop` 中同时注册 `mathTools` 与 MCP 工具，确认程序能区分它们，重名应拒绝。
- 故意填写不存在的脚本路径，观察连接失败；修复后重试。初始化失败也要释放此前连接的资源。
- 将第三／四课的 Skills 工具一起加入同一个 `tools` 数组，验证技能做法与 MCP 执行能力可以组合。

完成标准：同一个 Agent 循环可消费本地函数和 MCP 适配出的工具，结束时关闭自己创建的连接。外部传入、被多个 Agent 共用的连接不能由每个使用者随意关闭。
