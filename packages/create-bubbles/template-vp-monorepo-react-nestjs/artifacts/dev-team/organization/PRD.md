## 2. 背景与现有系统基线

现有系统已经具备平台、企业、项目三级工作空间及 AccessScope，拥有全局账号、企业成员、项目成员、企业／项目角色、菜单权限、作用域鉴权和审计能力。组织能力应建立在这些模型之上，不新增第四种访问作用域，也不替换现有成员与 RBAC 角色。

只读盘点确认了以下实现基线：

| 领域       | 当前实现                                                                | 本期衔接点                                           |
| ---------- | ----------------------------------------------------------------------- | ---------------------------------------------------- |
| 全局账号   | users.id 是全局用户标识；account 全局唯一；name 不唯一                  | 所有人员选择与关系最终使用 userId，不以姓名识别人员  |
| 作用域     | shared 已定义 platform、company、project 三种 AccessScope               | 组织能力只使用 company 与 project 作用域             |
| 成员       | 已有 company_members 与 project_members，项目成员受所属企业成员资格约束 | 组织归属和岗位任职必须绑定既有成员关系               |
| 权限       | 已有 roles、user_roles、权限目录、路由鉴权和审计                        | 组织、岗位本身不授予权限；管理动作继续通过 RBAC 授权 |
| 企业与项目 | 项目保存直接所属 companyId；企业、项目已有启停和管理员规则              | 扩展企业层级及企业／项目各自的组织能力               |
| Web 页面   | 企业、项目分别有独立工作空间路由和成员／角色页面                        | 新增企业与项目各自的“人员与组织”管理入口             |
| 选择器     | 已有 BasicTableSelector 与返回全局 userId 的 GlobalAccountSelect        | 复用全局账号选择器，新增组织成员选择器               |
| 组织数据   | 当前没有企业层级字段、组织树、岗位、模板或相关接口                      | 均为本期新增领域能力                                 |

当前共享请求仍有以完整账号添加成员、指定管理员的既有契约，而 GlobalAccountSelect 的稳定值是 userId。两种标识如何衔接必须在契约阶段统一，不能由各页面自行混用。

## 3. 背景问题与产品目标

### 3.1 要解决的问题

1. 集团、独立企业、企业内部层级和项目执行组织容易混成一棵没有权限边界的通用树。
2. 企业希望维护通用的项目组织标准，但不同项目又需要在创建后独立调整。
3. 同一个成员可能同时属于多个组织单元、担任多个岗位，现有成员和角色模型无法表达这些业务关系。
4. 岗位、组织归属和权限角色容易被误认为同一概念，导致组织调整时意外改变系统权限。
5. 人员选择既需要企业／项目范围、组织、岗位和角色辅助定位，也必须保持全局账号唯一和作用域隔离。
6. 后续项目流程需要引用企业组织目标，但当前阶段不应为了未来工作流提前交付一个不完整的审批引擎。

### 3.2 本期目标

1. 建立集团／企业主体层级，以及彼此隔离的企业组织树和项目组织树。
2. 提供组织单元创建、维护、移动、整数排序、停用／恢复和成员分配能力。
3. 提供与组织单元完全独立的企业岗位库和项目岗位库，支持一人多岗、一岗多人。
4. 支持企业成员、项目成员分别加入多个本作用域组织单元，且不存在主归属或默认组织。
5. 提供企业维护的项目组织模板，使项目可从标准结构初始化后独立演进。
6. 提供可复用的组织成员选择能力，并继续区分全局账号选择、具体成员选择和未来工作流目标选择。
7. 沿用现有 AccessScope、成员资格、RBAC、审计及 401／403／404 安全边界。
8. 为后续企业目标发布、工作流目标解析和任务级授权保留稳定引用边界，但不在本期实现完整工作流。

### 3.3 成功结果

- 管理员能够在对应工作空间维护组织、岗位、成员关系和模板，而不会意外改变成员权限。
- 同一账号在企业及不同项目中的组织、岗位关系分别维护，跨作用域关系无法写入。
- 项目可以按明确选择的模板版本初始化，也可以空白创建；之后不会被模板后台静默改写。
- 选择器能在服务端授权范围内查找具体人员，同名人员和同名组织均可可靠区分。
- 本期交付不产生“项目小组”、主归属、岗位挂组织、工作流半成品等额外概念。

## 4. 本期范围与明确不做

### 4.1 本期范围

| 能力组     | 本期交付                                                                         |
| ---------- | -------------------------------------------------------------------------------- |
| 企业层级   | 集团／企业主体的父子层级、展示类型、同级排序、循环校验及可见层级查询             |
| 企业组织   | 每个企业自己的组织树、组织单元维护、移动、状态、整数 sort、完整路径              |
| 项目组织   | 每个项目自己的组织树，与企业树和其他项目树隔离                                   |
| 成员关系   | 企业成员多企业组织单元、项目成员多项目组织单元、组织负责人、未归属视图           |
| 岗位       | 企业／项目平面岗位库、岗位状态、成员多岗位任职                                   |
| 组织模板   | 企业维护项目组织模板，分别复制组织结构和项目岗位定义                             |
| 管理页面   | 企业／项目工作空间中的组织架构、岗位、成员管理页面                               |
| 选择器     | 复用 GlobalAccountSelect；新增 OrganizationMemberSelector 及受权限保护的候选查询 |
| 权限与审计 | 组织、岗位、模板、成员分配动作的权限拆分、作用域校验、事务和审计                 |
| 后续边界   | 稳定组织单元、岗位、成员的 ID、作用域、状态与完整路径查询语义                    |

### 4.2 明确不做

- 不新增项目小组、协作组或类似实体；稳定结构使用项目组织单元，临时协作由具体业务选择成员。
- 不设置主归属、默认组织、首选组织或兼任归属；不得根据数组第一项、提交顺序、展示顺序推导特殊组织关系。
- 岗位不关联组织单元；岗位、模板岗位和任职关系均不保存组织单元字段。
- 组织单元、岗位不会自动创建、分配或撤销 RBAC 角色。
- 不实现完整工作流引擎、表单设计器、条件表达式、会签、转交、流程实例和附件授权。
- 本期不实现 WorkflowTargetSelector、企业目标发布管理、运行时接收人解析或任务级资源授权；这些进入单独的工作流阶段。
- 不支持跨企业、跨项目移动组织单元。
- 首期不要求拖拽组织树；移动通过显式选择目标父级和 sort 完成。
- 不把企业组织树实时映射为项目组织树，不做模板对已有项目的后台自动同步。
- 不改变现有上传数据的 ownerId 授权模型。
- 未确认物理删除规则前，本期只定义创建、修改、移动、停用和恢复，不自行增加删除语义。

## 5. 核心概念与已确认产品原则

| 概念           | 产品含义                                                 | 权限含义                       |
| -------------- | -------------------------------------------------------- | ------------------------------ |
| 企业主体       | 集团或独立企业的业务与数据边界，拥有独立 companyId       | 继续使用 company 作用域        |
| 企业组织单元   | 企业内部可嵌套的通用组织节点，如事业部、中心、部门、班组 | 不是新作用域，不直接授予权限   |
| 项目组织单元   | 项目内部可嵌套的执行组织节点                             | 不是新作用域，不直接授予权限   |
| 企业／项目成员 | 全局账号与对应企业／项目的既有成员关系                   | 是组织归属和岗位任职的资格前提 |
| 企业／项目岗位 | 对应作用域中的平面业务任职，如董事、项目经理、资料员     | 不进入组织树，不直接授予权限   |
| 权限角色       | 现有 RBAC 权限集合                                       | 决定页面、按钮和接口权限       |
| 组织模板       | 企业维护的项目组织结构和项目岗位定义快照来源             | 不复制成员、负责人、任职或角色 |

以下原则已经由用户明确，不再作为可选设计：

1. 企业组织树与项目组织树分开，界面可以聚合展示，数据库不建立跨树父子关系。
2. 企业成员可加入多个企业组织单元，项目成员可加入当前项目的多个项目组织单元。
3. 所有组织成员关系地位相同；没有主归属、默认组织或根据顺序推导的特殊关系。
4. 不建设项目小组。
5. 企业岗位和项目岗位保留，但岗位不关联组织单元。
6. 一名成员可以在同一作用域担任多个岗位，一个岗位可以有多名成员。
7. 组织单元 sort 只保存和编辑一个非负整数，不拆分输入、不使用小数。
8. 每个组织单元最多一名主要负责人；同一个人可以负责多个组织单元。
9. 平台账号以全局 userId 唯一识别，姓名不唯一。
10. 组织归属、岗位和权限角色相互独立。

## 6. 核心角色与用户故事

| 编号  | 角色             | 用户故事与可观察结果                                                                                                         |
| ----- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| US-01 | 平台组织维护者   | 我可以在授权范围内查看和维护集团／企业主体层级，调整上级、展示类型和排序，且不能形成循环或获得隐式的下级企业权限。           |
| US-02 | 企业组织维护者   | 我可以在当前企业工作空间维护企业组织树，不会修改项目组织树、上级集团或其他企业的数据。                                       |
| US-03 | 项目组织维护者   | 我可以在当前项目工作空间维护项目组织树，不能把节点移动到企业树或其他项目。                                                   |
| US-04 | 成员维护者       | 我可以把一个有效成员分配到多个本作用域组织单元，并为每条关系维护职责；系统不会创建主归属。                                   |
| US-05 | 组织负责人维护者 | 我可以为组织单元设置主要负责人；第二名主要负责人会被事务性拒绝，同一人可以负责多个组织单元。                                 |
| US-06 | 岗位维护者       | 我可以独立维护企业／项目岗位并为成员批量分配多个岗位；组织变化不会自动改变岗位。                                             |
| US-07 | 企业模板维护者   | 我可以维护项目组织模板，模板内的组织结构与项目岗位定义互相独立。                                                             |
| US-08 | 项目创建者       | 我可以空白创建项目或明确选择企业模板版本初始化；创建后项目组织由项目独立维护。                                               |
| US-09 | 业务选人者       | 我可以按可见企业／项目、组织、岗位、权限角色和搜索条件找到具体成员；选择结果以 userId 为核心。                               |
| US-10 | 普通成员         | 我可以在有权查看的页面中看到自己的全部组织和岗位标签，不会被标记为某个“主组织”。                                             |
| US-11 | 审计查看者       | 我可以在既有审计边界内查看组织、岗位、模板和成员关系变更，不会在日志中看到密码或 token。                                     |
| US-12 | 后续流程设计者   | 后续工作流可以引用稳定的组织单元、岗位和成员目标，但必须另行实现企业发布、解析和任务级授权，不能把组织成员资格当作流程授权。 |

## 7. 功能需求

本节同时包含“已确认原则的展开”和“设计源待确认项的推荐落法”。凡关联第 13.2 节 Q 编号的内容，在用户确认前只是本 PRD 的建议基线，不授权开发先行实现；确认时若方案变化，应同步调整对应功能需求和验收标准。

### FR-01 企业主体层级

1. 集团和独立企业继续共用现有 company 作用域及 companyId，不新增 group 作用域。
2. 按设计推荐，通过企业的直接上级关系形成企业主体树，展示类型只表达集团／企业语义，不自动改变权限。
3. 项目仍只归属一个直接企业；上级集团、兄弟企业和子企业不会因此同时拥有项目。
4. 创建或调整上级时必须拒绝自身作为父级、后代作为父级及任何完整循环。
5. 调整企业上级不迁移成员、角色、数据、项目或审计归属，不产生权限继承。
6. 企业层级查询只返回调用者有权查看的节点；不能因为父节点可见就默认泄露全部下级企业。
7. 企业同级排序沿用一个整数 sort；其具体范围和默认生成规则在契约阶段按待确认项定稿。

### FR-02 企业与项目组织树

1. 每个企业拥有自己的企业组织树，每个项目拥有自己的项目组织树。
2. 企业或项目本身作为界面虚拟根，真实顶级组织单元没有持久化的根节点记录。
3. 企业组织单元的父级只能是同一企业树的组织单元；项目组织单元的父级只能是同一项目树的组织单元。
4. 组织单元至少包含稳定 ID、所属树、父级、名称、编码、说明、sort、状态和版本；普通查询返回当前完整路径。
5. 允许不同分支出现同名组织单元；所有选择和展示必须带所属企业／项目及完整路径，不能只显示末级名称。
6. 组织单元支持创建、编辑、移动、停用和恢复。移动保持 ID 不变，禁止移动到自身或后代。
7. 停用组织单元保留节点、成员关系和历史引用；其自身及后代的有效性规则按第 9 节执行。
8. 企业组织树、各项目组织树可以在浏览器或选择器中聚合展示，但聚合位置不改变真实父子关系。

### FR-03 组织单元排序

1. 企业与项目组织单元只保存一个整数 sort，允许范围为 0～999999999。
2. 前端只显示一个整数输入框，编辑时原值回显并原样提交；拒绝负数、小数和超范围值。
3. 排序仅在同一棵树、同一父级下比较，统一按 sort 升序、ID 升序返回。
4. 相同 sort 合法，由 ID 保证稳定顺序；修改单个节点不自动重排其他节点。
5. 首个同级节点默认 sort 为 1，其余默认为同级最大 sort 加一；达到上限时停止自动递增并要求人工调整。
6. 移动时允许明确填写新 sort；未填写时排到目标父级最后，并使用下一个可用整数。

### FR-04 组织成员关系

1. 企业组织关系绑定有效 company_member；项目组织关系绑定有效 project_member。
2. 一个成员可以在本作用域拥有多条不同组织单元关系，但同一成员与同一组织单元的关系只能有一条。
3. 全部组织关系地位相同；请求和响应不得包含主归属、默认组织字段，后端不得把数组第一项解释为特殊关系。
4. 成员可以暂时不属于任何组织单元；“未归属组织”只作为查询和界面的虚拟分组，不创建数据库节点。
5. 关系可保存职责和可选的单元内成员展示排序。主要负责人必须是该组织单元的成员关系。
6. 每个组织单元最多一名主要负责人；唯一限制建立在组织单元上，不能限制同一个人负责多个组织单元。
7. 设计源推荐职责支持普通成员、主要负责人和副负责人；副负责人是否首期启用见 Q-03。
8. 批量替换成员组织关系必须在同一事务内完成；任一跨作用域、重复关系或负责人冲突都使整次提交失败。
9. 组织关系变化不会自动创建、删除或修改成员的 RBAC 角色和岗位任职。

### FR-05 独立岗位

1. 企业岗位只属于一个企业，项目岗位只属于一个项目；岗位不属于组织树。
2. 岗位是平面列表，不设置父级，也不保存组织单元 ID、树 ID或模板组织节点 ID。
3. 岗位至少包含稳定 ID、作用域、名称、编码、说明、状态和版本。
4. 企业岗位任职绑定企业成员，项目岗位任职绑定项目成员；一个成员可以多岗，一个岗位可以多人。
5. 同一成员不能重复担任同一岗位，跨企业、跨项目任职必须被拒绝。
6. 组织归属和岗位任职分别维护、分别提交、分别审计；任意一方的新增、移动、停用或移除不自动修改另一方。
7. 岗位不会自动映射现有权限角色，也不能仅凭岗位推导某个组织单元中的任职。

### FR-06 项目组织模板

1. 模板属于一个企业，用于初始化该企业直接所属项目的项目组织，而不是实时引用企业组织树。
2. 模板分别维护组织单元结构和项目岗位定义；模板岗位不关联模板组织单元。
3. 项目初始化支持空白和选择模板两类模式。前端可以推荐默认模板，但提交必须明确写明选择模式；模板模式同时提交模板 ID 和版本。
4. 复制组织单元名称、编码、层级和 sort；复制岗位名称、编码、说明和状态。新项目中的组织单元与岗位分别生成新 ID。
5. 模板不复制真实成员、负责人、组织成员关系、岗位任职或权限角色。
6. 项目创建后独立维护；模板后续修改或停用不自动改写已有项目。
7. 来源模板节点和来源模板岗位分别记录各自来源，不建立岗位与组织单元的映射。
8. 默认模板、版本冲突、现有项目补建空白组织的迁移策略按第 13 节确认。

### FR-07 组织成员选择器

1. GlobalAccountSelect 继续服务于平台开通企业、设置企业管理员等“候选人可能尚未成为企业成员”的全局账号场景，稳定值为 userId。
2. 新增 OrganizationMemberSelector，用于在服务端授权的组织范围内选择一个或多个具体成员。
3. 选择器由业务注入当前调用场景和候选查询，不自行决定接口地址、权限范围或保存行为。
4. 左侧可按可见作用域、组织架构、岗位或权限角色筛选，右侧选择具体人员；点击组织单元只筛选人员，不把组织单元本身作为成员选择值。
5. 企业工作空间可查看本企业及有权管理／查看的本企业项目；项目工作空间默认只查看当前项目及后续明确发布的企业目标，不浏览同企业其他项目组织。
6. 搜索由服务端执行，支持姓名或完整账号；结果按全局 userId 去重，同一人只显示一行并聚合可见身份、组织、岗位、必要角色和状态。
7. 姓名不作为唯一标识；人员行至少显示姓名、完整账号、来源企业／项目和状态。
8. 同名组织单元必须显示“企业／项目 + 完整路径”；组织标签和岗位标签分开展示，交叉筛选不会生成持久关系。
9. 停用账号、停用成员或停用作用域显示状态和禁选原因，不静默变成可选。
10. 一般选人返回 userId；业务必须保留以哪个企业／项目身份选择时，返回 userId 与明确作用域，不能返回临时表格行号。
11. 选择操作本身不创建成员、组织关系、岗位任职或角色授权。
12. WorkflowTargetSelector 与组织目标联合类型留到工作流专项，不并入本期具体成员选择器。

### FR-08 管理页面

1. 企业和项目分别从自己的工作空间进入“人员与组织”，页面内部不维护第二套企业／项目作用域状态。
2. 页面以“组织架构、岗位、成员”作为并列入口；岗位不挂在组织树节点下。
3. 组织架构页提供树、全部成员、未归属组织、组织详情、负责人、成员表和创建／编辑／移动／停用／恢复操作。
4. 岗位页使用平面列表，展示名称、编码、状态和任职人数；岗位表单不提供组织单元字段。
5. 成员页展示成员在当前作用域的全部组织和岗位标签，不突出第一个组织，也不拼接未保存的“组织－岗位”关系。
6. 成员分配中，组织归属和岗位任职分区编辑；修改一组不会自动修改另一组。
7. 组织单元表单只提供一个 sort 整数输入框；首期移动使用显式弹窗，不要求拖拽。

### FR-09 权限、事务与审计

1. 查看组织、维护结构、移动组织、分配成员、维护岗位、分配岗位和维护模板应按能力拆分，不能只靠页面是否显示进行授权。
2. 后端继续按登录态、账号状态、作用域与成员资格、功能权限、资源归属的顺序校验；URL 参数不是授权依据。
3. 企业、项目、组织单元、成员、岗位和模板的所有写操作必须同时校验资源所属作用域。
4. 跨企业或跨项目资源与不存在资源继续统一返回 404；作用域内已识别的权限不足返回 403。
5. 批量关系替换、负责人变更、模板复制和相关成功审计在同一事务内提交。
6. 组织单元、岗位和模板使用版本校验避免过期编辑覆盖；具体冲突响应由共享契约统一。
7. 组织、岗位、模板及成员关系的创建、编辑、移动、排序、状态、分配和移除写入现有作用域审计。
8. 审计记录操作者、作用域、对象、关键变更前后值和 requestId，不记录密码、token 或不必要的完整业务数据。

## 8. 权限边界

### 8.1 角色边界

- 平台管理员只有在平台入口及明确权限下维护企业主体层级或查看跨企业摘要；平台身份不自动成为任何企业成员。
- 企业管理员或具备对应企业权限的角色只能管理当前企业的组织、岗位、模板和成员关系。管理父集团、子企业或兄弟企业仍需目标企业的显式权限。
- 项目管理员或具备对应项目权限的角色只能管理当前项目组织、岗位和成员关系，不能修改企业组织树。
- 普通成员只获得角色明确授予的查看或操作能力；加入组织、担任岗位、成为负责人均不自动授予管理员权限。
- 企业父子关系不继承成员、管理员、角色、数据或审计权限。

### 8.2 能力拆分草案

现有权限目录的最终 key 在契约阶段统一。本期至少保持以下能力互相独立：

| 作用域   | 能力                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 平台     | 查看企业层级、创建企业、编辑企业层级资料、移动企业、调整企业排序       |
| 企业     | 查看组织、创建组织单元、更新／停用组织单元、移动组织单元、分配组织成员 |
| 企业     | 查看岗位、创建岗位、更新／停用岗位、分配岗位成员                       |
| 企业     | 查看与维护项目组织模板                                                 |
| 项目     | 查看组织、创建组织单元、更新／停用组织单元、移动组织单元、分配组织成员 |
| 项目     | 查看岗位、创建岗位、更新／停用岗位、分配岗位成员                       |
| 候选查询 | 按调用场景读取最小成员、组织、岗位或角色摘要                           |

设计真相源已给出 company.organization、company.position、project.organization、project.position 等权限建议。企业层级和模板的准确权限 key、内置管理员自动授权及菜单节点由契约阶段结合现有 ACCESS_PERMISSION_CATALOG 定稿，不能由前后端分别命名。

## 9. 生命周期规则

| 对象／操作     | 必须保留                                   | 本期行为                                                                                             |
| -------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 调整企业上级   | companyId、成员、角色、项目、数据、审计    | 只改变主体导航层级；禁止循环，不迁移或继承权限                                                       |
| 移动组织单元   | 组织单元 ID、成员关系、岗位独立性          | 仅同一棵树内移动；当前 fullPath 随结构更新                                                           |
| 停用组织单元   | 节点、下级节点、成员关系、历史审计         | 自身及受无效祖先影响的下级不参与新候选；不自动删除关系                                               |
| 恢复组织单元   | 原节点和关系                               | 重新参与后续有效查询，不改写历史审计                                                                 |
| 停用岗位       | 岗位、任职关系、历史审计                   | 不参与新的有效候选；保留任职关系                                                                     |
| 恢复岗位       | 原岗位和任职                               | 重新参与后续有效查询                                                                                 |
| 停用成员       | 组织关系、岗位任职、角色按现有成员规则保留 | 不再作为有效候选；恢复后按当前保存关系参与查询                                                       |
| 移除项目成员   | 历史审计                                   | 同一事务清理该项目成员的项目组织关系、岗位任职、负责人关系和项目角色                                 |
| 移除企业成员   | 历史审计及其他企业中的独立关系             | 同一事务清理本企业组织、岗位、负责人和角色，并按现有规则清理本企业直接所属项目中的项目成员及关联关系 |
| 修改或停用模板 | 已创建项目自己的组织与岗位                 | 不自动同步或删除项目数据                                                                             |
| 创建项目       | 既有项目创建事务边界                       | 按明确的空白／模板选择初始化组织与岗位；任一步失败整体回滚                                           |

组织单元停用时下级有效性的查询和界面表现沿用“任一祖先无效则当前节点不作为有效候选”的设计推荐；是否允许管理者在停用父节点下单独编辑子节点列入契约阶段细化。

## 11. 可测试验收标准

以下标准用于让本 PRD 的建议方案具备可验收性。其中标注“依赖 Q-xx”的条目，在对应待确认项定稿前不作为实施完成门槛；用户确认本 PRD 时应选择接受推荐方案或同步改写该条验收。

1. **AC-01 全局人员标识**：准备两个同名账号后，所有组织和岗位分配均以不同 userId 正确区分；任何接口都不以姓名作为唯一键。
2. **AC-02 作用域保持**：交付后 AccessScope 仍只有 platform、company、project；组织单元和岗位不会产生新的工作空间或访问作用域。
3. **AC-03 企业层级展示（依赖 Q-01、Q-11）**：具有权限的操作者能查询集团／企业主体层级、直接上级、展示类型和同级排序；无权节点不因其祖先可见而被返回。
4. **AC-04 企业循环保护（依赖 Q-01）**：把企业设为自身父级或其后代的父级时，服务端拒绝且企业层级、成功审计均不发生部分变更。
5. **AC-05 企业层级不继承权限（依赖 Q-02）**：把 B 企业移动到 A 集团下后，A 集团成员不会自动成为 B 企业成员、管理员或获得 B 企业数据权限。
6. **AC-06 项目直接归属（依赖 Q-01、Q-02）**：企业层级调整后，项目仍只保存原直接 companyId，不自动增加父集团或兄弟企业归属。
7. **AC-07 企业项目分树**：同一企业及其项目分别查询到独立组织树；企业节点不能成为项目节点父级，项目节点也不能成为企业节点父级。
8. **AC-08 跨树写入拒绝**：跨企业、跨项目创建父子关系或移动组织单元时返回统一的资源不可见结果，原树保持不变。
9. **AC-09 完整路径区分（依赖 Q-04）**：两个不同分支创建同名组织单元后，列表和选择器均返回所属企业／项目与完整路径，可明确区分两者。
10. **AC-10 整数排序**：sort 为 15 时接口与数据库保存 15；负数、小数和大于 999999999 的值被拒绝，同级始终按 sort 升序、ID 升序返回。
11. **AC-11 默认排序**：首个同级组织单元默认 sort 为 1，后续默认使用当前同级最大值加一；达到上限时不产生溢出值。
12. **AC-12 移动排序**：组织单元移动到同树其他父级时保持 ID；明确 sort 按提交值保存，未提交时排在目标同级最后。
13. **AC-13 多组织关系**：同一企业成员可以加入多个企业组织单元，同一项目成员可以加入当前项目多个项目组织单元，企业与各项目的关系互不覆盖。
14. **AC-14 无主归属**：组织分配请求、响应、数据库和界面均不存在主归属或默认组织；交换提交数组顺序不会改变任一关系语义。
15. **AC-15 关系唯一**：重复提交同一成员与同一组织单元的关系不会产生两条记录；跨作用域成员关系整批失败且不留下部分数据。
16. **AC-16 主要负责人唯一**：同一组织单元设置第二名主要负责人时整次写入失败；同一个人可以成功成为多个组织单元的主要负责人。
17. **AC-17 负责人资格（依赖 Q-03）**：非当前组织单元成员不能直接成为主要负责人；设置负责人不会新增管理员角色或权限。
18. **AC-18 未归属视图**：没有任何组织关系的有效成员出现在“未归属组织”虚拟分组中，数据库不存在对应虚拟组织单元记录。
19. **AC-19 岗位完全独立**：岗位定义、模板岗位和岗位任职请求／响应不包含 organizationUnitId、treeId 或 templateUnitId；传入此类字段时明确拒绝。
20. **AC-20 多岗位任职**：同一成员可同时担任多个岗位，一个岗位可包含多名成员；重复任职和跨作用域任职被拒绝。
21. **AC-21 组织岗位解耦**：移动、停用或移除一条组织关系不会自动修改岗位任职；修改岗位任职也不会改变组织归属或角色。
22. **AC-22 模板初始化方式（依赖 Q-05）**：创建项目时可以明确选择空白或指定模板；模板模式缺少模板 ID／版本、模板不属于直接企业或版本过期时整体失败。
23. **AC-23 模板复制边界（依赖 Q-05）**：模板初始化只复制组织结构和独立岗位定义并生成新 ID，不复制成员、负责人、任职和 RBAC 角色。
24. **AC-24 项目独立演进（依赖 Q-05）**：项目创建后修改或停用来源模板，不会自动新增、更新、移动或删除项目中的组织单元和岗位。
25. **AC-25 创建事务（依赖 Q-05、Q-06）**：模板复制任一步失败时，项目、项目成员、管理员授权、组织树、岗位及成功审计全部回滚。
26. **AC-26 页面作用域（依赖 Q-08）**：企业和项目分别从自己的工作空间进入人员与组织页面；快速切换工作空间时不会显示上一作用域的组织、岗位或候选结果。
27. **AC-27 组织成员候选范围（依赖 Q-09）**：企业选择器只返回当前调用者可见的本企业及获准项目成员；项目选择器默认不返回同企业其他项目成员。
28. **AC-28 搜索与去重（依赖 Q-07、Q-09）**：按姓名或完整账号搜索时由服务端分页返回；同一 userId 在多个可见身份命中时只显示一行并聚合标签。
29. **AC-29 同名信息展示（依赖 Q-07）**：同名人员显示完整账号和来源作用域，同名组织显示完整路径；组织标签与岗位标签保持独立。
30. **AC-30 禁选状态（依赖 Q-07、Q-09）**：停用账号、停用成员或停用作用域的候选显示明确禁选原因，不能被正常提交；未知或越权 ID 不能绕过前端直接写入。
31. **AC-31 全局账号选择器边界**：平台开通企业或设置企业管理员继续使用 GlobalAccountSelect，表单稳定值为 userId；该组件不加载组织树，也不在选择时创建成员或授权。
32. **AC-32 权限能力拆分**：仅有组织查看权限的用户不能创建、移动或分配成员；仅有岗位查看权限的用户不能修改岗位，前端隐藏与服务端拒绝一致。
33. **AC-33 资源归属保护**：修改组织、岗位、模板和关系的 Repository 查询同时约束公司／项目归属；跨作用域 ID 与不存在 ID 均返回 404。
34. **AC-34 生命周期清理**：移除项目成员或企业成员时，按第 9 节在同一事务清理对应组织、岗位、负责人及既有角色关系；其他企业的独立关系不受影响。
35. **AC-35 审计一致性**：每次成功的创建、编辑、移动、排序、状态和关系变更都有同事务审计；失败或回滚操作没有成功审计，日志不包含密码或 token。
36. **AC-36 排除范围验证**：数据库、共享类型、接口和页面中不存在项目小组、主归属、岗位－组织持久关联或可执行的工作流引擎；后续流程只能依赖本期稳定资源边界另行建设。

## 12. 接口草案

本节只描述资源与业务动作，方便下一阶段划分模块；不确定最终 URL、HTTP 方法、DTO、返回包装、错误码或数据库表。所有请求和返回类型必须在后续 contract.md 中统一，不能直接把本节当成接口契约。

| 资源范围         | 查询动作                                                         | 写动作                                               |
| ---------------- | ---------------------------------------------------------------- | ---------------------------------------------------- |
| 平台企业层级     | 查询可见企业树、读取企业层级摘要                                 | 创建企业时指定层级资料、调整上级、展示类型和同级排序 |
| 企业组织单元     | 查询树／子节点／路径／状态／成员摘要                             | 创建、编辑、移动、设置状态、设置 sort                |
| 项目组织单元     | 查询当前项目树／子节点／路径／状态／成员摘要                     | 创建、编辑、移动、设置状态、设置 sort                |
| 企业成员组织关系 | 按成员或组织查询关系、查询未归属成员                             | 批量替换成员的企业组织关系、调整职责和成员排序       |
| 项目成员组织关系 | 按成员或组织查询关系、查询未归属成员                             | 批量替换成员的项目组织关系、调整职责和成员排序       |
| 企业岗位         | 分页查询岗位、详情、任职人员                                     | 创建、编辑、设置状态、按岗位或成员批量替换任职       |
| 项目岗位         | 分页查询岗位、详情、任职人员                                     | 创建、编辑、设置状态、按岗位或成员批量替换任职       |
| 项目组织模板     | 查询企业模板、模板版本、组织结构和岗位定义                       | 创建、编辑、设置状态、设置默认模板                   |
| 项目初始化       | 读取可选模板摘要                                                 | 创建项目时按空白或指定模板版本初始化                 |
| 组织成员候选     | 按作用域、组织、岗位、角色、关键词分页查询，按 userId 回查已选项 | 无；选择器不负责创建关系                             |
| 全局账号候选     | 按平台权限和关键词查询账号、按 userId 回显                       | 无；继续由 GlobalAccountSelect 使用                  |
| 审计             | 按现有作用域查询组织相关事件                                     | 随业务事务写入，不提供绕过业务规则的独立写接口       |

后续工作流专项预计新增“企业目标发布”“项目可用企业目标”“目标解析”“任务参与者”“任务级资源授权”等资源与动作。本期既不暴露这些写动作，也不把企业通讯录直接开放给项目。

## 13. 风险与待确认项

### 13.1 主要风险

| 编号 | 风险                                                                 | 控制方式                                                     |
