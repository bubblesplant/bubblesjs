`workspace-requests.spec.ts` 覆盖同 key 重入、连续 A→B→C 切换、旧 scope 所有者键不能借用新 generation 发出请求、当前空间 401 正常退出，以及旧空间迟到 401／403 无副作用。`router/entry.spec.ts` 和 `router/workspace-data.spec.ts` 核对入口探测、最终项目请求及目标作用域 access／workspaces 请求使用正确的 owner `workspaceKey`。`workspace-navigation-boundary.spec.tsx` 确认跨路由导航会卸载旧页面及其 portal 并重置本地状态；权限重校验会保留表单和受页面树管理的弹窗状态，但同时对页面 surface 与专属 portal host 设置 `hidden + inert`；两类等待均清理静态 Modal。

`latest-dialog-request.spec.ts` 确认 A 慢 B 快时只允许 B 打开弹窗、A 的旧 `finally` 不清除 B 的 loading，且失效请求不执行成功或失败回调。`organization-assignment.spec.ts` 覆盖当前作用域成员资格、停用资源、既有关系降级和新增任职限制。新增的 `organization-member-selector.spec.ts` 以 6 个用例覆盖缺失快照补查、相同快照不重复请求、上下文／loader／项目筛选切换时忽略旧结果及失败后的同集合重试。

这些自动化证据提高了 AC-26～AC-32 的覆盖度，但没有替代真实浏览器中的路由 pending 渲染、Ant Design portal、原生 `inert`、焦点／鼠标／键盘交互和逐角色权限验收，因此对应 8 项状态保持不变。

## 4. 浏览器验收缺口

当前项目未提供可执行的 Playwright 环境，不能自行安装依赖后改变项目基线。若继续浏览器 E2E，至少应覆盖：

1. 企业／项目工作空间入口、A→B→C 快速切换和同路由权限重校验：确认旧树、筛选、分页、选择和迟到请求均不污染新作用域；导航时旧页面及真实 Ant Design portal 被卸载，重校验时表单与受页面树管理的弹窗状态得到保留，但页面 surface 和专属 portal host 均不可见且不可交互；静态 Modal 被清理，焦点、鼠标和键盘均不能触发旧作用域写入。
2. 组织单元创建、移动、重命名、停用／恢复后，当前节点和所有已加载后代的 fullPath、depth、effective 与 hasChildren 实时正确。
3. 组织成员选择器的服务端分页、姓名／完整账号搜索、同名账号、同名组织完整路径、标签独立、去重和禁选原因。
4. GlobalAccountSelect 只在平台授权场景出现；企业新增成员仍使用完整账号精确匹配，选择动作不创建成员或授权。
5. 仅查看、可分配、可维护等典型角色下，页面按钮、筛选能力和服务端 403／404 一致。
6. 同一页面连续打开 A→B 弹窗时，A 的迟到成功、失败和 `finally` 均不能覆盖 B 的内容或 loading。
