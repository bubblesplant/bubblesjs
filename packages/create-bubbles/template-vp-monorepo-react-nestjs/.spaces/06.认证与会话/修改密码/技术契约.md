## 2. 共享请求与响应类型

前后端在 `packages/shared/src/types` 共享下列类型；Server DTO 与 Web 请求方法引用该处定义，不在两端复制平行接口。

```ts
interface ChangePasswordRequest {
  oldPassword: string
  newPassword: string
  confirmPassword: string
}

interface ChangePasswordResult {
  passwordChanged: true
}

interface ResetAccountPasswordRequest {
  newPassword: string
  confirmPassword: string
}

interface ResetAccountPasswordResult {
  passwordReset: true
}
```

- 三个密码字段仅用于本次请求；均不做 `trim` 或其他隐式改写。旧密码必填；新密码按当前注册规则为 8–16 位；确认密码必须与新密码完全相同。本人改密时，新旧密码必须不同。
- 管理员重置不要求旧密码，也不以目标账号当前密码为输入；`userId` 为路径中的 UUID，不进入请求体。成功结果不包含目标资料、明文密码或摘要。
- 服务端必须重新校验所有约束；输入校验失败时密码与会话不变。前端校验只用于及时反馈。

## 3. 接口与权限

| 方法与路径 | 请求 | 200 正文 | 权限与作用对象 |
| --- | --- | --- | --- |
| `POST /auth/change-password` | `ChangePasswordRequest`，Bearer Session | `ChangePasswordResult` | `@Authenticated()`；目标固定为当前会话 `userId`，不依赖工作空间 |
| `POST /platform/accounts/:userId/reset-password` | `ResetAccountPasswordRequest`，Bearer Session | `ResetAccountPasswordResult` | 平台作用域 `platform.accounts.reset-password` 且 `adminOnly: true`；目标必须存在且不能等于操作者 `userId` |

- `platform.accounts.reset-password` 是绑定 `platform.accounts` 页面的新操作权限，加入共享权限目录；仅平台内置管理员可实际使用，不可授予自定义角色。守卫和服务层写事务均须复核平台管理员身份，避免授权状态变化与直接调用服务绕过。
- 平台账号列表按钮只在平台内置管理员且目标非本人时展示；任何已存在账号均可被重置，原状态保持不变。当前账号模型包含 `active`、`locked`、`disabled`；未来扩展状态亦遵循保留规则。角色或成员关系不变。本人改密对无工作空间但会话有效的用户开放。
- 成功后撤销**目标**在 `web`、`desktop`、`mobile` 全部终端的旧会话；本人改密包含当前会话，Web 删除本地令牌并转 `/login`。管理员自己的会话不受目标撤销影响。重置后用户下次登录不强制改密。
- 重置接口不发送密码；管理员按现有线下渠道告知用户。两个接口不接收幂等键，本期同一目标并发操作由用户行锁串行化。

## 4. 公开错误与失败行为

失败按统一 `ApiFailure` 返回，不回显请求字段值、密码摘要或原始异常。下表中的错误码为本期拟新增或复用的稳定码；`COMMON.VALIDATION_FAILED` 可包含安全清洗后的字段详情。

| 场景 | HTTP | 公开码 | 密码与会话 |
| --- | --- | --- | --- |
| 缺少或无效会话 | 401 | `AUTH.SESSION_TOKEN_MISSING` / `AUTH.SESSION_INVALID` | 不变 |
| 旧密码错误 | 422 | `AUTH.OLD_PASSWORD_INCORRECT` | 不变 |
| 新旧密码相同 | 422 | `AUTH.PASSWORD_REUSE_NOT_ALLOWED` | 不变 |
| 必填、长度、确认密码或目标 UUID 格式不合法 | 400 | `COMMON.VALIDATION_FAILED` | 不变 |
| 非平台管理员、无操作权限或重置自己 | 403 | `ACCESS.FORBIDDEN` | 不变 |
| 目标账号不存在 | 404 | `ACCESS.NOT_FOUND` | 不变 |
| Redis 撤销失败、脚本协议异常或必要认证依赖不可用 | 503 | `AUTH.SERVICE_UNAVAILABLE` | 密码更新回滚；撤销失败时不能报告成功 |

- 目标不存在与越权场景不泄露目标密码、角色或内部查询结果；错误码仍须保留可诊断的授权与资源语义。
- 任一失败不得向客户端显示“修改／重置成功”。会话撤销已成功但随后 PostgreSQL 提交失败时，密码事务回滚，旧会话可能已失效；接口返回失败，用户按原密码重新登录。此情况不可伪装为成功或恢复已撤销的会话。

## 5. 写入顺序与并发一致性

1. 本人改密在 PostgreSQL 事务中以目标用户 `FOR UPDATE` 行锁读取最新摘要并验证旧密码；管理员重置在平台权限写事务中复核管理员身份、锁定目标行并排除本人。
2. 用现有 Argon2id 规则生成新摘要，只更新 `users.password_hash` 和必要的更新时间；管理员成功的现有 `audit_logs` 记录随业务事务写入，摘要只含动作结果等白名单字段。
3. 在事务提交前执行 `SessionStoreService.revokeAllForUser(targetUserId)`；Redis Lua 脚本原子撤销三个终端槽位。撤销异常抛出并回滚 PostgreSQL 密码更新和事务内成功审计，然后返回 503。
4. Redis 成功后提交 PostgreSQL。数据库提交失败时不能返回成功；Redis 撤销不逆转。事务成功提交后才向客户端返回 200。
5. 登录流程必须与密码写入按同一用户行锁串行化：在获得共享行锁后重新验证最新密码摘要，或确认摘要没有从加锁前验证的值变化。禁止沿用加锁前对旧摘要的验证结果直接创建新会话，否则可能在改密撤销后生成有效的旧密码会话。

## 6. 安全事件与审计

- 两种操作的成功与失败均输出固定字段结构化安全事件：`event`（`account.password.change` 或 `account.password.reset`）、`actorUserId`（认证前未知时为 `null`）、`targetUserId`（目标未解析或路径不合法时为 `null`）、`requestId`、`result`（`success` / `failure`）、`reasonCode`（成功为 `null`，失败为稳定错误码）、`occurredAt`（UTC 时间）。只允许这些字段，禁止记录请求体、密码、摘要、Token、Cookie、账号资料快照或原始异常对象。
- 接口入口、认证守卫与平台权限守卫中的拒绝同样属于失败事件，不能仅在业务方法 `catch` 中记录；每个请求只记录一次最终结果。失败事件在业务事务外输出，避免回滚吞掉记录。未能解析的目标不伪造目标身份。
- 管理员重置成功另外按现有平台管理审计口径写入 `audit_logs`：`action='account.password.reset'`、`objectType='account'`、`objectId=targetUserId`，`summary` 只含 `{ result: 'success' }`；该行与密码更新同事务提交。失败不写入既有成功变更审计。本人改密的成功／失败由上述安全事件覆盖，不强行写入要求平台作用域的管理审计。
- 安全事件使用现有应用结构化日志采集链路，应用侧不新增单独的清理任务；访问范围沿用该链路的运维／安全权限。当前仓库没有可核验的统一保留期限配置，实际保留周期和检索能力须在交付时依据部署环境确认并记录，不能写成已落实。功能验收先检查事件固定字段、成功与失败覆盖，以及凭据不进入日志。

## 7. 兼容与验收

- 现有注册、登录、退出、`/auth/me` 的路径和返回类型保持不变；无需数据迁移或新增用户字段。新权限加入共享目录后同步种子数据与平台账号页操作授权。
- 已登录但无工作空间、跨终端撤销、管理员自身会话保留、锁定／停用目标状态不变、权限与自重置拒绝、Redis 故障回滚，以及“旧密码登录与改密并发”均须验证。
- 响应、结构化安全事件、平台审计、应用日志与测试证据均不得出现明文密码或密码摘要。验证结果须写入本功能测试报告；仅代码阅读不能标为通过。
