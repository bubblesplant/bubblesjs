# 修改密码设计方案

## 1. 状态与来源

- 状态：当前有效设计；密码变更方案已在当前工作树实现，自动化与隔离存储专项结果及未覆盖边界见[测试报告](./测试报告.md)，不代表已经部署上线。2026-10-12 的 `/workspaces` 账号菜单入口调整已实现，并通过本地 UI 与入口验证；API 全 mock，未提交真实改密或验证服务端会话撤销，见[主题验证说明](../../04.界面与主题/万物梦幻/验证说明.md)。
- 业务边界以[需求文档](./需求文档.md)为准，用户流程以[PRD](./PRD.md)为准，字段与错误以[技术契约](./技术契约.md)为准。
- 沿用当前全局 `users` 账号、Argon2id 密码摘要和 Redis Session；不引入工作空间级密码、临时密码或 Refresh Token。

## 2. 交互与权限设计

- 本人改密由全局账号操作承载；`/workspaces` 的现行入口为右上角账号下拉菜单中的“修改密码”，选择后关闭菜单并调用现有弹窗 `show()`，不再单独平铺。此次布局调整已在工作树实现，视觉和键盘交互以[主题设计方案](../../04.界面与主题/万物梦幻/设计方案.md)为准。已进入工作空间的布局仍沿用现有全局账号入口；即使用户没有任何工作空间，仍可使用已登录会话操作。表单为旧密码、新密码、确认密码，提交后成功即清除客户端凭据和待处理请求，再转 `/login`。
- 平台管理员重置位于 `/platform/accounts` 的目标账号行操作。仅当当前访问上下文为平台内置管理员且目标不是自己时显示入口；服务端独立要求平台内置管理员，禁止用前端隐藏代替授权。
- 管理员输入目标的新密码与确认密码；只展示目标公开资料作为核对信息。成功后保留管理员会话，并提示通过现有线下渠道交付；系统不回显或自动发送密码。

## 3. 服务端领域流程

### 3.1 本人改密

1. 认证守卫校验当前 Bearer 会话，使用会话中的 `userId` 作为唯一目标，不接受请求体指定目标账号。
2. 校验新密码与确认密码、8–16 位长度及新旧不同；在目标用户行排他锁内读取最新摘要并验证旧密码，避免并发密码操作以旧快照覆盖新值。
3. 使用现有 `PasswordService` 生成 Argon2id 摘要；在 PostgreSQL 事务内更新 `users.password_hash`，提交前调用 Redis 全端撤销脚本。撤销失败则抛错回滚数据库密码，不返回成功。成功和失败的安全事件使用固定字段结构化日志记录。
4. 事务提交后返回无凭据的成功正文；客户端删除本地令牌并转登录页。任何失败均不返回成功。

### 3.2 管理员重置

1. 会话和平台访问守卫校验平台作用域，再由写事务重新确认操作者仍为平台内置管理员。不能仅凭 `platform.accounts.read` 或普通账号管理权限授权。
2. 在写事务内锁定目标用户行，确认目标存在且不是操作者；任何已存在账号均可重置，状态原样保留。当前模型包含 `active`、`locked`、`disabled`，未来新增状态也遵循保留规则；角色及成员关系不变。
3. 校验新密码与确认密码及长度，生成 Argon2id 摘要，更新目标 `password_hash`。在同一事务内写入平台成功管理审计，并在提交前撤销目标全部终端会话；失败则回滚密码更新及成功审计。操作者的会话不参与撤销。

### 3.3 并发与一致性

- Redis 撤销采用现有 `SessionStoreService.revokeAllForUser` 的单脚本原子操作，覆盖 `web`、`desktop`、`mobile` 槽位。数据库与 Redis 不能共用分布式事务；以“数据库事务中更新密码 → Redis 撤销 → 提交事务”的顺序，保证**撤销失败时密码保持原值**。若 Redis 已撤销而数据库提交失败，密码仍为旧值，但会话已失效，客户端须重新登录；这是安全侧的可接受保守结果，不能提示改密成功。
- 改密或重置持有目标用户 `FOR UPDATE` 行锁，登录创建会话持有该用户共享行锁，两类操作必须串行化。现有登录在加锁前校验密码；实施时必须在共享锁内比对当前摘要与先前验证的摘要，或在锁内重新校验密码。如果摘要已变化，旧密码登录必须失败，不得在撤销后创建新会话。
- 并发本人改密、管理员重置、账号停用以目标用户行锁排序；实际成功结果以事务提交为准。失败不改变密码；已执行的 Redis 撤销不做会话恢复。

## 4. 安全记录与数据边界

- 两种操作的成功和失败使用固定字段结构化安全日志记录 `event`、`actorUserId`、可确定时的 `targetUserId`、`result`、`reasonCode`、`requestId` 和时间；不序列化请求体、密码字段、密码摘要、Cookie、Token、Redis/SQL 原始异常或错误对象。
- 管理员重置的成功平台管理审计与密码写入同事务提交；失败事件在业务事务外记录，避免回滚丢失。具体记录载体、可查范围和保留边界以[技术契约](./技术契约.md)为准。
- 公开错误沿用[API 与错误技术契约](../../07.API与错误/技术契约.md)包装；后端参数校验不可仅依赖前端。失败时不暴露目标摘要或内部依赖信息。
- 密码明文只在请求处理内用于验证和加密，不在服务端响应或任何日志、审计摘要、测试证据及截图中出现。目标密码摘要仅写入 `users.password_hash`。

## 5. 实施与验证边界

- 前后端接口类型与返回类型集中在 `packages/shared/src/types`；服务端 DTO 校验按共享类型建立，前端请求使用同一类型，不复制平行声明。
- 验证至少覆盖：无工作空间的本人入口、跨终端旧会话失效、旧密码或权限失败时密码原值、目标不存在、自重置拒绝、Redis 撤销故障回滚、并发旧密码登录、管理员自身会话保留、凭据不进入响应和记录。
- 本功能不修改账号状态、角色或成员关系，也不处理未登录找回；后续 Token 机制迁移应重新评估会话撤销实现。
