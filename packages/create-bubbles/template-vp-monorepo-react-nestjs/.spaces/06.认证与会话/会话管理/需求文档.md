# 认证与会话需求文档

## 1. 文档状态

- 状态：当前基线有效；令牌演进部分待单独确认实施契约。
- 整理日期：2026-09-17。
- 当前实现依据：`apps/server/src/modules/auth/`、`packages/shared/src/types/auth.ts`。
- 技术边界见 [技术契约](./技术契约.md)。

## 2. 目标

1. 用户通过全局唯一账号和密码完成注册、登录、获取当前身份及退出。
2. 同一用户在同一种终端只保留一个有效会话；新登录替换该终端的旧会话。
3. Web、桌面端和移动端可以分别保持会话；iOS 与 Android 统一归类为 `mobile`，不引入厂商专用 User-Agent 标记。
4. 账号停用、会话替换和主动退出能够撤销对应登录状态。
5. 会话数据和日志不保存明文密码或明文令牌，公开错误不泄露账号是否存在等敏感事实。
6. 为后续 Access Token + Refresh Token 轮换保留明确迁移边界，但在契约确认前不把目标方案写成当前实现。

## 3. 当前有效业务规则

### 3.1 账号与注册

- `account` 全局唯一；姓名不唯一，用户关系使用稳定 `userId`。
- 公开注册只创建全局账号，不自动加入企业、项目或授予角色。
- 企业“直接注册成员”是企业成员接入流程：创建新全局账号并建立企业成员关系；它不等同于公开注册，也不能覆盖已有账号。

### 3.2 终端分类

| 终端 | 识别规则 | 会话槽位 |
| --- | --- | --- |
| `desktop` | User-Agent 含 Electron | 用户 + desktop |
| `mobile` | Android、iPhone、iPad 或 iPod | 用户 + mobile |
| `web` | 其他浏览器请求 | 用户 + web |

同一槽位的新登录替换旧会话；不同槽位互不替换。

### 3.3 会话有效性

- 当前使用 Redis 保存服务端会话，客户端持有随机 Bearer Token；Redis 只使用令牌摘要定位会话。
- 会话同时受闲置有效期和不可延长的绝对有效期约束。
- 有效请求可以刷新闲置有效期，但不能突破绝对有效期。
- 账号停用时撤销该用户全部终端会话；重新启用后必须重新登录。
- 普通受保护请求至少校验会话和当前用户状态。权限敏感接口还必须读取当前作用域、成员和权限状态，不能只相信登录时快照。

### 3.4 Cookie 使用边界

- 当前 Web 端使用名为 `token` 的 Cookie 保存 Bearer Token，默认 `Path=/`、`SameSite=Lax`，HTTPS 下启用 `Secure`。
- 删除 Cookie 时必须使用与写入相同的名称、Path 和 Domain，否则浏览器中的旧值不会被真正删除。
- Cookie 名称若后续增加环境或应用前缀，写入、读取和删除必须共同使用同一前缀规则。
- 当前 Cookie 可由前端 JavaScript 读取；若迁移到 HttpOnly Refresh Token，必须单独设计 CSRF、跨域和兼容策略。

## 4. 后续令牌演进需求

历史讨论提出将会话演进为短期 Access Token + 可轮换 Refresh Token。该目标需要保留，但当前代码没有 Refresh Token，也没有刷新端点，不能把下面内容当作已实施事实：

1. Refresh Token 每次使用后轮换，旧 Token 失效；检测到复用时撤销对应会话族。
2. 普通接口可以在明确的短时间窗口内接受撤权传播延迟；高风险接口必须读取共享 Auth State 做实时状态和撤销检查。
3. 同一用户、同一终端类型仍只保留一个活动会话族。
4. Access Token、Refresh Token 的载体、有效期、Cookie 属性、刷新接口、并发刷新、跨端退出和迁移兼容期必须先形成完整技术契约。

## 5. 验收标准

1. 同一用户在同一终端再次登录后，旧 Token 无法继续使用。
2. Web、desktop、mobile 会话可以分别存在，iOS 与 Android 归入同一 mobile 槽位。
3. 闲置超时、绝对超时、退出和账号停用均使相关会话失效。
4. 登录、退出、会话校验和服务异常不会在响应或日志中暴露明文密码、Token、Cookie 或连接串。
5. Cookie 删除使用与写入一致的 Path／Domain；退出后前端不再携带旧 Token。
6. 在 Refresh Token 方案正式实施前，接口和文档均不得声称支持刷新或轮换。

## 6. 待确认事项

- 是否以及何时从 Redis opaque Session 迁移到 Access Token + Refresh Token。
- Access Token 是否使用 JWT；若使用，签发者、受众、密钥轮换和撤销窗口如何定义。
- Refresh Token 使用 HttpOnly Cookie 还是其他受控载体，以及 CSRF 防护方案。
- 哪些接口属于必须实时读取共享 Auth State 的高风险接口。
