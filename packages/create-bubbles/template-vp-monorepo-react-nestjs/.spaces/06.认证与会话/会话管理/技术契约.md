# 认证与会话技术契约

## 1. 状态和范围

- 状态：当前有效契约。
- 本契约描述当前 Redis Session 实现，不定义尚未实施的 Refresh Token 接口。
- 成功响应和失败响应的通用包装见 [API 与错误技术契约](../../07.API与错误/技术契约.md)。

## 2. 共享类型

```ts
type SessionTerminalType = 'web' | 'desktop' | 'mobile'

interface RegisterRequest {
  name: string
  account: string
  password: string
}

interface LoginRequest {
  account: string
  password: string
}

interface LoginResult {
  accessToken: string
  tokenType: 'Bearer'
  idleExpiresIn: number
  absoluteExpiresAt: string
}
```

`accessToken` 是随机不透明令牌，不是 JWT。客户端通过 `Authorization: Bearer <token>` 访问受保护接口；服务端将令牌摘要映射到 Redis 会话。

## 3. 接口

| 方法与路径 | 请求 | 成功响应 | 说明 |
| --- | --- | --- | --- |
| `POST /auth/register` | `RegisterRequest` | `{ id, name, account }` | 创建全局账号，不创建成员关系 |
| `POST /auth/login` | `LoginRequest` | `LoginResult` | 识别终端并创建或替换对应槽位会话 |
| `POST /auth/logout` | Bearer Token 可选 | `{ loggedOut: true }` | 幂等退出；无有效格式令牌也返回成功 |
| `GET /auth/me` | Bearer Token | `{ id, name, account, terminal }` | 返回当前启用用户及终端 |
| `POST /auth/change-password` | Bearer Token、`ChangePasswordRequest` | `ChangePasswordResult` | 本人改密并撤销该用户全部终端会话；详见[修改密码技术契约](../修改密码/技术契约.md) |
| `POST /platform/accounts/:userId/reset-password` | Bearer Token、`ResetAccountPasswordRequest` | `ResetAccountPasswordResult` | 平台内置管理员重置他人密码并撤销目标全部终端会话；详见[修改密码技术契约](../修改密码/技术契约.md) |

当前没有 `/auth/refresh`，也没有 `refreshToken` 字段。

本人改密与平台管理员重置已进入当前工作树实现。两接口的共享类型、权限、错误码和安全事件统一以[修改密码技术契约](../修改密码/技术契约.md)为准；已执行及未覆盖的验证见[修改密码测试报告](../修改密码/测试报告.md)。

## 4. Redis 会话约束

- 会话键前缀：`auth:v1:session:`；槽位键前缀：`auth:v1:slot:`。
- 槽位唯一键由 `userId + terminal` 组成。
- Redis 保存 Token 摘要、用户 ID、终端、有效期和受限长度的登录来源，不保存明文 Token。
- 创建／替换、校验／续期、退出和全端撤销使用 Lua 原子执行。
- Redis 不可用或脚本协议异常统一转换为认证服务不可用错误，不能退化为绕过认证。

## 5. 并发和撤销

- 登录在密码验证后锁定目标用户并再次确认账号有效，再创建会话。
- 同终端并发登录以最后成功写入的槽位为准，旧 Token 因槽位不再匹配而失效。
- 停用账号时撤销全部终端会话；撤销失败则停用事务不得声称成功。
- 每次受保护请求都必须确认会话存在且用户仍处于 active 状态。
- 本人改密和管理员重置成功后均撤销目标账号全部终端会话；撤销失败则密码事务回滚。登录在用户行共享锁内复核最新密码摘要，防止旧密码并发登录在撤销后重新建立会话。详见[修改密码技术契约](../修改密码/技术契约.md)。

## 6. Cookie 契约

Web 端当前写入 `token` Cookie：

```text
Path=/; SameSite=Lax; Secure=<当前页面是否为 HTTPS>
```

删除时必须复用写入时的 Path、Domain、SameSite 和 Secure 语义。后续修改 Cookie 名称或前缀时，所有写入、读取、删除和请求拦截逻辑必须同批变更。

## 7. Refresh Token 迁移门槛

实施 Access Token + Refresh Token 前，必须先补齐并确认：

- Token 格式、签名／摘要策略和存储位置；
- Access／Refresh 有效期和轮换、复用检测、会话族撤销；
- 刷新接口的并发幂等和错误码；
- Cookie、CSRF、CORS 和多端策略；
- 当前 Bearer Session 到新机制的兼容期和回滚路径；
- 普通接口撤权延迟上限及高风险接口的实时 Auth State 清单。

上述契约未确认前，不新增半成品 Refresh Token 字段或端点。
