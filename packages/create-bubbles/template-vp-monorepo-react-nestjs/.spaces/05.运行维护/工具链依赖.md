## NestJS 构建统一使用 Rspack

2026-10-21 用户要求清除 Nest 12 升级后遗留的独立 SWC 构建配置。范围限当前 monorepo 的 `apps/server` 及其 workspace 依赖；前端继续使用 Vite+，同级独立模板不在本次范围内。

现行需求与设计：

- `nest-cli.json` 显式选择 `builder.type: rspack`，通过 `builder.options.configPath: rspack.config.ts` 加载 TypeScript ESM 配置，开发、调试和生产构建共同继承；删除 `.swcrc` 和 `swcrcPath`。
- 移除项目直接声明的 `@swc/cli`、`@swc/core` 与旧 `ts-loader`，添加 Nest CLI 要求的 `@rspack/core`、`webpack-node-externals`、`tsconfig-paths-webpack-plugin`，同步 catalog 与本地锁文件。
- 优先采用 Nest CLI 自带 Rspack 默认配置；保留 TypeScript 路径别名、装饰器元数据、CommonJS 运行方式与 `dist/main.js` 启动入口。上传摘要 Worker 必须在打包后仍可定位并执行。
- Rspack 内置 SWC loader 属于内部 TypeScript 转译实现，不再直接依赖独立 SWC CLI 或维护 `.swcrc`。构建之外继续显式执行 TypeScript 类型检查。
- 不修改接口、权限、数据结构或外部服务状态，无产品及协议待确认项。

验收：无旧 SWC builder、配置文件或直接构建依赖；冻结安装、后端类型检查、Rspack 构建及现有后端测试通过；验证实际打包产物中的路径解析、装饰器元数据和 Worker。历史 SWC 编译证据仅表示当时执行结果，不作为本次 Rspack 验收。

实现：[Nest 配置](../../apps/server/nest-cli.json)统一设置 Rspack builder；[Rspack 配置](../../apps/server/rspack.config.ts)使用 `import`、`export default` 与 Rspack 配置类型，仅扩展 Worker 资产复制，其余沿用 CLI 默认值。Worker 源路径由复制插件按 Rspack 编译上下文解析，工作区构建脚本的上下文是 `apps/server`。打包后 `__dirname` 指向 `dist`，Worker 同步复制到 `dist/sha256.worker.cjs`，生产和 watch 共用复制插件。

2026-10-21 追加配置语言要求并确认文件名：两个项目统一使用 `rspack.config.ts`，保留 ESM 导入导出与类型标注，纳入服务端既有 `*.config.ts` 类型检查；由 Nest CLI 动态导入，并使用当前 Node 24 的原生类型擦除及模块语法检测。配置避免使用 `import.meta`，兼容现有 NodeNext 类型检查。服务端 bundle 延续已有 CommonJS 运行约定，无需修改应用包的模块类型。

依赖树仍包含 Nest CLI 等工具的可选 SWC peer，因此保留 `allowBuilds['@swc/core']` 满足安装策略；它不是项目直接依赖或构建入口。首次移除许可导致 `ERR_PNPM_IGNORED_BUILDS`，恢复许可后冻结安装通过。
