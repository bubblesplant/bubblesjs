# NestJS 独立模板需求

状态：当前有效，已实现并完成独立项目验证。

## 目标与范围

从当前项目的 `apps/server` 提取后端 NestJS 模板，交付到同级 `../template-nestjs`，保留现有认证、权限、企业、项目、组织、成员、菜单、审计、上传、任务队列、数据库迁移与测试能力，不包含前端应用。

## 约束与业务边界

- 后端源码放在新模板根目录的 `src/`，补齐其依赖的 `packages/shared`、TypeScript、包管理和工具配置，不能引用来源模板目录。
- 保留已有接口、权限策略、错误协议、Redis Session、数据库结构及迁移内容，本次不新增或改造业务接口。
- 环境配置使用脱敏示例，不复制来源项目的 `.env*` 实际配置；本地开发服务使用明确的示例凭据。
- 不复制依赖、构建结果、缓存、CodeGraph 索引、源项目需求空间和 Git 元数据。
- 目标目录已有 `project-name/node_modules` 残留，保留原文件；模板复制及发布排除依赖残留。
- 将模板接入 `create-bubbles` 的 NestJS 分类与 `nestjs` 模板名称，补充安装、开发、构建、数据库和初始化说明。

## 验收标准

1. 指定目录中具有完整后端源码、共享依赖、迁移、配置及中文使用入口。
2. 复制到独立临时项目后可安装依赖，类型检查、已有单元测试和构建能够执行；外部服务集成未运行时如实记录。
3. 没有来源目录的相对依赖、实际环境凭据、依赖目录或构建结果被作为新模板文件交付。
4. CLI 模板列表支持 `nestjs`，不改变已有模板行为。

验收结果见 [测试报告](./测试报告.md)，使用入口见 [交付记录](./交付记录.md)。
