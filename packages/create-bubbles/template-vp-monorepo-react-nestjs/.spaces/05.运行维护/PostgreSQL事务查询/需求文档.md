# PostgreSQL 事务查询兼容

状态：当前有效；顺序查询修复、专项回归与后端检查已完成，真实外部服务未验收。实际结果见[测试报告](./测试报告.md)。

## 目标与范围

2026-11-12 反馈 `pg` 的客户端并发查询弃用警告。当前安装版本为 `pg@8.23.1`，同一客户端尚有查询等待执行时继续提交查询会触发警告，提示该用法将在 `pg@9.0` 移除。

本次修复后端角色、岗位、组织关系和组织模板中共用事务连接的并发查询；保留上传摘要 Worker 等独立资源的并发流程。未提供原始调用栈，具体触发页面不能仅凭警告文本确定。

## 业务与兼容约束

- 同一 Drizzle 事务内的查询逐个等待完成，再发起后续查询；调用查询方法的数组遍历也须遵守该约束。
- 保持现有只读快照、写锁、作用域隔离、权限校验、版本与审计语义。
- 路径、请求字段、响应字段、排序、分页和数量统计保持现有契约；不修改数据库结构或执行迁移。
- 查询失败直接沿既有异常处理链传播，不吞掉错误，也不在失败后主动发起后续业务查询。

## 实现设计

将事务内的 `Promise.all` 改为顺序 `await`；需要按行查询详情的列表使用 `for...of` 顺序累积结果。数据库连接池与事务边界保持原样，不增加全局队列、不屏蔽警告、不降级依赖。

实现范围：`RolesService.list`、`PositionsService.list/memberPositionResult`、`OrganizationTemplatesService.snapshot/list`，以及 `OrganizationUnitsService` 的组织关系查询与替换。
