## 历史原因与补丁方案

Git 索引中目标文件的 flags 为 0，索引对象与工作区对象一致；Git 的 `--ita-visible-in-index`、`--ita-invisible-in-index` 输出包含相同的 247 个路径。

Vite+ 1.4.0 的 `dist/staged/bin.js` 内置 lint-staged 17.6.0 和 tinyexec 1.3.1。tinyexec 的 `readStream` 对每个 Buffer 分别调用 `toString()`，中文字符跨 Buffer 边界时会产生替换字符。lint-staged 并行读取两组 Git 输出，分块位置不同可导致路径字符串不相等，从而误判 intent-to-add。实际调试已复现“测试证据”被解码为乱码。

使用 pnpm 的版本限定依赖补丁，在 `readStream` 迭代前设置 UTF-8 流编码，让 Node 正确保留跨分块的未完成字符。补丁只调整文本解码，保留 Git 命令和检查规则；通过工作空间补丁配置和锁文件确保重新安装依赖后仍然有效。

完整检查随后暴露了另一处阻塞：Windows 下任务优先命中 `node_modules/.bin/vp.cmd`，额外的 shell 转义使接近上限的命令超过 cmd.exe 的 8191 字符限制。根仓库 staged 配置显式通过 `node node_modules/vite-plus/bin/vp` 调用已安装的 Vite+ 入口，避免经过 cmd.exe，并兼容其他平台；检查参数保持原样。
