# 数据库备份覆盖恢复需求

> 状态：当前有效

## 目标与范围

在本地 Docker 容器 `vp-postgres` 中，用备份目录的 `backup.dump` 完整替换 `postgres` 数据库。目标库原有表、约束和业务数据均可丢弃；备份中没有的对象也必须消失。仅作用于该容器和该数据库，不修改其他数据库或备份文件。

## 规则与流程

- 恢复前检查备份存在、容器运行，并验证转储文件可由 `pg_restore` 读取；未通过时不得删除目标库。
- 默认要求操作人输入 `YES`；显式传入 `-Force` 时跳过交互确认。两种方式执行相同的完整覆盖流程。
- 从维护数据库连接，强制断开目标库连接后删除目标库，再创建空的同名库并导入备份。恢复失败时必须返回错误，不能输出成功提示。
- 数据约束：旧库全部丢弃；备份内容是恢复后的唯一来源。删库之后若创建或导入失败，目标库可能暂时不存在或为空，操作人应修复错误并重新执行恢复。
- 权限边界：只有具备目标 Docker 容器和数据库管理员权限的操作者可以运行此脚本。

## 验收标准

1. 旧库含备份以外的外键或表时，恢复仍能成功，旧对象不再存在。
2. 无效备份或容器不可用时，在删库之前失败。
3. 默认确认与 `-Force` 两种入口均恢复为备份中的结构和数据，并在失败时返回非零退出码。
