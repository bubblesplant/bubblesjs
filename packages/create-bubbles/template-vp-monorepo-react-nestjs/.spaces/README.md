## 从 Codex 历史提炼的当前决策

以下结论按 2026-09-17 前本机该项目的 Codex 会话整理，已分别同步到所属正式文档：

1. 平台下企业彼此独立，不建设集团／子企业父子层级；集团、事业群、分公司等层次由单个企业内部的组织单元表达。
2. 企业与项目分别维护自己的组织树；成员可加入同一作用域的多个组织单元，不设置主归属。
3. 保留企业岗位和项目岗位，但岗位是作用域内的平面列表，不关联组织单元；不建设项目小组。
4. 组织单元排序只保存一个非负整数 `sort`。
5. `account` 全局唯一，姓名不唯一，所有人员关系最终使用稳定 `userId`。
6. 企业新增成员只确认“直接注册”和“邀请”两个产品入口；邀请对象、账号绑定、载体、有效期、状态、接受／拒绝、撤销／重发、发送渠道和技术协议均待确认。项目只能从所属企业的有效成员中按 `userId` 选择，且候选排除已经加入当前项目的成员。
7. `GlobalAccountSelect` 只用于平台有权搜索全局账号的场景；企业／项目业务选人使用受作用域和权限保护的成员选择器。
8. 单项目且没有平台或额外企业管理职责的成员，默认直接进入项目。
9. 项目流程流转到企业财务、董事抄送等需求合理，但属于后续工作流目标解析和任务授权能力，不纳入当前组织架构交付。

- 权限树、导航菜单、功能开关和独立业务逻辑权限是否彻底解耦，仍属于待确认设计，不能当作已实施事实。
- 企业邀请的对象范围、是否绑定账号、载体、有效期、状态、接受／拒绝、撤销／重发、发送渠道、DTO、端点、Token、安全、事务、审计和验收标准均待产品确认。
- 认证令牌是否从当前 Redis Session 迁移为 Access Token + Refresh Token，以及迁移兼容期、存储位置和刷新接口细节，需要在实施前单独确认技术契约。

## 当前实现偏差

- 现有 Schema、Shared、Server、Web、测试和 `0003` 迁移仍残留已明确取消的企业父子层级。完成全链路清理并在隔离环境重验前，不得对当前数据库执行 `0003`，也不得把旧层级方案的测试结果视为现行验收。
- 现有固定邀请代码、页面、自动化测试和 `0004_company-member-invitations.sql` 先于产品协议确认产生，只能作为待处置的实现偏差；协议确认并同步正式契约前，不得执行该迁移、发布相关功能或把既有测试结果计入产品验收。

## 成员接入状态

- 企业直接注册新账号、项目从所属企业有效成员中按 `userId` 选人是已确认边界，已有自动化与真实数据库集成记录可作为技术回归参考，新增真实浏览器证据仍待补。
- 企业邀请当前只确认产品入口。现有邀请自动化只证明代码行为曾被实现，不能证明邀请协议已确认，也不能作为现行契约、迁移、发布或验收依据。

## 历史整理边界

- 不把原始聊天、Cookie、Token、密钥、请求头或真实账号资料复制进仓库。
- 历史会话与当前决策冲突时，以最新明确决定为准，并直接修改原文档的现行正文。
- 已被新需求影响的联调或测试报告只能标记为历史证据或待重验，不能仅改文案后继续声称通过。
