## 从 Codex 历史提炼的当前决策

以下结论按 2026-09-17 前本机该项目的 Codex 会话整理，已分别同步到所属正式文档：

1. 平台下企业彼此独立，不建设集团／子企业父子层级；集团、事业群、分公司等层次由单个企业内部的组织单元表达。
2. 企业与项目分别维护自己的组织树；成员可加入同一作用域的多个组织单元，不设置主归属。
3. 保留企业岗位和项目岗位，但岗位是作用域内的平面列表，不关联组织单元；不建设项目小组。
4. 组织单元排序只保存一个非负整数 `sort`。
5. `account` 全局唯一，姓名不唯一，所有人员关系最终使用稳定 `userId`。
6. 企业新增成员只确认“直接注册”和“邀请”两个产品入口；邀请对象、账号绑定、载体、有效期、状态、接受／拒绝、撤销／重发、发送渠道和技术协议均待确认。项目只能从所属企业的有效成员中按 `userId` 选择，且候选排除已经加入当前项目的成员。
7. `GlobalAccountSelect` 只用于平台有权搜索全局账号的场景；企业／项目业务选人使用受作用域和权限保护的成员选择器。
8. 单项目且没有平台或额外企业管理职责的成员，默认直接进入项目。
9. 项目流程流转到企业财务、董事抄送等需求合理，但属于后续工作流目标解析和任务授权能力，不纳入当前组织架构交付。
