# 流程与业务解耦需求

状态：待确认。用户已表达目标与场景；具体产品规则与技术方案尚在讨论，未启动实现。

日期：2026-10-14。

## 目标与已表达需求

- 用户可以动态创建流程，再与业务绑定。
- 流程能力希望与具体业务实现解耦。
- 分支包含业务指标与阈值比较，以及调用业务接口取得结果后选择分支。
- 本轮只讨论可行性与架构边界；建议见[设计方案](./设计方案.md)。

## 范围与业务流程

建议的关键流程为：选择业务类型及流程 → 配置允许使用的条件 → 发起时关联业务记录 → 取得字段或业务判断结果 → 按配置分支。此流程待确认。

节点类型、审批参与者、会签、表单、通知和业务状态回写均未确定。[组织架构需求](../../01.企业级项目级/组织架构/需求文档.md)中的跨作用域工作流目标仍属后续独立范围，本轮讨论不改变组织交付边界。

## 权限与数据约束（建议，待确认）

- 分别明确流程配置、发布、业务绑定与运行权限；字段和能力按业务及作用域限制使用。
- 业务记录 ID 不等于读取权限，业务接入机制必须落实数据访问控制。
- 字段明确含义、类型、单位、缺失值及取值时机；凭证和认证由受控接入机制管理。
- 区分发起时快照与节点执行时读取，明确运行中实例的版本及必要判断记录。
- 接口失败不得隐式作为条件不满足，重试与人工处理规则待确认。

## 候选验收标准（待确认，未执行）

- 同一引擎接入不同业务时，不增加业务专用流转代码。
- 指标比较与业务接口判断均能完成分支；业务实现变化且契约兼容时，引擎无需修改。
- 条件配置仅使用绑定业务支持且有权限的字段与能力。
- 区分条件不满足、数据缺失与调用失败，可说明一次判断使用的数据和结果。

## 待确认事项

- 首个业务场景、绑定对象、第一期节点类型与审批或业务动作范围。
- 是否需要跨业务复用同一份流程定义，字段映射和判断能力的业务语义。
- 快照或实时取数、单位、分支优先级、默认分支和无匹配规则。
- 失败处理、重试、人工处理、版本兼容，以及企业／项目和任务权限边界。
