# 上传完整内容摘要技术契约

> 状态：当前有效的实施依据，2026-10-15；实现与验证状态见测试报告。
> 依据：[需求文档](./需求文档.md)、[设计方案](./设计方案.md)。

## 范围与兼容

服务端可信 SHA-256、大小校验、完成持久化与恢复沿用原生 crypto 和 worker_threads。本轮增加前端 Worker + hash-wasm 本地摘要模块；不新增 Rust、秒传、物理／业务文件表或持久化队列。完整内容去重尚未实现。

沿用 `/uploads/multipart` 的初始化、查询、分片、完成和取消接口；登录及 ownerId 归属检查继续有效。请求字段、成功 HTTP 状态和响应字段保持现有协议，摘要暂不公开。完成仍返回 `uploadSessionId/status/objectKey/etag`；未来业务文件接口独立迁移，不能把当前 objectKey 当最终业务文件 ID。

## 完成状态与恢复

1. `uploading → completing` 条件更新后，校验分片并调用合并。
2. 合并成功或探测到已合并对象后，必须验证会话元数据、实际长度和非空 ETag。按 ETag 发出 `If-Match` 读取完整对象，再校验读取响应及实际流字节数。
3. 原始字节按顺序输入同一 SHA-256 实例，结果为 64 位小写十六进制。不能使用分片摘要拼接或 Multipart ETag。
4. 只有可信摘要成功后才能用一次条件更新写入 `object_sha256/object_etag/status/completed_at`。禁止仅凭 HeadObject 恢复完成。
5. 合并前的可修正错误回退 `uploading`；合并后失败保留 `completing`，保留对象，不重开 multipart、不删对象。
6. 同一进程内并发完成／状态恢复共享该会话的校验；多实例允许重复计算，由数据库条件更新收敛。完成重试复用持久化结果。写库失败后的下一请求可重新读取完整对象。
7. 状态查询可触发恢复并等待；对象尚未出现时返回 `completing`，不再依赖已消失的 multipart 列表。没有自动后台重试或跨实例任务租约。

## 资源与失败

每进程最多 2 个校验，单次最长 30 分钟。分块最多 256 KiB，逐块确认传输；不把整文件放进内存。超时或应用关闭时中止存储读取、销毁流、终止线程并释放名额。HTTP 断开后当前校验可继续至完成或超时；无需将断开误作业务取消。`completing` 仍不可取消。

| 场景                              | HTTP / code                               | 状态       |
| --------------------------------- | ----------------------------------------- | ---------- |
| 对象身份、元数据、ETag 或大小不符 | 409 / `UPLOAD.OBJECT_VERIFICATION_FAILED` | completing |
| 计算名额已满                      | 503 / `UPLOAD.VERIFICATION_BUSY`          | completing |
| 单次验证超时                      | 504 / `UPLOAD.VERIFICATION_TIMEOUT`       | completing |
| 存储请求或对象读取失败            | 503 / `UPLOAD.STORAGE_UNAVAILABLE`        | completing |
| 未知线程、程序或数据库错误        | 500 / `COMMON.INTERNAL_SERVER_ERROR`      | completing |

错误正文沿用 `{code,message,details?}`，不公开存储地址、凭据、异常堆栈。已有上传错误保持原义。新增完成与状态查询的失败场景需同步 Swagger。

## 数据迁移与部署

以新增迁移增加 nullable `upload_sessions.object_sha256 varchar(64)`。历史 completed 记录保持 null，重复完成仍返回原结果，不自动回填；这些记录不得视为可信去重来源。新完成流程必须写入非空摘要，但不增加跨会话唯一约束，相同内容仍允许多份对象。

本次只生成迁移，不连接真实数据库执行。部署时先应用加法式迁移，再部署服务；旧服务可继续忽略该列。发布必须包含构建复制的 `hash/sha256.worker.cjs`，不能只部署主线程 JS。

Bucket 继续私有；上传生成随机唯一 Key，服务端不得覆盖既有对象。ETag 条件读取可防常规覆盖竞争，但不是内容哈希或独立安全证明；其他写入者与版本化对象仍需存储权限和不可变策略保护。

## 前端本地摘要契约

- 入口：`apps/web/src/services/file-hash/index.ts` 的 `calculateFileSha256({ file, signal?, onProgress?, chunkSize? })`，返回 `Promise<string>`，成功值为完整文件的 64 位小写 SHA-256。
- `file` 为 File 或 Blob；名字、修改时间不参与摘要。空 Blob 返回标准空摘要，不改变服务端拒绝空文件的规则。
- `chunkSize` 为 1 字节至 16 MiB 的正整数，默认 4 MiB；按原始字节顺序更新同一增量实例，不组合分片摘要。
- `onProgress` 接收 `{ processedBytes, totalBytes }`。开始和完成均通知，中间最多约每 100 ms 通知一次；仅表示读取并输入摘要的进度。回调抛错会终止任务并拒绝 Promise。
- 每个页面模块实例最多两个运行任务，其余 FIFO 等待；等待不读文件、不创建 Worker。AbortSignal 可取消等待或执行，拒绝原始 signal.reason（默认 AbortError）。成功、错误、取消、反序列化或发送失败均移除监听并释放 Worker 与名额。
- Worker 通过结构化克隆接收 Blob 引用，不在主线程读取完整 ArrayBuffer。浏览器或 CSP 不允许 Worker／WASM 时明确失败，不回退主线程计算；调用方负责展示或重试。
- 通用算法 `calculateBlobSha256` 放 shared/utils，Worker 通过独立导出 `shared/utils/file-hash` 加载，避免带入其他共享业务工具；选项、进度及 Worker 消息类型放 shared/types。Worker 只发送 progress、complete 或 error（name/message）；每个 Worker 执行一个文件后释放。
- 本轮没有上传页面调用或 HTTP 字段变化。结果是客户端候选摘要，服务端保留完整可信计算；摘要不是持有文件或有权复用内容的证明。
