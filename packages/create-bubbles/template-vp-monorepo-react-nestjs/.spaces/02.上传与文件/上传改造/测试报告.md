## 已执行的功能验证

- 摘要使用真实 Worker 和原生 crypto：标准 `abc`、空输入内核、百万 `a`、二进制数据与不同读取边界均正确。上传入口仍拒绝空文件，内核向量不表示开放空文件上传。
- 实际读取字节数过多或过少均拒绝；存储流中断不保存部分结果；不会转移调用方 Buffer 池。
- 同时最多两个校验，完成后释放名额；30 分钟超时及应用关闭会取消读取、销毁流并释放线程；线程消息错误保持程序错误语义。
- 分片合并后必须读取完整对象，等待摘要完成才保存 SHA-256、ETag 和完成状态；已完成请求重试直接复用结果。
- 合并响应丢失、multipart 已消失、写库失败、读取失败后可由后续请求恢复；摘要或写库失败不会在同一次请求重复全量读取。
- 条件 GET 失败、对象响应身份变化不能标记完成；并发完成与状态恢复在同进程共享一次校验；对象暂不可见时不再查询已消失的 multipart。
- 合并前分片不完整可以回退上传；历史 completed 的空摘要保持兼容；跨用户访问不会读取对象；Nest 依赖注入和关闭钩子通过。
- MinIO SDK 替身验证了 `If-Match`、取消信号、二进制流与条件失败映射；这些检查没有发出真实存储请求。

对应测试位于 `apps/server/test/upload/`，错误目录测试同步登记新增上传错误。
