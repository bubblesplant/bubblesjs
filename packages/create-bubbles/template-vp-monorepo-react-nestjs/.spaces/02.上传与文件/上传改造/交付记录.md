## 本次交付

后端采用 Node.js 原生 `crypto.createHash('sha256')` 和 `worker_threads`。分片合并后从 MinIO 条件读取完整对象，按原始字节顺序计算 SHA-256 并校验实际大小，验证成功后一次条件更新保存摘要、ETag 和 completed 状态。分片乱序、重传及续传不参与独立摘要拼接。

每进程最多两个校验、每次最长 30 分钟、每块最多 256 KiB，逐块确认传输。线程异常、读取失败、超时或应用关闭会释放流与线程；同进程同会话的完成和状态恢复共用一次校验。合并后失败保留 completing 和候选对象，下一请求重新验证；已完成重试复用已保存结果。

增加对象校验失败 409、校验繁忙 503、校验超时 504，并同步完成与状态接口的 Swagger 失败场景。请求字段、成功响应字段、登录归属检查及私有 Bucket 策略沿用现有契约。服务端摘要使用原生模块；前端新增依赖见下节。

## 前端调用与构建

新增 [calculateFileSha256](../../../apps/web/src/services/file-hash/index.ts)，采用 Web Worker + hash-wasm 4.12.0。默认每次读取 4 MiB，按顺序计算完整 SHA-256；支持进度、AbortSignal 取消，最多两个并发，其余等待。成功、失败与取消均释放线程和监听。核心算法及类型在 shared，Worker 通过独立导出 `shared/utils/file-hash` 加载，生产资产约 19.16 kB。

```ts
import { calculateFileSha256 } from '@/services/file-hash'

const controller = new AbortController()
const sha256 = await calculateFileSha256({
  file, // 文件选择器获得的 File 或 Blob
  signal: controller.signal,
  onProgress: ({ processedBytes, totalBytes }) => {
    console.log(totalBytes === 0 ? 100 : (processedBytes / totalBytes) * 100)
  },
})
// 取消按钮或所属页面卸载时调用 controller.abort()，并处理 Promise 拒绝。
```

现有 shared 构建流程已经包含独立入口，先构建 shared 再构建 web。业务接入后 Vite 会自动生成并引用 Worker 资产；发布时保留完整 assets。当前前端没有上传入口，本轮未创建上传页面、秒传请求或自动预计算调用；可在后续上传流程中调用上述 API。浏览器／CSP 不支持 Worker 或 WASM 时任务明确失败，不回退主线程。前端摘要仍是候选值，不能替代服务端校验或取得文件权限。

## 数据与发布

新增迁移 `apps/server/drizzle/0007_upload_object_sha256.sql`，为 `upload_sessions` 增加 nullable `object_sha256 varchar(64)`，同时保留 Drizzle 快照与日志。本次没有连接数据库执行。

发布时按以下顺序操作：

1. 在目标环境按既有迁移流程应用该迁移，再部署新版服务。先确认列已存在，避免完成流程写库失败。
2. 发布完整后端构建目录，确认包含 `dist/modules/upload/hash/sha256.worker.cjs`。Worker 路径已在本地产物验证，不能只发布主线程 JS。
3. 在目标环境完成真实上传、校验失败与重试、服务重启恢复、超时配置和并发容量验证。

历史 completed 记录的摘要保持 null，不自动回填；它们可以继续返回历史完成结果，但不能作为可信内容去重来源。新列为加法式兼容，旧服务会忽略它；回退旧服务后不再保证新完成记录具有摘要，不应把回退期间记录作为后续可信复用依据。回退应用时保留该列和数据，避免破坏性删列。
