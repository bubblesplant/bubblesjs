## 2. 迁移与部署边界

2026-10-14 只读核验确认当前库已经应用 `0003`，旧文档“尚未应用”已纠正。本轮没有对当前业务数据库执行迁移，也没有提交、推送或部署。

- 已应用 `0003` SQL／快照保留原样；未应用 `0004` SQL／快照撤下并不可执行归档。独立 `0005_menu_svg_icons.sql` 原样保留；新增 `0006_independent_companies.sql` 与最终快照，有效 journal 为 `0,1,2,3,5,6`。
- `0006` 在同一事务先锁表并预检，再删除企业层级专属字段／约束／枚举，精确清理 `platform.companies.hierarchy` 权限、菜单与角色授权。只递增受影响角色及菜单作用域的版本，保留其他授权、用户角色、审计及组织数据。
- 旧层级菜单有子项或其他权限引用、非空企业父子关系、已存在邀请表时整批中止；不会自动迁移父子关系或删除邀请记录，须另行审阅存量处理方案。
- 清理墓碑中的 `migration:0006_independent_companies` 是迁移标识，用于阻止旧种子恢复权限；它不是部署证明，不改变通用权限清理接口的门槛。
- 尚未应用 `0003` 的存量库仍受历史 code 与同父企业名称预检约束，例如同名企业可能阻断历史升级；本次测试不宣称覆盖所有历史升级场景。历史组织 backfill 的受保护 rollback 本轮未重跑。

目标环境更新顺序：备份 → 停止旧服务 → 审阅预检与版本兼容 → `db:migrate` → 新服务与目录 → 前端。操作指引见[数据库迁移指南](../../05.运行维护/数据库迁移/操作指南.md)；禁止修改已应用历史、手工跳号或用 `db:push` 绕过阻断。`0006` 后旧层级版本不能直接回退运行。
