## 1. 当前联调结论

- 企业间父子关系、企业类型、企业树查询／移动、企业同父约束及相关权限已经从产品和技术契约中取消。此前关于 `entityType = group`、`parentCompanyId`、企业层级排序或循环保护的联调结论全部失效。
- 当前契约目标为 45 个实际受影响端点、21 个新增权限 key、7 个新增领域错误码，以及 10 张组织相关新表、97 个新增字段；`companies` 不新增企业层级字段。旧记录中的 47 个端点、22 个权限 key 和 `97 + 4 = 101` 个字段属于已废弃方案，不能继续作为完成统计。
- 最新成员入口只确认企业侧保留直接注册和邀请两个入口；直接注册与项目成员从所属企业有效成员按 `userId` 选择的既有联调结果可继续核对。邀请对象、流程和技术协议尚未确认，当前邀请代码、页面、自动化及 `0004` 不构成已接通结论。旧“按完整账号新增企业／项目成员”的入口仍不属于当前产品规则。
- 当前待交付的数据库 `0003` 尚未应用到当前数据库。旧版 `0003` 曾在随机测试库随真实集成测试执行，但它包含已取消的企业层级变更；完成 Schema、迁移与实现清理并重新验证前，不得执行正式迁移。
- 企业／项目内部组织树、成员多组织关系、独立岗位库、模板复制、GlobalAccountSelect、OrganizationMemberSelector 和跨工作空间前端隔离已有自动化或历史真实环境证据。这些证据不自动证明独立企业边界已经落地。
- 2026-09-16 的真实 PostgreSQL／Redis 集成测试为 19/19 通过，但运行基线仍含旧企业层级方案。组织、岗位、模板、关系和选择器相关结果可作为回归参考；涉及企业层级或 `0003` 最终结构的结论已失效，独立企业边界必须重新执行集成测试。
- 当前项目仍没有可执行的 Playwright 环境，真实浏览器关键流程继续保留为验收缺口。

## 2. 契约同步状态

### 2.1 Shared

- `AccessScope` 继续只有 `platform | company | project`，不新增集团或组织访问作用域。
- 当前契约不允许企业 DTO、响应或请求出现企业间父级、企业类型、企业排序等层级字段；实现同步后必须通过 strict schema 与全仓扫描确认这些字段已经移除。
- 企业成员入口概念已收敛为“直接注册／邀请”，项目成员新增 DTO 以 `userId` 表达所选企业成员；邀请 DTO、状态、端点及其他协议均待产品确认，Shared 中已经存在的相关类型只能记为实现偏差，组织模块不得补造或引用平行协议。
- 组织、岗位、模板和候选 DTO 继续使用稳定 `userId`、单整数 `sort`、独立岗位以及无主归属关系模型。
- 既有 `pnpm --filter shared test` 结果为 2 个文件、14/14 通过，`pnpm --filter shared build` 构建成功；该结果可证明既有组织共享能力，但不能替代独立企业边界变更后的复跑。

当前技术契约固定 45 个实际受影响端点，统计口径如下；这是同步目标，不代表旧实现已经按新口径复验完成：

| 能力组                                                 | 实际端点数 | 说明                                       |
| ------------------------------------------------------ | ---------: | ------------------------------------------ |
| 全局账号候选及 4 个修改请求 DTO 的既有创建／管理员端点 |          6 | 不接受企业层级字段                         |
| 企业／项目组织单元与组织关系                           |         14 | 仅在各自组织树内维护                       |
| 企业／项目岗位与岗位任职                               |         12 | 岗位与组织单元独立                         |
| 企业／项目组织成员候选搜索与 resolve                   |          4 | 按当前 URL 作用域查询                      |
| 企业项目组织模板                                       |          5 | 仅供所属企业的项目初始化                   |
| 企业／项目资料更新及成员移除行为变更                   |          4 | 既有路由，新增规范化或清理行为             |

组织相关 Controller 的 `@AccessPolicy`、候选服务的 purpose 最小权限和响应裁剪仍属于有效联调范围。实现同步后需重新核对企业 Controller 不再暴露企业树查询、父级选择或企业移动端点。

成员入口业务边界仅部分接通：企业侧直接注册，以及项目侧从所属企业有效成员中按 `userId` 选择、排除已加入者并在保存端再次校验的流程，可按已确认规则继续联调；企业侧邀请只确认入口，现有邀请接口和行为均为待处理偏差，不计入组织专项 45 个端点或任何现行契约统计。

### 2.4 权限、错误码与审计

- 当前契约新增权限为 21 个 key；旧方案多出的企业层级权限必须从共享目录、服务端策略、菜单种子及前端判断中移除，再重新执行数量与名称核对。
- 企业、项目工作空间中的组织、岗位和企业项目组织模板页面继续保留；平台企业管理沿用既有列表与权限，不增加企业层级页面或权限。
- 7 个组织领域错误码继续保留：`ORGANIZATION_CYCLE`、`ORGANIZATION_DEPTH_EXCEEDED`、`ORGANIZATION_LEADER_CONFLICT`、`ORGANIZATION_SORT_EXHAUSTED`、`INVALID_MEMBER_RELATION`、`TEMPLATE_VERSION_CONFLICT`、`TEMPLATE_UNAVAILABLE`。
- 组织、岗位、模板、项目初始化和关系替换继续要求业务写入与成功审计同事务；企业间父子移动及其审计动作不再属于当前方案。

## 3. 前后端已接通能力

以下联调结果不依赖企业间层级，继续保留：

- 企业和项目工作空间分别注册组织、岗位页面，企业额外注册项目组织模板页面。
- `GlobalAccountSelect` 以 `userId` 为值，支持搜索、resolve、快照回显、取消和失败去重。
- `OrganizationMemberSelector` 独立于 `BasicTableSelector`，按当前 URL 作用域查询既有成员，并保持组织、岗位和角色标签相互独立。
- 项目成员新增已使用 `addProjectMember` purpose 接通企业成员候选：只允许选择项目所属企业的有效成员，以 `userId` 提交并排除已加入者；保存端再次校验。企业直接注册可继续按已确认规则核对；现有邀请列表、创建、撤销、重发、接受页面和请求不构成现行联调结论。
- 企业／项目内部组织树支持懒加载、同树移动、完整路径、有效状态、成员关系和整数排序；这里的父子关系仅指单个企业或项目内部的组织单元，不代表企业之间存在层级。
- 企业／项目岗位、成员归属和模板页面均通过 Shared 类型调用 Server 端点。
- 请求、组织树缓存、筛选、分页和已选结果均绑定所有者 `workspaceKey`；工作空间切换后，旧作用域不能借用新 generation 发出请求，迟到结果会被取消或丢弃。
- 跨路由导航等待时卸载旧页面及 React portal；同路由权限重校验时保留页面本地状态，同时对页面 surface 与专属 portal host 设置 `hidden + inert`，并清理不受上下文管理的静态 Modal。
