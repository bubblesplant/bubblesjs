## 一、核心结论

组织页和成员选择器的数组筛选复用统一请求工厂的编码约定，详见[前端请求层技术契约](../../07.API与错误/前端请求层适配/技术契约.md)。后端继续严格校验字段与 ID，不在每个页面手工拼接数组参数。

1. 平台下的企业彼此独立，不建立企业间父子关系；每个企业继续使用现有 `companyId` 作为边界。
2. 项目始终直接属于一个企业。企业 A 的成员、角色、权限、组织和项目数据不会继承或传播到企业 B。
3. 每个企业有一棵企业组织树，每个项目有一棵项目组织树。界面可以聚合浏览，数据库不建立跨树父子关系。
4. 树节点统一称为“组织单元”。事业群、分公司、部门、中心、科室和班组都可以是客户在单个企业内部对组织单元的命名和用法。
5. 企业组织主要表达企业治理、共享职能和人员归属；项目组织主要表达项目执行结构。两者分别维护，避免项目差异污染企业标准。
6. 一个成员可以加入当前作用域的多个组织单元，也可以担任多个岗位；所有组织关系地位相同，不设置默认或主要归属。
7. 岗位保留，但岗位是企业／项目作用域内的平面列表，与组织单元完全独立。
8. 不建设项目小组。稳定协作结构使用项目组织单元，临时协作由具体业务选择成员。
9. 组织单元排序只使用一个非负整数 `sort`，不拆分输入，不使用小数。
10. 平台账号以全局 `userId` 唯一标识；姓名可以重复，界面必须结合完整账号和来源作用域帮助识别。

## 二、企业与组织树的边界

### 2.1 独立企业边界

平台只管理彼此独立的企业列表，不建立企业父子树。

- 企业沿用现有 `companyId`、名称、编码、状态和版本等模型，不新增企业间父级、类型、排序、规范名称或层级查询／移动能力。
- 每个企业拥有独立成员、管理员、角色、组织、数据、审计和直接项目。
- 项目始终只保存一个所属企业 `companyId`，其他企业不会因此获得隐式关系或访问权。
- 企业组织与权限严格限定在当前企业，不能跨企业继承、查询、分配或授权；跨企业资源继续按不可见处理。

需要独立成员目录、管理员、RBAC、数据和项目归属的单位，应建立为平台下的独立企业；只用于同一企业内部层级、汇报或分类的事业群、分公司等名称，应使用组织单元表达。

### 2.2 企业组织树与项目组织树

企业和项目分别拥有独立组织树：

```text
企业 A
├─ 企业组织树
│  ├─ 财务中心
│  └─ 人力资源部
└─ 项目甲
   └─ 项目组织树
      ├─ 工程部
      └─ 商务部
```

- 企业组织单元的父节点只能来自同一企业组织树。
- 项目组织单元的父节点只能来自同一项目树。
- 企业与项目本身是界面虚拟根，不创建持久化根节点。
- 组织单元只能在本树内移动，移动时保持 ID 不变。
- 每棵树最多 10 层，顶级真实组织单元计为第 1 层。
- 树按父节点懒加载，每次返回一个层级、完整路径和 `hasChildren`。
- 节点的完整路径和有效状态会受祖先变化影响；移动、重命名或状态变更后，前端必须刷新受影响节点及全部后代，无法可靠追踪时直接清空当前作用域组织树缓存。
- 同树编码唯一，同父名称唯一；唯一比较使用 `lower(NFKC(trim(value)))`。
- 编码接受 ASCII 大小写输入，新建或更新时统一保存并返回小写；名称只去除首尾空白并保留展示大小写。

## 三、成员、负责人和岗位

### 3.1 组织成员关系

- 企业组织关系只能绑定当前企业成员，项目组织关系只能绑定当前项目成员。
- 同一成员可加入多个本作用域组织单元，但同一成员与同一组织单元只有一条关系。
- 成员可以不属于任何组织单元；“未归属组织”只是查询和界面虚拟分组。
- 每条关系的职责固定为 `member | leader | deputy`。
- 每个组织单元最多一名 `leader`，可以有多名 `deputy`。
- 同一人可以负责多个组织单元；负责人身份不会自动授予管理员权限。
- 既支持按成员替换其全部组织关系，也支持在组织详情中按组织单元替换全部成员；后者只修改当前单元，不覆盖成员在其他单元的关系。两种方式均原子保存，空数组分别表示解除该成员全部组织关系或清空当前单元。
- 组织成员默认按 `leader → deputy → member`，再按关系 ID 稳定返回，不提供人工成员排序。

### 3.2 岗位

岗位用于表达董事、财务负责人、项目经理、资料员等稳定业务任职。

- 企业岗位只属于一个企业，项目岗位只属于一个项目。
- 岗位是平面列表，不设置父级，不进入组织树。
- 岗位、任职关系和模板岗位均不保存组织单元字段。
- 一人可以多岗，一岗可以多人；同一成员不能重复担任同一岗位。
- 任职既支持按成员批量维护，也支持在岗位详情中按岗位批量维护成员；按岗位保存不覆盖成员的其他岗位，空数组可清空当前岗位任职。
- 组织归属、岗位任职和 RBAC 角色分别维护、分别审计，任一方变化不会自动修改另外两方。

## 四、排序与状态

### 4.1 单整数排序

- 组织单元同级使用 `0～999999999` 的整数 `sort`。
- 前端只显示一个整数输入框，编辑时直接回显和提交原值。
- 同级统一按 `sort ASC, id ASC` 返回，相同 `sort` 合法。
- 首个同级节点默认 `sort = 1`，其余默认使用当前同级最大值加一。
- 达到上限时停止自动递增，要求用户先调整现有顺序。
- 移动时可显式填写新 `sort`；省略时排到目标父级最后。

### 4.2 停用与关系处理

组织单元、岗位和模板首期只支持停用／恢复，不提供物理删除。

- 停用组织单元保留节点、下级节点、成员关系和历史引用。
- 停用岗位保留岗位及任职关系。
- 停用成员保留组织关系和岗位任职，恢复后按当前关系重新可见。
- 全量替换时，既有停用关系可以原样保留或解除；按成员保存空数组表示解除该成员在当前作用域内的全部对应关系，按组织单元或岗位保存空数组表示清空当前资源的全部成员关系。
- 停用成员不能新增组织关系或岗位任职，也不能升级组织职责；既有职责只允许保留、移除或按 `leader → deputy → member` 降级。
- 停用或受无效祖先影响的组织单元不能新增成员或升级职责，停用岗位不能新增任职。

## 五、项目组织模板

企业通过项目组织模板提供通用标准，项目创建后仍可独立调整。

- 创建项目必须显式选择 `blank` 或 `template`。
- `blank` 不携带模板信息；`template` 必须携带模板 ID 和精确版本。
- 模板只可用于其所属企业下的项目，且必须处于有效状态。
- 模板分别保存组织结构和岗位定义，两者不建立关联。
- 初始化复制组织层级、名称、编码、说明、排序和岗位定义，并为项目生成新 ID。
- 模板组织单元不单独设置状态，存在的节点初始化为 active；模板岗位保留状态，disabled 岗位按 disabled 复制并由项目后续独立启用。
- 不复制真实成员、负责人、组织关系、岗位任职或角色。
- 模板的组织单元／岗位使用完整子项版本快照；项目只读取明确的 `templateId + templateVersion`。模板名称、说明、状态和默认标记只保存当前值，历史变化由审计记录，不承诺从模板表重建历史主表状态。
- 每个企业最多一个有效默认模板。设置新默认模板时，旧默认模板也生成保留完整子项的下一版本、递增版本并写审计。
- 模板后续修改、停用或恢复不会自动同步既有项目。

## 六、账号与成员选择器

### 6.1 成员接入边界

- 平台开通企业或设置企业管理员时使用 `GlobalAccountSelect`，稳定值为 `userId`，请求字段为 `administratorUserId`；服务端提交时仍需复核账号有效性。
- 企业新增普通成员只有两条已确认的产品路径：直接注册新账号并立即加入企业，或使用企业邀请；不允许通过完整账号直接挂接既有全局账号。
- “企业邀请”在本阶段仅表示入口名称。邀请对象、是否绑定账号、载体、有效期、状态、接受／拒绝、撤销／重发、发送渠道、DTO、端点、Token、安全、事务、审计和验收标准均待产品确认；现有邀请代码、页面、自动化测试及 `0004_company-member-invitations.sql` 不构成设计依据，组织模块也不得从其他专项复制或补造协议。
- 项目新增成员使用 `OrganizationMemberSelector` 的 `purpose=addProjectMember`，只返回所属企业的有效成员并排除已加入当前项目者，不返回组织、岗位或角色标签；只要求 `project.members.add`，提交 `{ userId }` 后服务端再次校验资格、状态和重复关系。
- 企业和项目成员入口均不允许通过完整账号直接挂接既有全局账号。

### 6.2 全局账号选择

`GlobalAccountSelect` 只用于有权搜索平台账号的管理场景：

- 稳定值为 `userId`，不以姓名或账号作为关系主键。
- 表单字段点击打开全局账号选择弹窗，复用 `BasicTableSelector` 提供姓名／账号搜索、服务端分页和单选；仅打开弹窗后加载候选，不在字段挂载时预加载账号。
- 2026-11-04 已选区布局变更：通用选择器左侧查询表格、右侧独立滚动的已选容器，空选择也占位，避免选中、移除或清空造成重排；窄屏已选区固定为 160px，并限制弹窗内容高度、居中显示以保持确认按钮可达。与角色选择器共用实现，现行交互及验收见[权限与菜单需求](../权限与菜单/需求文档.md#账号与角色选择器布局)。
- 确认后回填姓名与完整账号，取消保留原值；既有选中值通过快照或按 `userId` 补查回显，停用／锁定候选禁选。
- 同名账号显示完整账号和状态。
- 普通企业或项目操作者不能借此枚举平台账号。
- 企业侧新增普通成员不使用全局账号选择器，其直接注册与邀请边界按 6.1 节执行。

### 6.3 组织成员选择

`OrganizationMemberSelector` 只选择调用者当前可见的既有企业／项目成员：

- 表单中表现为 Select 风格字段，点击后打开弹窗式组织浏览器。
- 桌面左侧按可见作用域、组织、岗位或角色筛选，中间搜索并分页展示人员，右侧 280px 已选容器始终占位。复用 `BasicTableSelector` 的分栏布局，数量与清空操作固定在顶部，已选列表 `overflow: auto`，不贡献布局固有高度；窄屏上下排列，组织筛选面板取消桌面最小高度并占满可用宽度，已选区固定 160px。选择、移除、清空和长名称均不撑高弹窗或推动表格重排。

## 七、页面与权限

企业和项目分别从现有工作空间进入“人员与组织”，页面内部不再提供第二套企业／项目切换器。

页面包含三个并列入口：

1. 组织架构：懒加载组织树、全部成员、未归属成员、组织详情、负责人和成员关系。
2. 岗位：平面岗位列表、状态和任职人数。
3. 成员：当前作用域成员的全部组织和岗位标签。

权限继续依附现有 `platform | company | project` 三种 `AccessScope`：

- 查看、创建、更新、移动、成员分配、岗位维护、岗位分配和模板维护分别授权。
- 加入组织、担任岗位或成为负责人均不会自动获得 RBAC 权限。
- 后端按登录状态、作用域成员资格、功能权限和资源归属逐层校验。
- 跨企业、跨项目、跨组织树和不存在资源统一返回 404；当前作用域内权限不足返回 403。
- 所有写操作与成功审计保持同一事务，失败不得留下部分数据或成功审计。
