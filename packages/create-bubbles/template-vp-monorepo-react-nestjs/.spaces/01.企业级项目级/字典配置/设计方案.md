# 字典配置与缓存设计

状态：当前有效，已实现并通过本机验证。业务依据见[需求文档](./需求文档.md)，接口及字段见[技术契约](./技术契约.md)，执行证据见[测试报告](./测试报告.md)。

## 领域与入口

平台、企业、项目共用领域模型和管理页面，作用域按既有 AccessScope 表示。菜单均称“数据字典”，平台页面 /platform/dictionaries，企业和项目在各自 URL 下增加 /dictionaries。后台管理与业务选项读取分开授权。

采用一张 dictionaries 表，scopeType/companyId/projectId 表达归属，数据库检查范围完整性并验证项目所属企业。同归属 code 使用部分唯一索引。items 以 JSONB 保存，最多 500 项；整体 expectedVersion 乐观锁保存。这样同一次编辑的名称、状态与选项原子提交，避免分散项接口的中间状态。旧 value 禁改与禁移除，停用代替删除。

管理页使用现有 FullHeightProTable，表单弹窗可通过 ref.show/hide 打开关闭；选项表单允许新增、改名称、排序和启停，已保存项不允许删改值。列表提供当前字典的业务选项预览，复用公共 DictionarySelect。

## 读取和缓存职责

调用链：DictionarySelect / ProFormSelect.request → requestDictionaryOptions → store.ensureDictionary → fetchDictionaryItems。命中有效缓存不发网络请求；HTTP 层关闭 alova 缓存和共享，由 store 统一负责去重与失效。

一个 store 的 entries 以 JSON 元组 [scopeType, companyId或null, projectId或null, code] 编码，避免分隔符歧义。平台键不随所在企业／项目变化；引用企业字典使用企业真实归属。无同名兜底、覆盖或合并。

完整的启用选项按 sort、value 稳定排序后缓存，keyWords 仅对返回副本做 label/value 过滤。空数组有效，失败不写空值。有效期 10 分钟，最多 200 条，过期清理并淘汰最早缓存。存储失败时尝试删除旧快照并降级内存，避免刷新恢复已失效条目，不把成功请求变成失败。

## 会话、权限和持久化

sessionStorage 专属键 bubbles.dictionary-cache，schemaVersion、ownerUserId、entries 为快照内容。令牌、Promise、AbortController、错误与加载状态不持久化。

首次读取等待现有 user store 的真实工作空间校验，再按用户归属核对和恢复。企业缓存只对当前有效企业资格可用，项目缓存只对当前有效项目资格可用；企业管理员沿用现有项目授权。平台缓存只要求有效登录会话。

内存状态保存 sessionEpoch 与逐键 revision；请求记录两者，完成时二次核对。退出／换号推进会话代次、中止在途操作并删除专属快照。主动失效推进键代次并取消该键请求，旧响应无法回填。workspace-access-refresh 事件使全部字典失效；focus/storage 事件核对共享 Cookie 的身份变化，sessionStorage 不用作跨标签数据同步。

## ProFormSelect 接入

统一 requestDictionaryOptions 接受 scope、code、可选 keyWords，返回 Promise<DictionaryOption[]>。公共 DictionarySelect 把会话代次和字典 revision 纳入 params，关闭字段跨键缓存；依赖改变时字段重建。打开下拉时推进 params.opened，触发 request 重新读取，由 store 决定是否需要网络。保存管理数据后失效对应键，已挂载订阅字段自动重新读取。请求失败在字段下方显示提示，再次打开允许重试；加载失败不会覆盖表单自身的校验信息。

直接使用 ProFormSelect 的页面可调用统一方法，但须自行传入 store 的 sessionEpoch/revision 并在下拉打开时重读；推荐复用封装，避免漏掉字段自身的缓存刷新。

## 取舍与后续

不物理删除字典／历史项，不做远程关键词查询和每用户不同的平台字典内容。10 分钟为首期可调整常量，跨客户端立即推送、模板初始化、历史名称快照与更细业务授权由未来具体需求决定。
