# 字典配置技术契约

状态：当前有效，2026-10-19 已实现并完成本机验证。依据[需求](./需求文档.md)与[设计](./设计方案.md)，运行状态见[交付记录](./交付记录.md)。

## 数据与共享契约

共享 DTO、响应类型位于 packages/shared/src/types/dictionary/，纯规则及 Zod Schema 位于 packages/shared/src/utils/dictionary/，Web 与 Server 复用。

- DictionaryItem：value（1–100 字符，首尾去空格）、label（1–100）、sort（0–999999 整数）、status（active/disabled）。
- CreateDictionaryRequest：code（小写字母开头，仅小写字母数字下划线，最长 64）、name（1–100）、description（最长 500，默认空）、status（默认 active）、items（0–500 项，value 唯一）。
- UpdateDictionaryRequest：除 code 外以上字段，加 expectedVersion（正整数）。禁止额外 code 字段。
- DictionaryRecord：以上创建字段、id（UUID）、scope（AccessScope）、version、createdAt、updatedAt（ISO 字符串）。
- DictionaryListQuery：page、pageSize（最多 100）、query（名称／编码搜索）、status。
- DictionaryOptionsQuery：scopeType、code，以及 company/companyId 或 project/companyId/projectId。平台不接收归属 ID，项目必须带企业 ID，均严格校验。
- DictionaryOption：label、value。只返回启用字典下启用项，按 sort、value 排序，字典缺失或停用为 404。

## HTTP

管理路径基准：

- /platform/dictionaries
- /companies/:companyId/dictionaries
- /companies/:companyId/projects/:projectId/dictionaries

| 方法  | 路径                | 正文与结果                                          | 权限                           |
| ----- | ------------------- | --------------------------------------------------- | ------------------------------ |
| GET   | 基准                | query 为列表参数；PageResult<DictionaryRecord>      | {scope}.dictionaries.read      |
| POST  | 基准                | CreateDictionaryRequest；201 DictionaryRecord       | {scope}.dictionaries.create    |
| PATCH | 基准/:dictionaryId  | UpdateDictionaryRequest；DictionaryRecord           | {scope}.dictionaries.update    |
| GET   | /dictionary-options | query 为 DictionaryOptionsQuery；DictionaryOption[] | 有效会话，服务内按真实归属授权 |

管理接口原生 Nest Zod Body/Query 与响应序列化，Swagger 描述同 Schema。所有响应为直接业务正文，Cache-Control:no-store。参数 ID 均按 UUID 处理，code 仅放 query，不作为路由参数。平台写接口额外校验平台管理员，企业／项目写按权限事务内重新授权；创建与更新审计同事务。

顶层选项数组的 Swagger 使用 dictionaryOptionsSchema；Nest 原生序列化器逐项处理数组，SerializeOptions 使用 dictionaryOptionSchema。该组合已通过真实 HTTP 测试，不能将整个数组 Schema 配给逐项序列化器。

选项平台读取不使用平台后台访问策略，仅检查有效用户；私有范围读取复用 AccessService.read（有效企业成员／现有项目访问资格），无需字典配置页权限。

## 一致性和错误

数据库用范围完整性检查、企业及项目外键、分范围 code 唯一索引、正版本约束兜底。写入复用权限事务锁并按 expectedVersion 检查版本；更新再次限定 id 与 scope，不能跨范围更新。历史 value 禁改／禁移除，可停用及增加；不物理删除。

| code                            | HTTP | 含义                               |
| ------------------------------- | ---- | ---------------------------------- |
| DICTIONARY.NOT_FOUND            | 404  | 字典不存在、非当前归属或不可读取   |
| DICTIONARY.CODE_EXISTS          | 409  | 同归属编码已存在                   |
| DICTIONARY.ITEM_VALUE_IMMUTABLE | 409  | 已保存选项值被修改／移除           |
| ACCESS.VERSION_CONFLICT         | 409  | 保存版本已过期                     |
| ACCESS.NOT_FOUND                | 404  | 私有归属不存在或用户不具备成员资格 |
| ACCESS.FORBIDDEN                | 403  | 归属／成员停用或管理权限不允许     |
| COMMON.VALIDATION_FAILED        | 400  | Schema 校验失败                    |

统一错误结构为 `{ code, message, details? }`，Request-ID 遵循[API 契约](../../07.API与错误/技术契约.md)。

私有选项读取沿用 AccessService 的资格检查：企业成员不存在、项目非成员且不具备企业管理员资格时返回 ACCESS.NOT_FOUND（404），不暴露归属是否存在；有效成员被停用或缺少操作权限时返回 ACCESS.FORBIDDEN（403）。

## 前端接口与缓存

requestDictionaryOptions({scope, code, keyWords?}) 返回 Promise<DictionaryOption[]>。ensureDictionary 才做缓存判断；fetchDictionaryItems 仅做 HTTP。freshRequest 禁用 alova 的二次缓存／请求共享。

缓存键为 JSON 元组编码的精确 scope/code；一个 store、10 分钟 TTL、200 项上限。sessionStorage 键 bubbles.dictionary-cache、schemaVersion=1、ownerUserId、entries；每项包含 scope、code、items、fetchedAt、expiresAt。恢复前经服务端 user/workspaces 校验，权限资格与身份均匹配才可复用。格式损坏丢弃；存储异常时尝试删除旧快照并降级内存，删除也不可用时仍保留内存能力。

同键合并、空数组可命中、失败不缓存、搜索不污染完整缓存。每键 revision 和 sessionEpoch 防迟到写回。保存后主动失效该键；权限刷新全失效；会话改变清内存及专属持久化，不能 sessionStorage.clear()。打开字段重读，由 store 执行 TTL 判断；字段 params 随代次变化。
