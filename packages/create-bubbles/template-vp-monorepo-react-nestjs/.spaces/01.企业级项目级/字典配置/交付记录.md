## 已交付能力

平台、企业、项目各自提供“数据字典”管理入口，支持列表搜索、新增、编辑、选项排序与启停。平台入口与企业管理、菜单管理同级。平台字典由平台管理员维护，所有有效登录用户可以读取；企业和项目字典沿用真实访问资格，管理权限与业务选项读取分离。

字典使用显式 `scope + code` 引用，同编码在不同归属下独立存在。字典编码及已保存选项值保持稳定，不物理删除。保存携带 `expectedVersion`，服务端防止覆盖其他人的修改；审计随事务提交。

统一入口 `requestDictionaryOptions` 负责读取缓存，未命中或过期再取接口；真实 HTTP 方法只负责请求。缓存使用独立 Zustand store，按精确归属保存于一个 entries 对象；TTL 为 10 分钟，最多 200 个字典，同键并发合并，失败不缓存。`sessionStorage` 仅使用 `bubbles.dictionary-cache`，退出、换号、权限刷新及主动失效都有对应处理。

## 业务页面接入

推荐复用 [DictionarySelect](../../../apps/web/src/components/DictionarySelect/DictionarySelect.tsx)，内部已接入真正的 `ProFormSelect.request`，处理字段自身缓存、字典失效和下拉重新打开时的 TTL 检查：

```tsx
import DictionarySelect from '@/components/DictionarySelect/DictionarySelect'

;<DictionarySelect scope={{ type: 'platform' }} code="units" name="unit" label="计量单位" />
```

先在平台“数据字典”创建 `units` 并启用选项；此示例编码不属于系统预置业务数据。所有企业共用时沿用该平台引用，无需复制企业字典。

企业私有字典传入 `{ type: 'company', companyId }`；项目私有字典传入 `{ type: 'project', companyId, projectId }`。项目业务要使用企业字典时仍传企业归属。不要由当前页面位置自动猜测字典来源。

其他消费者可直接使用统一方法：

```ts
import { requestDictionaryOptions } from '@/store/dictionary'

const options = await requestDictionaryOptions({
  scope: { type: 'platform' },
  code: 'units',
})
```

直接使用原生 ProFormSelect 时，`request` 可调用该方法；需要同步字典 store 的会话／逐键代次并在打开下拉时触发重读，完整做法参照公共组件。管理页保存已经主动失效对应字典，其他客户端在下次缓存过期读取时更新。
