# 字典配置需求

状态：当前有效，首期已实现并完成本机验证。平台共享、三范围管理与统一缓存按以下规则生效，细节见[设计方案](./设计方案.md)、[技术契约](./技术契约.md)和[交付记录](./交付记录.md)。

## 目标与范围

为平台、企业和项目提供可配置的业务选项。各工作空间菜单统一称“数据字典”，平台入口为“平台管理 → 数据字典”，与企业管理、菜单管理同级。企业与项目在自己的工作空间维护私有字典。

平台共享字典由平台管理员维护，所有有效登录用户可在业务表单中读取启用选项，无需平台后台权限。企业字典限该企业有效成员读取，项目字典限现有项目访问授权读取；读取业务选项不要求字典管理页面权限。企业和项目的既有边界以[权限与菜单需求](../权限与菜单/需求文档.md)为准。

首期提供列表、搜索、新增、编辑、排序和启停；业务字段显式传入真实归属和字典编码。不同范围的同名字典互相独立，不自动继承、覆盖或合并。项目引用企业字典时明确使用企业归属。不包含模板复制、继承扩展或跨企业私有字典共享。

## 业务规则

- 同一归属下字典编码唯一，创建后不修改；名称、说明、启停和选项可编辑。
- 选项含值、显示名称、排序和启停状态；同字典选项值唯一，最多 500 项。
- 保存过的选项值保持稳定，不删除；不再使用的项停用，以保留历史业务值的含义。历史记录的显示名称快照仍由具体业务负责。
- 字典或选项停用后不再出现在新选择列表，字典停用／不存在读取返回错误，全部选项停用返回有效空数组。
- 多人编辑采用版本校验，过期保存提示刷新后重试。
- 配置维护要求对应范围的管理权限；平台写入额外要求平台管理员。写入与审计同事务，禁止跨范围修改。

## 缓存与表单

提供统一 requestDictionaryOptions 方法，供 ProFormSelect.request 与其他组件使用。由独立 Zustand store 判断缓存，缺失或过期才请求接口。一个 entries 索引同时保存多个范围、归属和编码的数据，sessionStorage 仅保存成功选项及必要元信息。

首期有效期 10 分钟、最多 200 个字典，空数组可命中；同键请求合并，错误保留为错误并允许重试，搜索在完整结果内过滤。保存后当前客户端主动失效对应键，其他客户端最迟在下次过期读取时更新。

登出、认证失效或换号清理内存和字典专属 sessionStorage 键；刷新恢复须核对服务端身份与可访问范围。旧会话与失效前的迟到请求不得回填。权限刷新清理缓存；切换工作空间保留有权范围的缓存。存储不可用时降级内存。

公共 DictionarySelect 处理字段自身缓存、会话代次和字典失效；下拉打开时重读以落实有效期。业务页面无需各自实现缓存。

## 验收标准

1. 三类菜单、管理操作、范围隔离和管理员约束符合既有权限体系。
2. 企业／项目用户可直接读取平台共享选项，无需进入平台后台。
3. 创建、编辑、启停、排序、编码和值稳定、版本冲突及审计可验证。
4. 统一入口正确处理同键并发、空结果、失败重试、有效期和搜索。
5. 退出／换号、权限刷新及主动失效阻止迟到响应回填；持久化异常不影响成功结果。
6. ProFormSelect 切换归属、会话和失效后重新加载，打开时按有效期刷新。

验收证据见[测试报告](./测试报告.md)：176 项自动化、8 组模拟 API 浏览器检查及 11 组真实完整服务验收通过。完整服务验收使用虚构账号真实注册／登录、隔离 PostgreSQL、真实 Redis、完整后端和独立前端，覆盖三级维护、共享读取、缓存恢复和退出清理；不等同于生产部署验证。
