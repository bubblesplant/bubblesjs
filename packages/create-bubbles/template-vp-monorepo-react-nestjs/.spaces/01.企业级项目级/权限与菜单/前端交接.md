- 修复前根路由使用 `<Outlet />`，认证、入口、错误页与布局页面区域分别包裹 `RouteTransition`；App 单一过渡边界属于历史方案。现代 Edge 基线显示原生过渡仍在执行，但跨空间快照由全页 `(0, 0)` 收缩为内部内容区域 `(64, 72)`／`(232, 72)`，使既有整页转场失效。
- 等待目标数据期间按现行工作空间边界隔离旧页面交互，不能因恢复动画使旧权限或旧请求重新生效。
- 减少动态效果偏好关闭动态转场；不支持浏览器 View Transition API 时正常导航。
- 本次导航与浏览器动画专项证据已写入[测试报告](./测试报告.md)；使用模拟业务接口而非真实后端。本文历史的“唯一过渡容器”或截图不用于证明当前动画有效。

### 当前修复设计（已在工作树实现）

根路由使用持续存在的 `RouteTransition region="layout"`，边界名称固定为 `route-layout`。以 `useMatches()[1].pathname` 区分登录、工作空间、企业及具体项目，仅布局／空间标识变化时执行整页滑动，使跨入口与跨空间导航持续拥有全页快照。

布局内部保留 `route-page`，负责同一空间内菜单内容区更新；移除 `share`，使用默认 `none` 禁止内部边界跨布局共享快照。认证与入口的普通页面移除局部过渡边界，交由根边界处理。保留旧页面到目标提交及等待期间隔离交互的现行行为，减少动态效果同时禁用两类动画，API 不支持时普通导航。

### 可感知速度调整（已实现并专项验证）

用户确认 Chrome、`http://localhost:9999`。真实 headless Edge 与 Chrome 的 160ms 中间帧和计算样式补验显示旧／新快照像素可见；调整前 320ms、`cubic-bezier(.4,0,.2,1)` 在半程已推进约 78%，视觉主要变化较早完成。

跨布局／空间 `route-layout` 已改为 500ms、`cubic-bezier(.45,0,.55,1)` 对称曲线，菜单 `route-page` 保留 320ms 原曲线。边界分工与减少动态效果／不支持 API 降级保持现行要求。Chrome 155 的 8 项速度专项通过：整页快照覆盖 1440×1000，250ms 位移中点约 720px，旧／新像素可见，动画恢复后自然完成，减少动态效果关闭动画。证据见[速度报告](./测试证据/route-transition-speed-chrome.json)、[中点截图](./ui/route-transition-speed-login-chrome.png)和[验证工具](./工具/route-transition/route-transition-speed.mjs)。隔离 headless Chrome 使用模拟接口，未读取用户现有会话；原 35 项 JSON 不覆盖本速度增量。

- 平台创建企业、设置或更换企业管理员统一使用 `GlobalAccountSelect`，表单保存 `userId` 并提交 `administratorUserId`，不再把账号字符串作为关系标识。
- 企业成员页当前已确认的新增能力是“直接注册新账号并加入企业”，提交姓名、完整账号和密码；不能继续使用完整账号搜索并直接拉入既有平台账号。
- 企业邀请只确认是企业新增成员的另一条产品入口；邀请对象、载体、有效期、状态、接受／拒绝、撤销／重发、安全与审计规则均待确认。
- 当前前端已存在 7 天链接管理和 `/member-invitations/accept?token=...` 接受页，但这是未获产品确认的实现记录，不是现行交接要求，不得据此继续扩展或宣称产品可用。
- 项目成员页使用 `OrganizationMemberSelector` 的 `purpose=addProjectMember`，只展示所属企业有效且未加入当前项目的成员，选择和提交均为 `userId`；不展示组织、岗位或角色标签。
- 管理员选择、企业直接注册和项目成员候选已有组件／请求层自动化与构建证据，但当前真实浏览器全过程和正式环境仍未复验。邀请相关测试只能证明现有实现行为，不能替代产品确认或产品验收。

## 实现范围

- `src/pages/register`、`src/pages/login/index.tsx`：公开注册、登录、注册成功账号提示，以及登录后的工作空间入口。
- `src/pages/workspaces`：按服务端有效身份展示企业、项目和平台工作空间。无企业普通账号不得被要求提供完整账号供管理员直接挂接；具体邀请引导文案应在协议确认后定稿。有效平台身份仍保留平台入口。
- `src/pages/access`：工作台、企业开通与启停、项目创建与启停、管理员补任与更换、账号与成员管理、角色分配、自定义角色与权限树、资料、三套菜单编辑、废弃权限清理预览与执行、审计筛选与分页。当前邀请列表／创建／撤销／重发界面仅作为未确认实现登记。
- `src/pages/member-invitations`：当前存在基于 URL token 的登录／注册和主动确认页面，仅作为未确认实现登记；产品协议确认前不把其路由、状态或交互当作稳定契约。
- `src/pages/access/components`：通过 `show/hide` 暴露弹窗操作，所有写操作使用共享契约 DTO。内置角色定义只读；权限树保留页面和操作的依赖关系及全选、半选行为。
- `src/router`：17 个静态管理页面注册，路由按功能拆入 `modules`，父级 scope middleware 获取作用域上下文，叶子 access middleware 校验页面权限；未知页面显示 404。页面 403 不会清空其他可用导航；空间首页无读权限时，优先进入可见菜单中的已授权静态页面。默认入口对无平台或额外企业职责的单项目成员直接进入项目，其余进入工作空间；明确选择的工作空间和页面不被分流覆盖。示例页面不出现在生产菜单。
- `src/router/lazy-load`、`src/App.tsx`：使用 `lazyLoad('access', 'home')` 等相对 pages 的路径统一懒加载。历史版本在 App 中只保留一个 `RouteTransition`；当前根路由、认证／入口／错误页与布局的过渡边界现状及待修复范围见上文 2026-10-12 增量。
- `src/layouts/WorkspaceLayout/index.tsx`、`workspace.css`：三种作用域布局、具体企业／项目名称、导航和切换；菜单路由等待期间保留旧页面视觉内容并禁用交互，由加载层覆盖，目标路由提交后再替换以保持 `RouteTransition` 动画；进入新空间时重建业务子树；权限刷新时隐藏页面并保留表单输入。
- `src/utils/request/workspace.ts`：沿用现有 alova 请求封装；管理请求禁止缓存，取消旧请求，使用用户、作用域和请求代次阻止迟到结果。旧 401 不得退出新账号，旧 403 不得刷新新空间。当前业务 403 刷新一次，access 403 不递归。
- `test/workspace-requests.spec.ts`、`test/workspace-navigation.spec.ts`、`test/router`：权限导航、请求竞态、入口分流及真实 React Router memory 导航回归测试；原 loader 测试迁移至 middleware 测试。

## 联调边界

- 页面直接调用真实 API，没有使用 mock 数据。共享类型与纯工具统一从 `shared/types`、`shared/utils` 导入。
- 企业项目列表的管理员设置使用已同步契约的 `GET /companies/:companyId/projects/:projectId/administrators`，支持读取停用项目的显式项目管理员，避免将企业隐式管理员当作待替换的项目身份。
- React Router 当前安装版本为 8.3.1，使用原生 Data Mode middleware。工作空间列表及各空间权限保存在 `pages/workspaces/state.ts`，页面随导航或重新校验完成后读取。布局通过 `Outlet context` 向子页面提供同一份权限；缺数据时显示加载态，避免撤权过渡中的旧页面读取空权限。不再订阅路由状态或维护导航快照。
- 开发前端默认 API 前缀为 `/api`；隔离联调环境由主控启动，前端端口 5301，后端端口 3301。前端代理通过 `VITE_API_URL` 配置。
- Playwright 真实页面、后端接口和数据库事务验收由主控及 QA 独立执行，结果应写入最终测试报告，不能用本交接中的静态检查替代。
