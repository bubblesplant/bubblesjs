# 企业、项目与菜单权限管理 PRD

## 1. 文档状态与需求来源

- 状态：主体业务范围已确认；企业成员只确认“直接注册或邀请”两个入口，邀请协议与验收尚待确认。
- 业务依据：[已确认需求文档](./需求文档.md)。该文档及本节记录的用户后续确认是唯一业务来源；本 PRD 只负责拆分用户故事和映射验收，不新增业务政策。
- 本会话最新确认：有效平台管理员即使没有企业成员身份，仍能进入平台空间开通企业；无企业不等同于没有平台管理权限。普通注册用户的具体邀请载体和加入流程尚未确认。
- 若本 PRD 的摘要与需求原文存在表述差异，按已确认需求及用户后续确认核对修正，不由开发或测试自行扩展规则。
- 本文不记录测试账号、密码、会话或其他凭据。验收状态将在后续测试报告中记录；本 PRD 的确认不表示功能或测试已经完成。

## 2. 目标与首期范围

在现有 React、NestJS、Drizzle、PostgreSQL 和 Redis 基础上，交付企业开通、项目管理、成员与角色、菜单授权、页面及接口鉴权、基础操作审计的完整管理流程。

首期覆盖平台、企业、项目三类工作空间，以及注册与工作空间选择。平台维护全局资源和企业管理员恢复入口；企业管理员管理本企业及全部项目；项目管理员仅管理当前项目；普通成员按所在作用域的有效授权使用功能。各层级的具体权限、停启和管理员保护规则直接引用需求文档，不另建一套规则。

## 5. 已确认的关键边界

- 工作空间入口按有效身份展示：普通账号未加入企业时显示该状态；邀请载体和加入流程待确认。平台管理员无企业仍保留平台入口，不能以企业列表为空作为整页阻断平台入口的条件。
- 平台开通企业、设置或更换企业管理员使用全局账号选择器并提交 `userId`；企业新增普通成员只允许直接注册或邀请，不能复用平台账号枚举能力。
- 企业邀请只确认作为企业成员新增入口存在。有效期、token、是否绑定账号、发送、状态、接受／拒绝、撤销／重发、幂等、数据表、DTO、端点和审计均待确认。
- 项目新增成员只能查询所属企业有效成员，排除已加入当前项目者，提交 `userId` 后由服务端重新校验企业成员资格和重复关系。
- 企业管理员的项目管理能力及项目有效管理员计数来自企业身份，不要求复制项目成员或角色记录；不新增项目必须长期保留专任管理员的要求。
- 创建项目属于内置企业管理员专属能力，不能通过自定义角色下放；平台开通企业和设置企业管理员不等同于平台直接取得企业内部业务权限。
- 停用、移除和恢复按源文档状态表执行；企业停用后先由平台恢复企业，再通过有效企业入口管理项目。平台在停用企业设置或更换管理员属于明确例外。
- 平台禁用全局账号可以使企业暂时缺少有效管理员，但平台自身最后有效管理员不得失效；管理员更换和恢复校验按源文档事务规则执行。
- 内置角色定义禁止人工修改，系统版本升级与合规的废弃权限清理可以维护系统定义；自定义角色不随新功能自动扩权。

## 7. 明确排除范围

- 企业和项目物理删除、项目跨企业迁移。
- 权限专项内另建“部门”模型或部门权限作用域；组织结构统一由组织架构专项的“组织单元”承载。字段级权限、审批流、SSO、外部协作者同样不在本专项范围。
- 企业独立菜单副本、角色继承和显式拒绝规则。
- 通过后台菜单配置创建未开发的页面、保存可执行组件路径，或让旧前端通过刷新权限获得不存在的页面代码。
- 企业、项目上传归属改造及历史上传租户迁移；现有上传仍按 `ownerId` 授权，不将本期交付描述为已完成上传租户隔离。
- 自动为注册用户创建或分配企业、自动提升首位注册用户、提供固定默认管理员密码。
- 企业邀请的具体协议和功能闭环；在有效期、token、账号绑定、发送、状态、接受／拒绝、撤销／重发、幂等、数据表、DTO、端点及审计确认前，不纳入当前交付与验收。

未在已确认需求中列出的企业功能，不因“企业级”名称自动纳入本期。验收和实现细节的必要澄清应回写统一契约并由主控协调，不能借此增加业务政策。

## 8. 交付与验证要求
