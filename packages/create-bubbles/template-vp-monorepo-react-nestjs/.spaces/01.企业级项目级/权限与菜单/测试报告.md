### 原 320ms 的像素补验（验证记录）

用户确认使用 Chrome 与 `http://localhost:9999`，仍难以感知动画。上述 4 组配置／35 个检查项证明原生动画生命周期、时间推进与快照区域，不能单独证明快照像素实际出现在画面中，因此补充暂停真实原生动画于 160ms 的截图与计算样式采样。

真实 headless Edge 155.0.4283.45（`127.0.0.1:9999`）与 Chrome 155.0.8059.39（`localhost:9999`）均在 1440×1000、模拟业务接口下采到可见中间帧；Chrome 默认环境支持原生 API，未覆写减少动态效果偏好。旧／新快照的 `visibility=visible`、`opacity=1`，在 160ms 时旧画面平移约 -1116.81px、新画面平移约 323.192px，页面异常为 0。像素样本显示原 320ms、`cubic-bezier(.4,0,.2,1)` 此时已推进约 78%，主要视觉变化较早完成。

证据：[Edge 像素报告](./测试证据/route-transition-visibility.json)、[Chrome 像素报告](./测试证据/route-transition-visibility-chrome.json)、[Edge 中间帧](./ui/route-transition-login-midpoint.png)、[Chrome 中间帧](./ui/route-transition-login-midpoint-chrome.png)；工具：[route-transition-visibility.mjs](./工具/route-transition/route-transition-visibility.mjs)。此阶段只新增工具、证据与 UI 产物，没有修改源码。
