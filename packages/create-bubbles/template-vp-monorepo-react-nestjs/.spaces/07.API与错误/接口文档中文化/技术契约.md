# 接口文档中文化技术契约

## 1. 状态和依据

状态：当前有效，已在工作树实现并通过中文覆盖与兼容比较；实际检查和未覆盖范围见[测试报告](./测试报告.md)。业务目标与范围见[需求文档](./需求文档.md)，现行 HTTP 协议见[API 与统一错误技术契约](../技术契约.md)。

## 2. 展示元数据

| 位置                                      | 现行约定                                                                            |
| ----------------------------------------- | ----------------------------------------------------------------------------------- |
| Swagger `info.title`                      | 前后端模板接口文档                                                                  |
| Swagger `info.description`                | 前后端一体化模板的 HTTP 接口文档，涵盖认证、平台、企业、项目与示例接口。            |
| Controller `@ApiTags`                     | 显式使用中文业务分组，涵盖全部生产 Controller 与未挂载示例 Controller               |
| HTTP handler `@ApiOperation({ summary })` | 显式使用中文操作摘要，覆盖所有 handler；同一 handler 生成多个路径时各操作均保留摘要 |

中文化仅作用于展示字段，不修改默认或已有 `operationId` 生成规则。例如 `RolesController_list` 类标识继续保留原值，不能将中文摘要代替操作标识。

## 3. 必须保持的协议与行为

- 路由方法、路径、全局前缀、Controller／方法名及模块挂载关系保持不变。
- 请求参数位置、名称、必填性、Schema、校验规则、响应正文、状态码及响应头保持不变。
- 原生 Schema／`standardSchema`、Session Bearer 声明、安全方案、实际访问策略、权限与作用域保持不变。
- `/api-docs` 和 `/api-docs-json` 保持现有入口；不新增文档认证方案或改变文档访问规则。
- 现行异常映射、统一错误、请求关联 ID、业务 Service、事务和存储行为保持不变。
- 未挂载的数据库／缓存示例只更新注解，不加入生产模块。

## 4. 验证方法

实施前直接从当前未修改 Server 的工作树生成真实 OpenAPI 基线并保留生产与全量操作数据。实施后再次生成，将允许变更的 `info.title`、`info.description`、分组 `tags` 和操作 `summary` 移除后比较完整结构；同时检查操作集合和操作标识稳定，并比较排除文档元数据后的业务 AST。

基线、最终报告与可重跑工具均归档到本功能目录。静态比较与不启动应用的文档生成不等同于真实数据库、Redis、对象存储或浏览器联调；报告必须区分这些边界。
