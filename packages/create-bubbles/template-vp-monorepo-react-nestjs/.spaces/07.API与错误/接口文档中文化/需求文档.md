# 接口文档中文化需求

## 1. 状态与目标

- 状态：当前有效；工作树已实现，中文覆盖与兼容验证、后端检查、类型、构建及 22 项回归通过，实际范围与未覆盖边界见[测试报告](./测试报告.md)。
- 适用范围：当前 React／NestJS monorepo 模板的后端 Swagger 文档。
- 目标：接口分组、操作名称及文档标题使用中文，使 Swagger 与导入 OpenAPI 的工具能够直接展示中文业务含义。

## 2. 实施范围

1. 所有已发布 Controller 显式声明中文 `@ApiTags`，所有已发布 HTTP handler 显式声明中文 `@ApiOperation({ summary })`。
2. 未挂载的数据库和缓存示例 Controller 同步补充中文文档注解，继续保持示例状态，不增加路由挂载。
3. 全局标题采用“前后端模板接口文档”；描述采用“前后端一体化模板的 HTTP 接口文档，涵盖认证、平台、企业、项目与示例接口。”，避免包含特定业务项目名称。
4. 现有上传接口中文文案可直接沿用；分组与摘要应表达实际用途，不能仅机械翻译类名或方法名。

## 3. 行为与权限边界

- 本次仅调整 Swagger 展示元数据；HTTP 方法、路径、全局前缀、`operationId`、Controller 与方法标识保持不变。
- 请求字段与校验、响应结构和状态码、错误、鉴权声明、访问策略、角色权限、作用域及 Service／存储行为保持不变。
- 中文操作名称通过 `summary` 提供，不通过重命名 `operationId` 实现。
- `/api-docs` 和 `/api-docs-json` 的访问入口保持不变；Swagger 文档注解不构成实际授权。
- 不修改 Web，不同步其他模板或外部业务仓库。

## 4. 数据与兼容约束

无数据库表、迁移、缓存结构或业务数据变更。OpenAPI 除 `info.title`、`info.description`、分组 `tags` 与操作 `summary` 外的结构应与变更前一致。现行成功正文、统一错误和请求关联 ID 继续遵循[主题技术契约](../技术契约.md)。

## 5. 验收标准

1. 使用真实 Nest Swagger 文档生成流程检查生产路由和包含示例的全量路由，分组与操作均有明确中文展示。
2. 对照修改前基线确认操作集合、`operationId`、参数、响应、安全等非展示结构一致。
3. 对照修改前业务 AST，确认仅改变文档元数据，没有改动处理方法或业务逻辑。
4. 执行必要的后端定向检查、类型、构建与相关回归，准确区分 handler、OpenAPI 操作数和自动化测试数。
5. 验证脚本归档至本功能 `工具/`，JSON 与日志归档至 `测试证据/`；在测试报告中明确未覆盖的外部服务与浏览器／导入工具操作。
