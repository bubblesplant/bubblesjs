## 1. 目标与范围

将当前后端接口的稳定实现约定整理为一份按需读取的项目规则，使后续新增、修改或重构接口时可以直接遵循规则，并核对相关实现，无需每次重新扫描全项目归纳约定。

本次只新增规则、接入读取条件并同步文档索引，不修改后端业务代码、依赖、数据库、HTTP 路径或接口返回结构。

## 2. 现行决策与设计

- 新建 `.agents/rules/后端接口.md`，集中说明运行时校验、访问策略与数据范围、公开响应、业务异常、事务与并发、Swagger 和验证要求。
- 根目录 `AGENTS.md` 在按需规则表中声明：新增、修改或重构后端接口，以及调整请求校验、访问策略、响应、异常或接口文档前，必须读取该规则。
- 原有代码设计、共享代码和需求文档规则继续按条件读取；新规则引用既有约定，不另立冲突的类型位置、归档或错误协议。
- Swagger 按当前项目已启用的状态保留，使用原生 Standard Schema 生成文档。迁移中的清理指移除 `nestjs-zod` 的旧适配，不代表停用 Swagger；未来是否停用须以明确的新需求更新现行文档。
- 规则区分后续接口开发要求与历史实现状态，不因新增规则而扩大为全仓接口迁移。守卫提前校验、流式响应和无响应正文等边界应明确说明。
- 规则正文作为执行指令维护在 `.agents/rules/`；本目录维护需求、决策、验收和交付状态，API 协议继续引用所属正式技术契约。

## 3. 权限与数据边界

新增文档不改变现有认证、权限和数据范围。规则须明确登录身份、操作权限与资源归属分别校验，响应和日志仅保留契约允许的公开信息，不存放真实凭据或生产数据。

## 4. 验收标准

1. 后端接口规则文件存在，`AGENTS.md` 的读取条件明确且相对链接有效。
2. 规则与现行 NestJS 原生校验、响应处理、访问策略、错误契约和 Swagger 用法一致。
3. 明确当前保留 Swagger，并区分文档注解和运行时校验、序列化、鉴权。
4. API 技术契约和 `.spaces/README.md` 可导航到本功能，无重复规则正文或平行版本。
5. 完成文档格式、引用和变更范围检查；实际未执行或未通过的检查如实记录，不借用历史业务测试作为本次验证。
