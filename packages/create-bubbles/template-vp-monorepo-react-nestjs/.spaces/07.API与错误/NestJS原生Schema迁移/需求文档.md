# NestJS 原生 Schema 迁移需求

- 状态：当前有效；NestJS 12 迁移已在工作树实现并完成框架与 HTTP／Swagger 验证，真实外部服务集成待验证。
- 日期：2026-10-14。
- 操作入口：[实施教程](./实施教程.md)。
- 现行约束：[API 与统一错误技术契约](../技术契约.md)。
- 执行结果：[测试报告](./测试报告.md)、[交付记录](./交付记录.md)。

## 1. 背景与目标

项目迁移前使用 NestJS 11、Zod 4 与 nestjs-zod 5.5.0，已有部分 Schema 和错误转换改动。本轮按现行教程补齐 NestJS 12 迁移，复用原生请求校验、响应 Schema 和 Swagger，保留用户已有代码和业务契约。

本轮安装教程指定版本、更新源码与锁文件，执行类型检查、自动化测试、构建和 HTTP／Swagger 验证。不得执行数据库迁移或平台初始化；真实数据库／Redis 流程仅在可用的本地测试环境验证，未执行项必须明确记录。

Nest 12 构建按现有 `rootDir: src` 输出到 `dist/main.js`，预览启动入口同步到实际产物位置。

本地 `pnpm-lock.yaml` 已更新并通过冻结安装；pnpm 12 将包管理器和工作区依赖分别写入两段 YAML。模板原有 `.gitignore` 忽略该锁文件，本轮保留此规则；框架版本和 Terminus 兼容性约束由 workspace 配置复现。

## 2. 实施范围

1. 核对本项目 workspace、Node、Nest 核心包与 Swagger 的版本兼容性，集中调整 catalog。
   Redis 适配包的可选健康检查依赖固定为兼容 Nest 12 的 `@nestjs/terminus@12.1.0`，避免沿用旧锁定版本造成 peer 冲突。
2. 完整移除当前 nestjs-zod 的运行时耦合，包括全局 Pipe、Interceptor、Swagger 清理、DTO 包装与异常转换。
3. 保留现有 Zod 字段规则，将认证、上传、Redis／数据库示例及项目控制器的 Body、Query、Param 接入原生 Standard Schema 校验。
4. 为认证模块的注册、登录、当前用户、退出和修改密码配置响应 Schema 与 Swagger，作为后续业务响应推广的完整样板。
5. 项目控制器五处手动校验改为参数 Schema；权限守卫所需的提前校验继续保留，不将权限逻辑移入 Pipe。
6. 给出错误契约适配、依赖检查、类型检查、测试、运行、Swagger 检查与回退步骤。

不改变数据库、会话协议、HTTP 路径、成功正文包装、权限策略与密码规则；不把所有数据库记录直接当成响应 Schema。其他业务返回值按各自既有契约后续推广，不宣称升级框架会自动规范所有响应。

## 3. 业务、权限与数据约束

- API 类型继续以 packages/shared/src/types 为正式来源；运行时 Schema 在后端复用，避免为前端重复生成 DTO 类型。
- 请求失败继续返回 HTTP 400、COMMON.VALIDATION_FAILED 与安全的 details，保留可用的 Zod issue code。
- 响应 Schema 失败属于服务端错误，返回 HTTP 500 和统一内部错误，原始异常仅进入脱敏日志。
- 守卫先于参数 Pipe 执行；权限解析依赖的 ID 校验继续使用可复用的手动 parse。
- 分页默认值、数值转换、字符串 trim、严格对象与跨字段密码校验均保持当前语义。
- 响应字段筛选不代替 Service 的公开字段选择；不把密码、Token 等私密信息扩展到公开用户 Schema。
- 上传流、下载流和错误响应不得套用普通 JSON 成功响应 Schema。

## 4. 迁移验收标准

1. Nest 核心 common／core／platform-fastify／testing 为 12.1.3，Swagger 为 12.0.2，CLI 为 12.0.8，schematics 为 12.0.7。
2. 应用、测试及依赖声明中全部 nestjs-zod 导入和旧 DTO 调用清零。
3. 认证五个接口配置响应 Schema 与 Swagger；上传流保持 binary；项目七个路由和权限不变。
4. 请求失败保持 400、COMMON.VALIDATION_FAILED 和安全字段详情；响应校验失败保持安全 500。
5. shared／server 类型检查、原生 Schema 与既有回归测试、构建、CommonJS 加载、HTTP／Swagger 结果有真实证据。
6. 同步教程、API 契约、索引、测试与交付状态，记录基线问题和真实数据库／Redis 未覆盖项。

## 5. 待确认事项与实施边界

本轮迁移无待确认产品项。文件与教程的差异应以当前源码核对，例如认证响应文件已纠正为 auth-response.dto.ts。基线因已有部分迁移而失败时应先记录并在本轮补齐；不得强制忽略 Nest peer 兼容问题。其他业务模块全面接入响应 Schema 的范围由各模块的字段与权限契约确定。
