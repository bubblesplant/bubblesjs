## 3. HTTP 与 Swagger 验证边界

[复验工具](./工具/verify-native-schema.cjs) 加载实际 SWC 产物中的 Auth、Upload、Projects 控制器，复用 AppModule 中三个全局 provider、Fastify adapter、SessionAuthGuard 与 AccessGuard；业务、会话和权限服务使用内存替身，不连接 PostgreSQL、Redis 或对象存储。

覆盖认证五个接口的响应白名单、trim、改密跨字段规则、400 字段路径与 issue code、安全 500、请求 ID、401 Bearer 质询；上传 Body／Param、严格对象、UUID、partNumber 数值转换与二进制流；项目分页 default／coerce／trim／strict、守卫提前校验 ID、403 先于 Pipe、七条既有路由。Swagger 直接通过 Nest 12 从这些编译产物生成。

未执行完整 AppModule 原样启动、真实注册／登录／会话撤销、数据库权限读写、真实分片上传／下载／取消、队列消费者及数据库／Redis 示例模块运行。完整启动会执行权限／菜单／角色 seed，真实集成开关可能创建测试库并跑迁移；本轮未开启这些流程、未执行 `db:migrate` 或 `access:init`。33 个跳过项不计为通过。

## 5. 历史 SWC 复验（仅适用于当时版本）

在项目根目录按顺序执行。HTTP 工具必须使用新构建的 shared 和 server 产物：

```powershell
vp install --frozen-lockfile
pnpm --filter shared build
pnpm --filter server exec tsc --noEmit -p tsconfig.json
pnpm --filter server test
pnpm --filter shared test
pnpm --filter server build
$migrationVerifier = Join-Path (Get-Location).Path '.spaces/07.API与错误/NestJS原生Schema迁移/工具/verify-native-schema.cjs'
pnpm --filter server exec cross-env TS_NODE_PROJECT=tsconfig.scripts.json node -r ts-node/register/transpile-only -r tsconfig-paths/register $migrationVerifier --commonjs
node $migrationVerifier
```

工具会更新本功能的安全 JSON 摘要，不记录请求凭据、密码或业务正文。新增 8 项迁移测试位于 `apps/server/test/schema/native-schema.spec.ts`。SWC 配置仍不进行类型检查，因此不能省略 `tsc`。
