## 1. 实现范围

1. workspace catalog 固定 Nest 核心／testing 12.1.3、Swagger 12.0.2、CLI 12.0.8、schematics 12.0.7；删除 nestjs-zod 声明及应用／测试导入。
2. AppModule 注册原生 StandardSchemaValidationPipe 与 StandardSchemaSerializerInterceptor。开启 transform，使 trim、coerce、default 与字段剥离结果进入业务方法；通过 exceptionFactory 和 shared 的 toValidationDetails 保持 `COMMON.VALIDATION_FAILED` 及安全详情。现有 Filter 继续处理统一错误、安全 500 与请求 ID。
3. 认证请求改为普通 Zod Schema，Service 参数使用 shared 请求类型；注册、登录、当前用户、退出、改密五个响应均声明 Schema，并复用为 Swagger standardSchema。认证响应路径统一为 `auth-response.dto.ts`。
4. 上传 Body／Param 接入 Schema，新增 shared 上传类型；保留二进制流、取消、清理与对象存储边界。Redis／数据库示例去除旧 DTO 包装，Redis 使用整个 Query，数据库保留 Drizzle 生成 Schema；示例模块未启用。
5. 项目控制器五处手动校验改为参数 Schema，七个路由及权限保持原契约；守卫所需的提前校验继续调用 parse。补齐手动 parse 遗漏的返回值，使已有调用取得转换后的数据。
6. 新增 8 项迁移测试与编译后 HTTP／Swagger 复验工具；同步教程、技术契约、空间索引及数据库运维技术栈说明。
7. scoped override 固定 ioredis 适配包可选的 Terminus 12.1.0，清除 Nest peer 冲突；`build:preview` 改为实际 SWC 入口 `node dist/main.js`。

迁移不更改数据库表结构、会话协议、HTTP 路径或成功正文包装。认证之外的所有业务响应 Schema 尚未全面推广，仍按各模块现有公开字段契约运行。

## 2. 依赖与启动

本地 `pnpm-lock.yaml` 已真实更新并通过 `vp install --frozen-lockfile`。pnpm 12 在锁文件中分别写入包管理器与工作区两段 YAML；Nest 12 与 Terminus 的实际版本位于第二段。该文件原本被模板 `.gitignore` 忽略，本轮保留此设置，未强制加入 Git；固定版本及兼容性约束已写入可版本管理的 `pnpm-workspace.yaml`。复制模板后执行 `vp install` 重新生成锁文件；要求部署严格复现时应由使用项目决定保留其完整锁文件。

先构建 shared，再构建 server；完整应用启动前准备数据库、会话 Redis、队列 Redis 和对象存储。启动会自动同步权限、默认菜单和内置角色，并初始化存储与队列。本轮没有执行完整原样启动、数据库迁移、平台初始化或真实外部服务联调；HTTP 28 场景使用内存服务替身，具体边界见测试报告。
