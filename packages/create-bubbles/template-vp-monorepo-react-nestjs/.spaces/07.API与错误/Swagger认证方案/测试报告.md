## Swagger 验证方式

在模板根目录执行：

```powershell
vp exec node .spaces/07.API与错误/Swagger认证方案/工具/verify-session-auth.cjs
```

[验证工具](./工具/verify-session-auth.cjs)在独立 Node 子进程中分别加载本轮开始前的 Git HEAD 与当前服务端源码，避免模块缓存交叉。工具通过受限 AST 读取实际 `main.ts` 的 DocumentBuilder 配置及 `swagger.constants.ts`，并使用真实认证、企业、字典、上传 Controller 与构造器服务替身生成文档，不执行启动文件。基线子进程按 Git 文件清单解析旧模块，再通过 `git show` 读取历史源码，支持旧常量文件已从工作树移除的情况，无需生产兼容转发文件。

实际验证 `components.securitySchemes` 仍为 `session` 的不透明令牌 Bearer 方案；完整文档及各操作 `security` 与 HEAD 一致。工具自己的格式、lint 与类型检查通过，见[工具检查日志](./测试证据/verification-tool-check.txt)；6 个相关文档的 `vp fmt --check` 结果见[文档格式检查日志](./测试证据/documentation-check.txt)。未覆盖其他功能的历史 OpenAPI 基线或证据。
