# Swagger 认证方案常量

- 状态：当前有效；常量按职责拆分及文件命名调整已实现并完成本地验证，实际范围见 [测试报告](./测试报告.md)。
- 日期：2026-10-26。

## 目标与范围

将 Swagger 认证方案名称提取为服务端共享常量，避免 `main.ts` 注册名称与 Controller 引用名称依赖重复字符串约定。

范围为 Swagger 启动配置、现有四个 Controller 的六处 `ApiBearerAuth`、两处测试文档配置、公共常量文件命名及所有调用方，以及现行后端规则和教程示例。接口路径、请求与响应、权限边界、Token 格式及 Redis 会话逻辑保持现行契约。

## 设计与契约

- 在 `apps/server/src/common/constants/swagger.constants.ts` 导出 `SWAGGER_SESSION_AUTH = 'session'`，由模块显式导入；Swagger 文档常量与运行时鉴权常量分别维护，不引入可变全局变量、环境配置或前端共享包依赖。
- 同目录的 `auth.ts`、`response.ts` 分别改名为 `auth.constants.ts`、`response.constants.ts`，保留 `IS_PUBLIC_KEY` 和 `ContentTypeEnum` 的导出与含义；源码、测试、验证工具和现行文档同步引用新路径，不保留旧路径转发文件。
- `DocumentBuilder.addBearerAuth` 的方案名称和 `ApiBearerAuth` 的参数统一引用该常量，测试配置使用同一来源。
- 方案值保持 `session`，生成的 OpenAPI `components.securitySchemes.session` 和各操作的 `security` 引用保持一致。
- 修正启动配置中“仅 JWT 需要 Bearer 配置”的误导注释；当前不透明 Session Token 同样通过 `Authorization: Bearer <token>` 传输。
- Swagger 注解只描述文档，运行时登录及权限仍由现有守卫和访问策略执行；退出登录的 `@Public()` 与幂等行为不变。

## 验收标准

1. 服务端源码和现行测试的 Swagger 认证配置不再重复硬编码方案名称。
2. 类型与受影响文件检查通过，现有相关回归通过；外部数据库集成未启用时明确记录跳过。
3. 实际生成 Swagger 文档，确认认证方案注册及现有操作引用与修改前一致，不覆盖其他功能的历史证据。
4. 文档示例、后端规则与实现使用同一常量名称。
5. 三类常量分别位于 `swagger.constants.ts`、`auth.constants.ts`、`response.constants.ts`，有效代码引用不再使用旧文件路径；`auth-response.dto.ts` 不属于本次命名调整。
