# 前端请求层适配

- 状态：2026-10-23 兼容迁移、登录成功重置与统一本地会话清理已实施并完成专项验证，全量检查边界见测试报告。
- 背景：用户已将 Web 请求层改为 `createAlovaInstanceFactory`、命名导出的 `alovaRequest` 和原生 Axios 响应／异常拦截器，现有工作空间与部分认证调用仍使用旧工厂接口。

## 目标与范围

1. 适配 `workspace.ts` 及 Web 内对通用请求、工作空间请求的引用，采用新实例与拦截器契约。
2. 保留现有空间切换、换号、取消和请求代次隔离；旧请求的成功、401、403 均不得影响新空间或新会话。
3. 登录、注册继续不附带旧令牌，失败交给表单展示；权限及管理请求继续禁用缓存和请求共享，由现有页面反馈错误。
4. 成功默认返回业务正文，异常保留原始 `AxiosError`。现有页面读取服务端公开错误消息，保持冲突提示与用户输入保留行为。
5. 同步旧契约测试，运行定向测试、类型检查及受影响检查，记录实际验证范围。
6. 登录成功保存新令牌后重置 `unauthorizedHandled`，允许同一 SPA 中后续会话再次触发失效提示与导航；登录失败不重置。
7. 普通请求与有效空间／会话请求的 401 共用本地清理入口：删除 token、中止空间及 store 在途操作、清用户／权限与字典内存、移除工作空间和字典快照。token 已自然过期时也必须清理；保留语言、主题等无关设置。

## 边界与待确认事项

- 不回退用户重写的三个请求文件，不恢复旧双调用工厂、包装响应或业务码转换。
- 本次维护已有业务行为，不修改后端接口、权限规则、403 刷新策略或会话协议。
- 用户已确认先实现登录成功重置 401 去重标记及统一本地会话清理。普通请求主动取消的提示策略、普通请求换号后的迟到 401 保护仍待用户决定，不在本轮扩展。

## 验收标准

- Web 业务代码不再使用默认导入的旧 `request(config)` 或已删除的配置项。
- 登录／注册失败不触发全局登录导航，且能展示服务端公开文案。
- 工作空间迟到响应仍被丢弃；当前 401 统一进入登录失效提示／导航；403 保留已有防递归逻辑。
- 错误对象保持 Axios 原始形态，现有页面仍显示业务文案。
- 首次 401 同步清理本地会话，重复 401 不重复提示与导航；重新登录成功后下一次 401 仍执行清理、提示与导航。token 已不存在时也清除会话内存与专属快照。
- 测试与类型检查依据[技术契约](./技术契约.md)记录，范围外失败如实列出。
