## 产品定位建议

提供 Node.js + TypeScript SDK。调用方配置模型、提示词、工具、技能及子代理后，由运行时完成模型调用、工具执行、等待与结果汇总。

SDK 核心与具体业务、HTTP 框架和桌面界面解耦。后端宿主负责身份、业务授权、凭证和对外任务状态；客户端按公开协议收发命令和事件；桌面负责会话展示和用户操作。其他 Node.js 应用可以直接使用 SDK，不必启动桌面应用或服务。

下面的 P0／P1／P2 延续原功能清单，表示建议能力分层，不代表本轮已确定交付顺序。先用一个真实任务确定首个闭环；执行中提问作为既有首期目标，不因分批实现而默认取消。

### 初始化配置建议

按用途分组，避免一个初始化对象混入全部宿主业务参数：

- 身份与行为：标识、名称、描述、system prompt。
- 模型：主模型、备用模型、服务地址、能力配置及凭证引用。建议进一步分开模型元数据、默认调用参数、思考预设、Agent 选择及本次调用覆盖项；具体结构见设计草案，尚未确认。
- 上下文：区分实际模型窗口、最大输入／输出、应用使用上限和压缩策略。容量校验与自动摘要分开；自动上下文压缩仍属于原 P1 建议，首批范围未变。
- 能力：function 工具、MCP 服务、Skills、可用子代理或模板。
- 执行策略：作用域、工具授权、审批、超时、预算、并发及嵌套限制。
- 运行依赖：状态存储、事件接收器、日志及可选生命周期扩展。

用户身份、session、当前任务输入、父运行关联与取消信号属于每次运行的上下文；不能通过改写全局初始化配置传递。

## 关键行为约束

1. 创建实例不等于开启一次会话；会话不等于单次运行。实例复用不能共享不同用户的可变历史。
2. 子代理复用相同内核，每次委派创建独立子运行；默认只获得任务需要的上下文，不自动继承全部历史和凭证。
3. 动态创建仅使用宿主开放的模板与能力覆盖项；模型不能任意指定新凭证、提权或无限递归。
4. 用户澄清与操作审批是两种不同状态。补充问题答案不能被当成业务写入授权。
5. 等待用户不占用模型请求或活跃工作名额；等待期间的执行计时、交互有效期和整树截止规则在实施前明确。
6. 模型、工具和权限错误分别处理。主备切换不重复已经完成的写操作；结果未知的操作不能自动重试。
7. 工具白名单与工作区路径检查属于应用策略，不等同于操作系统沙箱；取消也不能保证撤销已经发生的远端操作。
8. 关闭父实例不能无条件关闭调用方提供并被其他实例复用的子代理或连接。
9. 事件用于展示进度、操作与结果，不承诺暴露模型内部完整推理过程。
10. API 密钥和工具凭证保留在可信的 Node.js 宿主；浏览器可共享公开事件类型，不能导入含凭证的核心运行时。

## 建议验收场景

- 从 Node.js 直接调用 SDK 不需要监听 HTTP 端口；桌面能通过公开协议连接服务，不加载内核和模型凭证。通过替换可控的模型适配器验证这两条路径共享同一运行语义。
- 通过不同配置初始化两个实例，各自调用自己的模型与工具，历史和凭证不串用。
- 一个实例先独立运行，再作为其他实例的子代理运行，复用初始化抽象且保持会话隔离。
- 父运行根据任务动态启动 A／B，等待两者完成后将结果交给 C；失败、取消、超时及依赖失败均有确定结果。
- 并发名额较少时，父任务等待子任务不会占满工作名额造成死锁；嵌套、循环等待及整树预算受到约束。
- 子代理提出问题后可统一展示，用户回答后继续原 run，重复或越权回答不能触发执行；若首批承诺界面重连，还需验证同进程内断开界面再连接后仍能查询并回答原问题。
- 工具已成功执行后模型发生故障，备用模型继续处理已有结果，不重复执行工具副作用。
- 模型配置专项建议验证：每个主备模型独立校验思考参数和输入／输出限制；同模型不同预设并发时参数互不污染；切到更小窗口时重新检查上下文，超过限制时按已启用策略压缩或明确拒绝。具体批次待确认。
- 父运行取消能终止其树内后续调度，其他独立运行继续；共享子代理实例仍可被其他调用方使用。
- 无模型密钥时可以使用模拟适配器完成自动化验证；真实模型、MCP、浏览器与 PC 操作必须分别留下真实验证记录。

| 4    | 首期如何分批？                                         | 单次执行、工具扩展、提问续接、动态委派各批验收，不将完整 P0 默认纳入一次施工。         |
| 5    | 底层引擎与公开 API 如何确定？                          | 原生运行内核或框架，统一入口、事件、任务句柄、输入输出契约；历史名称与默认值均须复核。 |

主备切换、部分流式输出后的处理、审批策略、Skills 脚本范围、MCP 传输与认证、会话保留和资源所有权，随对应功能确认。包名、ESM 与 Node.js 声明保留为现有工程信息；新增依赖与实际兼容范围在实施前核验。

模型接入补充议题：OpenAI Chat Completions、OpenAI Responses 与 Anthropic Messages 是否同时纳入首批；协议适配器采用内置注册、宿主注入或二者兼有；同一网关的不同协议是否使用独立连接标识。多协议能力与可恢复故障时的备用模型切换分别定义，配置多种协议不代表每次请求自动尝试所有协议。

模型配置补充议题：思考模式、强度或 token 额度如何按模型声明；是否提供 fast／deep 等具名预设；模型窗口、应用输入上限、输出预留和压缩阈值如何表达；不支持或冲突的参数如何报错，以及切换备用模型时如何重新解析。上述讨论不自动确认统一参数名、压缩实现或默认预算。
