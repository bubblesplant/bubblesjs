## 本轮运行时实施范围

- `bootstrapAgent()` 统一创建主代理、同进程子代理与独立 Node.js 进程代理。进程从可信模块工厂重建配置和客户端，不通过 IPC 序列化函数或模型密钥。
- Anthropic Messages、OpenAI Chat Completions 适配，当前请求故障 fallback，Zod 参数校验、本地工具循环及宿主授权。
- 实例、session、run 分层，会话内串行、会话间并发，成功运行提交历史；AsyncLocalStorage 隔离异步身份。
- 仅允许声明的子代理；支持显式并行委派，父子取消传播，深度及整树请求、工具、子任务、已报告 token 限额。
- 生命周期事件、资源释放、确定性测试、产物和真实模型验证；首批事件按模型回合发出，不提供 token delta。
- 本批不实现 MCP、Skills、后台 DAG 队列、提问与审批恢复、持久化、结构化最终结果、多模态、NestJS 与 Web／PC 执行器，不等同于完整 P0。
- API、默认预算和兼容边界见[技术契约](./技术契约.md)。真实密钥仅用于测试进程环境，不进入源码、文档或证据。

## 产品定位建议

提供 Node.js + TypeScript SDK。调用方配置模型、提示词、工具、技能及子代理后，由运行时完成模型调用、工具执行、等待与结果汇总。

SDK 核心与具体业务、NestJS 控制器、Web 页面和桌面界面解耦。宿主负责身份、业务授权、凭证配置与界面展示；核心负责运行状态、调用循环和统一事件。

下面的 P0／P1／P2 表示建议实施顺序，尚未确认的项目不作为既定交付承诺。

| A03  | 任务执行循环         | 完成“模型提出操作 → 校验与执行工具 → 回传结果 → 继续或结束”；返回明确状态、结果及失败原因，支持按 Schema 校验结构化结果。                       |
| A04  | 本地函数工具         | 统一名称、说明、参数 Schema、执行函数、错误格式、超时与取消；每次实际执行均经过宿主策略校验。                                                   |

| A07  | 会话与上下文         | 区分 Agent 实例、session 和 run；同实例可服务多个隔离会话，同会话默认顺序执行；主子代理仅共享明确传入的信息。首期采用进程内状态。               |

| A12  | 执行限额与取消       | 提供超时、步骤、模型调用、token、子任务数量、嵌套深度及并发限制；约束覆盖整棵任务树，父运行取消传播到其子运行。                                 |
| A13  | 工具权限与作用域     | 宿主传入身份和执行策略，限制工具、路径、进程及业务操作；子代理授权不超过调用方与委派范围。需要确认的操作通过独立审批状态处理。                  |

### 初始化配置建议

按用途分组，避免一个初始化对象混入全部宿主业务参数：

- 身份与行为：标识、名称、描述、system prompt。
- 模型：主模型、备用模型、服务地址、能力配置及凭证引用。
- 能力：function 工具、MCP 服务、Skills、可用子代理或模板。
- 执行策略：作用域、工具授权、审批、超时、预算、并发及嵌套限制。
- 运行依赖：状态存储、事件接收器、日志及可选生命周期扩展。

用户身份、session、当前任务输入、父运行关联与取消信号属于每次运行的上下文；不能通过改写全局初始化配置传递。

## 关键行为约束

1. 创建实例不等于开启一次会话；会话不等于单次运行。实例复用不能共享不同用户的可变历史。
2. 子代理复用相同内核，每次委派创建独立子运行；默认只获得任务需要的上下文，不自动继承全部历史和凭证。
3. 动态创建仅使用宿主开放的模板与能力覆盖项；模型不能任意指定新凭证、提权或无限递归。
4. 用户澄清与操作审批是两种不同状态。补充问题答案不能被当成业务写入授权。
5. 等待用户不占用模型请求或活跃工作名额；等待期间的执行计时、交互有效期和整树截止规则在实施前明确。
6. 模型、工具和权限错误分别处理。主备切换不重复已经完成的写操作；结果未知的操作不能自动重试。
7. 工具白名单与工作区路径检查属于应用策略，不等同于操作系统沙箱；取消也不能保证撤销已经发生的远端操作。
8. 关闭父实例不能无条件关闭调用方提供并被其他实例复用的子代理或连接。
9. 事件用于展示进度、操作与结果，不承诺暴露模型内部完整推理过程。
10. API 密钥和工具凭证保留在可信的 Node.js 宿主；浏览器可共享公开事件类型，不能导入含凭证的核心运行时。

## 建议验收场景

- 通过不同配置初始化两个实例，各自调用自己的模型与工具，历史和凭证不串用。
- 一个实例先独立运行，再作为其他实例的子代理运行，复用初始化抽象且保持会话隔离。
- 父运行根据任务动态启动 A／B，等待两者完成后将结果交给 C；失败、取消、超时及依赖失败均有确定结果。
- 并发名额较少时，父任务等待子任务不会占满工作名额造成死锁；嵌套、循环等待及整树预算受到约束。
- 子代理提出问题后可统一展示；同进程内断开界面再连接，仍能查询问题并恢复原 run，重复或越权回答不能触发执行。
- 工具已成功执行后模型发生故障，备用模型继续处理已有结果，不重复执行工具副作用。
- 父运行取消能终止其树内后续调度，其他独立运行继续；共享子代理实例仍可被其他调用方使用。
- 无模型密钥时可以使用模拟适配器完成自动化验证；真实模型、MCP、浏览器与 PC 操作必须分别留下真实验证记录。
