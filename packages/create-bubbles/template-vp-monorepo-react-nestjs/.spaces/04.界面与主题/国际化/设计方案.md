# 前端国际化设计方案

## 统一状态

`@bubblesjs/i18n-core` store 是唯一语言状态源。`apps/web/src/i18n/config.ts` 集中维护应用 locale 及其适配标识，`ui-locale.ts` 将应用 locale 映射为：

- antd 的 `Locale` 对象；
- Pro Components 的 `IntlType`（`zhCNIntl` / `enUSIntl`）；
- Day.js locale 标识（`zh-cn` / `en`）；
- `<html lang>` 标识。

## 渲染与副作用

`App.tsx` 在渲染时将 antd locale 和 Pro `intl` 传入 Provider；在 locale 变化后的 effect 中设置 Day.js 全局 locale 和 `<html lang>`。这样静态组件配置会随 React 重新渲染，日期库的全局副作用也只在语言变化时执行。

## 扩展约束

新增语言时必须同时补充词条加载器、`APP_LOCALE_ADAPTERS`、antd locale 包、Pro Components intl 以及 Day.js locale 导入，并执行 `pnpm i18n:check` 与前端构建。

## CLI 调用边界注释

状态：已实现，依据 [需求文档](./需求文档.md) 的 CLI 调用边界注释支持要求；执行证据见 [测试报告](./测试报告.md)。

扫描器在调用名后、左括号后和解析出的静态字符串后使用同一个内部方法跳过空白、`//` 行注释及 `/* ... */` 块注释。行注释以 LF、CR、U+2028 或 U+2029 结束，未闭合块注释视为未找到有效后续 token。原始源码不做预处理或删除，因此词条正文、转义和源码行列位置保持精确。

字符串解析仍由原有逻辑处理；边界注释之后只接受既有引号、逗号或右括号，不放宽动态表达式限制。扫描器仍按文本扫描全文，保持注释或普通字符串内完整调用也会被提取的既有约定。

## React selector 快照缓存

状态：2026-10-09 验证通过。React hook 使用 `useMemo([store, selector])` 创建独立快照闭包，对同一 state 引用复用 selector 结果。具名和内联对象 selector 均稳定渲染，state 更新后 DOM 正确变化；这是快照稳定性修复，尚未提供跨 state 的选择结果相等比较，也未增加 SSR 快照。完整发布结论仍以 [发布评估](./发布评估.md) 为准。
