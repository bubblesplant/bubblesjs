# i18n 独立包发布评估

> 状态：验证记录。日期：2026-10-09。结论：CLI 注释提取与 React selector 缓存已验证通过，当前版本仍不宜直接发布。

## 评估范围

依据 [需求文档](./需求文档.md)，重新检查 `@bubblesjs/i18n-core`、`@bubblesjs/i18n-react`、`@bubblesjs/i18n-vue` 和 `@bubblesjs/i18n-cli` 的独立 npm 发布准备情况。本轮对用户修改的 React selector 缓存执行真实渲染验证，重跑构建、CLI 测试、UI locale 测试、类型/格式检查及本地打包。未修改业务实现、包配置或执行 npm 发布。

## 结论与包边界

方案可以作为轻量国际化库发布，定位是字符串 key、扁平 JSON 词条、占位符插值、异步语言加载、React/Vue 订阅和词条维护 CLI。核心与适配层没有业务应用依赖，React/Vue 已声明框架 peerDependencies，构建也将框架排除出 bundle。

建议保持现有四包，版本协调发布：core 提供运行时，react/vue 提供按需框架适配，cli 作为开发依赖。若需要统一入口，可后续增加聚合包；单一包不是此次独立发布的前提。应用内 antd、Pro Components、Day.js 和 `<html lang>` 的映射继续作为接入示例。

## 技术发布阻塞

| 问题                                | 当前证据                                                                                                                                        | 整改要求                                                                      |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 四包禁止发布且公开入口为源码        | 四个 `package.json` 均 `private: true`；`exports.types/import` 指向 `src/*.ts` 或 `*.tsx`，CLI `bin` 也指向 TS 源码                             | 调整发布元数据，入口引用构建后的 JS 与声明文件，CLI `bin` 引用 `dist/cli.mjs` |
| 构建产物未进入实际 tarball          | 四包构建成功，但 core/react/vue 的 dry-run 清单和实际 tarball 均完全没有 `dist`，仅有源码和开发配置                                             | 用 `files` 白名单明确包含 dist、README 和许可证；增加打包前构建步骤           |
| CLI 在 Windows 当前检出状态不能打包 | `pnpm --dir packages/i18n/cli pack --dry-run --json` 返回 `ERR_PNPM_BIN_CRLF`，shebang 为 CRLF                                                  | 将 bin 指向构建后的可执行入口，并确保发布入口使用 LF，验证权限与命令可执行性  |
| core 独立检查不通过                 | `vp check --no-fmt packages/i18n` 在 `core/src/i18n.ts:41,74` 报 `TS2584: Cannot find name 'console'`；lib tsconfig 只包含 ES2020 且 types 为空 | 校准核心包声明环境或日志实现，独立 lint/type check 必须通过                   |

相关配置：[core](../../../packages/i18n/core/package.json)、[React](../../../packages/i18n/react/package.json)、[Vue](../../../packages/i18n/vue/package.json)、[CLI](../../../packages/i18n/cli/package.json)。运行时包产物为 `dist/index.js`、`dist/index.d.ts`；CLI 库入口为 `dist/index.mjs`、`dist/index.d.mts`，不能将 CLI 的声明入口误写为 `.d.ts`。

工作区源码入口能被 Vite 消费，不代表普通安装环境可用。以 `--preserve-symlinks` 模拟 node_modules 路径的 Node 导入，core 返回 `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`，React 返回 `.tsx` 的 `ERR_UNKNOWN_FILE_EXTENSION`。

`workspace:*` 与 `catalog:` 本身不是缺陷：本轮实际检查 core/react/vue tarball，pnpm 已把适配包的 core 依赖转换为 `0.0.0`，并把 catalog 开发依赖转换为真实版本范围。发布应使用能够执行这种转换的打包流程；CLI 因 CRLF 阻塞，本次没有生成其实际 tarball。

## 建议发布前修复的行为缺陷

| 优先级 | 问题和触发条件                                                                                                                      | 定位与建议                                                                                                                                                          |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1     | 异步语言切换按完成顺序提交。先请求 en_US，再请求 zh_CN，zh_CN 先完成、en_US 后完成，最终语言错误地变回 en_US                        | [core/i18n.ts](../../../packages/i18n/core/src/i18n.ts) 第 36–47 行；增加请求序号，只提交最后一次请求的结果                                                         |
| P2     | 缺失词条读取 Object 原型链：`tr('toString')` 返回函数，`tr('constructor', { a: 1 })` 抛错；缺失 `{toString}` 插值会输出原生函数文本 | [core/i18n.ts](../../../packages/i18n/core/src/i18n.ts) 第 34 行和 [format.ts](../../../packages/i18n/core/src/format.ts) 第 8 行；查词条与插值参数时只允许自有属性 |
| P2     | CLI include 匹配零源文件时，`check` 仍输出 `Check passed.` 并返回 0，不能可靠发现扫描范围配置错误                                   | [command.ts](../../../packages/i18n/cli/src/command.ts) 第 116、189–199 行；默认拒绝零源文件检查，允许空项目时应使用明确配置                                        |

初次 CLI 删除问题通过 `--dry-run` 复现，没有真正删除词条；两个场景的语言包 SHA256 前后完全相同。运行时复现的预期结果是确认当前缺陷，不能将其记为产品测试通过。

### 已修复：React 对象 selector 快照不稳定

[use-store.ts](../../../packages/i18n/react/src/use-store.ts) 第 13–24 行使用独立闭包缓存，同一 state 引用复用 selector 结果。本轮真实 React DOM 检查具名与内联对象 selector，均渲染 2 次，状态更新后 DOM 从 en_US 变为 zh_CN，无警告或异常，已撤销无限更新缺陷。另行只读验证 StrictMode 下父级重渲染、state 更新及 store 替换，结果也正常。当前 React 版本为 19.3.0；未执行完整 React 18/19 版本矩阵。缓存仍不提供跨 state 的可选相等比较，这是优化范围；SSR 仍见下述限制。

### 已修复：CLI 调用边界注释漏提取

`tr(/*说明*/ '保留')` 等静态调用现在可以正常提取。[scanner.ts](../../../packages/i18n/cli/src/scanner.ts) 在调用名后、左括号后和字符串后跳过空白、行注释与块注释；字符串正文和动态表达式限制保持原有规则。新增 16 个扫描用例及 1 个实际 `sync --clean` 用例，本轮重新执行 CLI 共 71 个测试通过。相同 dry-run 场景识别两个词条，`deleted` 为空、`unchangedCount` 为 2，语言包 SHA256 不变。当前证据见 [当前复验](./测试证据/cli-扫描边界/当前复验.json)；首次修复证据见 [注释回归](./测试证据/cli-扫描边界/注释回归.json)。

## 首发支持范围与其他建议

- React SSR 当前不可用：`useSyncExternalStore` 缺少 `getServerSnapshot`，`renderToString` 报 `Missing getServerSnapshot`。如首发承诺 SSR，需要修复并定义服务端快照；仅支持浏览器渲染时应在 README 明确。
- Vue Provider 在 setup 中只注入一次 `props.store`，替换 prop 后后代仍使用旧 store。应支持替换，或明确实例初始化后保持不变的契约。
- core 公开导出的 `shallowEqualObject({ first: undefined }, { second: undefined })` 错误返回 true。建议检查键是否同时存在，或缩小公共工具的导出范围。
- 发布包目前缺少许可证、仓库与发布说明；core/react/vue 缺少 README。补充各包安装、最小接入、支持环境、语言加载失败语义和 API 文档。版本 `0.0.0` 合法，但建议确定一致的预发布版本与依赖范围。
- 当前仅输出 ESM 可以作为首发范围，不必为了发布强制增加 CJS。复数、ICU、命名空间等能力属于扩展选择，不是此次技术发布阻塞。
- CLI 文本扫描会提取注释或普通字符串中的完整 `tr(...)`，README 已声明这一边界。Excel 同步文档属于尚未实施的规划，不能作为已交付功能宣传。

## 达到可发布状态的验收

1. 四包通过独立构建、类型和格式检查，公开入口与 tarball 内文件一致；CLI 在声明的 Node 环境下可执行。
2. 修复 P1 行为缺陷及词条查找契约错误，补充对应回归测试。
3. 明确 SSR、Vue store 替换和 ESM 的支持范围，完成 README、许可证、版本与发布元数据。
4. 用真实 tarball 在隔离消费者工程中验证安装、类型解析、core 翻译、React/Vue 订阅和 CLI sync/check；不依赖本仓库的源码别名或开发脚本。
5. 依赖协议正确转换、core 版本可被适配包解析后，再进行协调的预发布。
