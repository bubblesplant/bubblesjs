# 前端国际化需求

## 目标

应用语言切换必须由同一份 locale 状态驱动，确保业务词条、Ant Design、Ant Design Pro Components、Day.js 以及文档语言属性同步变化。

## 范围

- 当前支持 `zh_CN`（简体中文）和 `en_US`（English）。
- 切换结果继续由现有 i18n store 持久化。
- Ant Design 组件文案、Pro Components 内置文案和 Day.js 日期/相对时间格式必须与当前语言一致。
- 浏览器 `<html lang>` 必须同步更新。

## 验收标准

1. 初始语言、持久化语言和运行时切换均使用同一 locale 状态。
2. 切换到英文后，antd、Pro Components、Day.js 和 `<html lang>` 均使用英文配置；切回中文后恢复中文配置。
3. 新增语言时只需扩展集中式映射，并能明确补充对应组件库和 Day.js locale。

## 独立包发布评估

- 状态：2026-10-09 复验完成；CLI 注释提取及 React 对象 selector 缓存均已验证通过，四包构建成功，但发布入口、实际 tarball、CLI 打包、core 类型检查及剩余运行时缺陷仍阻止直接发布。此次仅检查发布准备情况，未修改业务实现或执行发布。
- 范围：`packages/i18n/` 下的 core、React、Vue、CLI 四个包。
- 验收：检查包边界、公开入口、构建与类型产物、依赖转换、包外消费及已有测试，区分发布阻塞与后续增强建议。
- 评估结果与执行证据归档于 [发布评估](./发布评估.md)。

## CLI 调用边界注释支持

- 状态：已实现；CLI 71 个测试、构建及修改文件的格式、lint、类型检查通过。
- 范围：保留文本扫描方式，在调用名与左括号之间、左括号与静态字符串之间、静态字符串与逗号或右括号之间，将空白、行注释和块注释作为可跳过的分隔内容。
- 字符串内部的注释符号属于词条正文，必须原样保留；注释后仍是动态表达式时继续忽略。
- 保留既有行为：注释或普通字符串内出现完整静态 `tr()` 调用时仍会提取。
- 验收：带边界注释的静态调用能被提取；未闭合块注释不匹配；行列位置正确；`sync --clean` 保留对应已有翻译，只删除真正未使用的词条。
