## 2. 背景与目标

调整前，`/workspaces` 页头将用户名、语言切换、修改密码和退出登录连续平铺，账号信息与账号操作缺少层次。用户要求重新设计该区域，减少横向占用，并使操作归属更清楚。

本次将账号操作集中到账号菜单，保留方便访问的语言切换，使桌面、窄屏和长用户名场景均有清晰、紧凑的页头。

账号区收纳完成后，用户反馈头部 hover 抖动，要求检查是否由悬停样式引起重排。纯视觉反馈应优先使用重绘或合成阶段的属性，不改变布局；边框先预留宽度，需要显隐的背景、阴影优先在默认状态声明并以透明颜色隐藏。调整前隔离 Chromium 检查未复现用户可见抖动：两个按钮已预留透明边框，悬停前后及 30 帧几何无变化；排除卡片浮动动效干扰后，账号 hover 的 `LayoutCount` 增量为 0，存在样式重算，见[历史基线证据](./测试证据/hover-baseline.json)。当时确认按钮继承的 `transition-property: all` 是过渡范围风险，不能据此断言它是用户反馈的确定根因；共享头部此前结果见增量前 12 场景基线。

用户明确产品面向多语言，已选择并实施 C 列表 Popover。页头入口只保留截图中的小翻译图标，不显示语言名称、代码或下拉箭头；点击图标打开带标题及语言列表的 Popover，其箭头指向触发图标，点击语言完成切换。新增实际注册总数≤5隐藏搜索、>5显示的要求已实现并通过本轮定向验收，少量语言不再额外占用搜索空间。方案支持语言数量增长，不把产品限制为中英两种语言。共享账号菜单已覆盖工作空间、企业级、项目级及平台头部，头像入口收纳改密、退出，切换空间独立保留；当前 12 场景报告为本轮重新执行结果。

现有[三方案预览图](./ui/language-switch-options.png)、[静态样稿](./ui/language-switch-options.html)及[渲染工具](./工具/language-switch-preview.mjs)作为方案比选的静态基线保留，用户已选定其中 C，A／B 不再作为待选方案。该图为 1500×1207px，已成功解码并目视检查，静态样稿无溢出；由本地 HTML／CSS、Edge headless 和示例数据渲染。每候选展示 12 种示例语言，入口为 16px 翻译图标及 32×32px 点击区域；C 搜索框为只读静态示意，原图不能证明搜索、箭头定位或实际语言切换已实现、已验收，不代表新增 12 种实际产品语言或翻译。

## 3. 范围与业务规则

- 空间切换入口点击后返回 `/workspaces`。左侧类型、当前名称、切换图标及“切换空间”合成单一链接，无下拉箭头；右侧仅保留语言与账户。平台、企业和项目共用布局。
- 选择页每张卡片展示类型、管理员／成员角色、名称、项目所属企业及一个进入动作；刚离开的空间标记为“当前空间”，该卡片动作显示“返回空间”。当前项由头部导航携带真实作用域键，并与最新授权清单匹配；标题区同时提供“返回当前空间 + 名称”快捷链接，即使当前卡片位于其他页或被筛选隐藏仍可返回。直接进入选择页或原空间已撤权时不猜测当前项，隐藏该快捷链接。
- 清单沿用现有授权接口，前端按空间名及所属企业名忽略大小写、去除搜索首尾空白进行检索，与类型和企业筛选共同生效。类型分类计数基于搜索与企业筛选后的清单；企业选项按公司 ID 去重，包含只有项目访问资格的所属企业，选择企业时仅显示该企业及其项目，平台不属于企业。DTO 的 `companyName` 为可选字段，同一企业存在企业入口时优先使用该入口的名称；仅有项目入口时使用已取得的所属企业名称，仍缺失则回退企业 ID，不把项目名当作企业名。
- 每页六项，桌面三列、中等屏两列、手机一列；搜索、类型或企业变化返回第一页。刷新成功保留筛选条件，列表缩小时修正越界页码；企业权限消失时取消失效企业筛选。空授权与筛选空结果分别提示，筛选空结果提供清空条件动作。初次加载及刷新失败沿用路由加载／错误边界和重试，不保留失败后未经重新授权的旧入口。刷新失败导致选择页卸载，重试成功后重新挂载并恢复默认筛选和第一页，不承诺跨错误边界保留界面条件。
- 图稿的 68 个空间和 12 页均为虚构示例，生产总数及页数只取真实授权清单，不新增空间、权限或接口。“≤5隐藏搜索”仍仅针对语言选择框。
- 卡片与头部入口预留边框、背景和阴影结构；hover／focus／active只调整颜色，不抬升或缩放。新页面与导航的当前项、过滤、分页、错误、窄屏和头部回归均须独立验证。
- 已实施语言与账号范围包括 `/workspaces`、企业级、项目级及平台共享头部；此前语言12场景结果仅覆盖当时实现，新空间页面与导航使用本轮空间12场景独立验收。账号业务规则不变。
- 语言切换独立于账号业务，工作空间、企业级、项目级及共享头部统一使用小 `TranslationOutlined` 翻译图标作为唯一入口，不显示语言名称、代码或下拉箭头。Popover 本身保留指向该图标按钮的箭头，与触发器不带下拉箭头的要求分别适用。
- 点击图标打开 C 语言列表 Popover，其中包含标题、原生语言名称与辅助名称、当前项勾选及可滚动列表；实际注册语言总数≤5时不渲染搜索框，>5时显示搜索框。阈值读取完整语言配置总数，与搜索结果数量无关；>5场景筛选到5项、1项或0项时仍保留搜索框。点击语言项完成切换并收起选择层，当前语言不改变页头入口宽度。
- 有搜索框时打开聚焦搜索框，可按原生名称和辅助名称筛选，结果为空时有明确空态；无搜索框时打开聚焦当前语言选项，无当前语言匹配则聚焦首项。两种模式均保留方向键、Home／End、Enter／Space 选择、Escape 关闭并归还触发器焦点，以及外部点击关闭与现有语言切换行为。
- 列表按实际已支持的语言配置生成，保留语言数量增长的能力；长名称、非拉丁文字及窄屏不导致头部或浮层横向溢出。当前实际配置、资源 loaders 及 UI adapters 仅支持 `zh_CN`／`en_US`，本轮实际两语言应进入无搜索模式，不凭测试配置或预览新增产品语言资源或翻译。
- 不在页头平铺全部语言，不用国旗替代语言识别，不以现有代码语言清单限制产品需求。预览中的语言仅为样式示例，不代表本任务新增实际产品语言或完成对应翻译。
- 账号按钮由头像、用户名和展开箭头组成。桌面用户名超长时截断；手机只保留头像与箭头。姓名和账号在展开菜单的信息区可核对。
- 菜单的信息区展示当前用户姓名和账号，不作为可选操作；下方提供“修改密码”，用分隔线隔开危险操作“退出登录”。
- 企业级／项目级及平台共享页头使用头像账号菜单，修改密码与退出登录已收纳；“切换空间”独立保留，以免工作空间导航混入账号操作。账号菜单与语言浮层互斥，打开账号菜单会收起语言 Popover。
- 本人改密仍使用现有弹窗；退出登录仍沿用现有本地登录状态清理和登录页跳转流程。入口调整不改变接口、会话、权限或密码规则，正式业务边界见[修改密码需求](../../06.认证与会话/修改密码/需求文档.md)。
- 已登录但没有工作空间的用户仍可使用语言切换、修改密码和退出登录。
- 菜单须支持鼠标、触屏和键盘；账号按钮有清晰的键盘焦点，Enter／Space 可打开，Escape 和点击外部可关闭。
- 页头交互状态稳定性要求覆盖 `/workspaces`、企业级、项目级及平台共享头部。普通 hover 不改变元素及相邻元素的位置、尺寸或命中区域，不以 `transform` 位移作为默认反馈；此前语言验收的33个目标只证明当时实现。本轮空间报告重新检查22个头部目标，24帧几何稳定、隔离 `LayoutCount` 增量为0；企业导航先前增量1的失败及最终定向复测仍保留，不断言其原因。
- 默认状态与 hover／focus／active 状态保持边框宽度、样式及盒模型一致。仅需显隐的边框预置透明边框；背景优先显式声明透明色，阴影优先预置相同数量、偏移、模糊及扩散参数的透明阴影，状态只修改颜色或透明度。
- 默认透明样式不得覆盖按钮原有的按下反馈。两个页头按钮的 active 状态保留可见背景与边框颜色反馈，且按下期间同样保持位置、尺寸及命中区域稳定。
- 纯视觉交互的过渡列出具体属性，避免 `transition: all` 将布局或位置属性纳入动画；颜色、背景色和边框颜色通常触发重绘，`opacity`／`transform` 是否走合成取决于浏览器，不能将无重排等同于无抖动。
- 确需改变布局或空间位置的交互可以例外，但须在实现或设计中说明理由、限制作用范围，并验证指针命中、相邻布局及键盘焦点稳定。
- 该原则已纳入[前端 AGENTS.md](../../../apps/web/AGENTS.md)的按需入口和[交互状态样式规则](../../../apps/web/.agents/rules/交互状态样式.md)，并同步到用户指定的 `C:/malei/stu/skills/skills/init-agent-rules` 技能模板资产；模板与项目规则正文的 SHA256 一致，技能验证通过。本次不运行初始化覆盖其他项目规则。

## 4. 权限与数据约束

- 仅展示当前会话已取得的用户公开资料，不新增用户资料查询或权限判断。
- 修改密码和退出登录继续作用于当前全局账号；不能因菜单收纳产生额外工作空间权限条件。

## 5. 验收标准

1. 桌面页头不再平铺修改密码、退出登录，语言入口与账号按钮间有明确分隔；账号按钮与现有梦幻主题协调。
2. 打开账号菜单后，可核对姓名和账号，且能访问修改密码与退出登录；退出操作有明确危险色与分隔。
3. 手机 320px／390px 宽度下语言入口仅显示小翻译图标、用户名收起，页头及完整 Popover 无横向溢出；长用户名不挤压品牌或语言入口。本轮三作用域的 320px／390px 窄屏复验通过，未单独重跑长用户名场景。
4. 账号菜单可由 Enter／Space 打开，由 Escape 和外部点击关闭；键盘焦点清晰，触发按钮及菜单项具备可访问名称。
5. 有工作空间与无工作空间两种状态下均可打开本人改密；关闭改密后仍能继续使用页头。退出后现有登录信息清理并转到登录页。
6. 本次不新增服务端接口，不改变改密、退出、会话或权限业务行为。构建与针对本次入口的浏览器验证结果须归档后才能标记完成。
7. 桌面、窄屏及减弱动画设置下，页头普通 hover 前后元素和相邻元素的边界稳定，持续悬停不会反复切换进入／离开状态。验证同时检查布局事件与视觉位移，不能仅以没有 Layout 事件判断无抖动。
8. 默认／悬停／按下状态不新增边框宽度；背景和阴影显隐保持预设结构，纯视觉过渡使用具体属性。hover 和 active 均有清晰颜色反馈；例外需有明确理由和复验范围。
9. 前端项目规则入口、规则正文及指定初始化技能模板同步完成，链接有效；[语言与头部检查工具](./工具/language-popover-check.mjs)、[hover 检查工具](./工具/header-hover-check.mjs)与[本轮原始证据](./测试证据/language-popover.json)归档到本功能目录，本轮报告和截图更新原路径。原 Dropdown 的 7 场景报告仅作为历史记录。
10. 工作空间、企业级、项目级及共享头部实施已确认的 C 方案：仅小翻译图标入口，点击展开带标题及语言列表的 Popover，箭头指向触发按钮；语言项展示原生名称、辅助名称和当前项勾选，列表可滚动。实际注册语言总数≤5不显示搜索框，>5显示；有搜索时空结果有提示，点击语言后切换并收起，不在页头显示语言名称、代码或下拉箭头。
