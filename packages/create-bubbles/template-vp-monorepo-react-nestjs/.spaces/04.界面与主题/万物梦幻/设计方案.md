## 2. 布局与层次

### 当前样式回归根因与修复

按确认图稿和真实页面逐项核对浅紫／浅蓝背景、半透明圆角卡片、间距与头部布局，不把上一轮mock截图等同于用户实际页面正确。冷加载登录、工作空间选择与企业页面均已复现：`main.tsx` 把声明层序的 `index.css` 移到 App／路由样式之后，浏览器实际层序为 `components → properties → theme → base → antd → antd-pro → utilities`；重置样式和 Ant Design 优先于自定义主题，造成标题变为14px、间距丢失。修复恢复入口中 `index.css` → `dream.css` 在 App 前的顺序，并在 `index.html` 的 head 最前部提前声明 `theme, base, antd, antd-pro, components, utilities`，提前固定既有层级。保留 `index.css` 的同名声明作为独立样式入口保障；重复声明不会重新排列已有层。修复只处理全局层级，不改变已确认卡片设计、空间业务或路由过渡。[开发6场景](./测试证据/workspace-css-regression-after.json)和[构建预览3场景](./测试证据/workspace-css-regression-built.json)均通过：配置六层顺序正确，末尾另有Tailwind的properties层，冷加载、企业返回选择页、320px及拦截模拟旧导入顺序均保持正确主题。两源码定向检查及非缓存TypeScript／构建通过；本轮未做热更新专项，不把固定层序的设计保障扩大为所有热更新场景已验收。

### 当前共享页头实现

沿用页面已有浅紫、半透明背景和柔和边框，收紧右侧操作组。语言切换是独立的小图标入口；工作空间选择页通过细分隔线区分设置与账号，账号菜单承载低频操作。企业级、项目级及平台头部左侧当前空间和切换动作合为单一导航入口，右侧使用相同语言与账号组件。

工作空间手机： [翻译图标]  │  [圆形头像 ▾]

           │ 钥匙图标  修改密码        │
           ├──────────────────────────┤

头像、姓名与账号使用当前会话已取得的公开资料，作用域角色按现有布局上下文展示；本次不引入头像上传、图片依赖或用户资料维护功能。

### 当前语言方案：C 列表 Popover，按语言总数显示搜索

工作空间选择页、企业级、项目级及共享头部统一使用 `TranslationOutlined` 小翻译图标入口，图标 16px、点击区域 32×32px，不显示语言名称、语言代码或下拉箭头。用户已选定 C 可搜索列表：点击图标打开带箭头的 Popover，箭头必须指向图标按钮，点击语言项切换。触发器没有下拉箭头，浮层具有指向箭头，两者不冲突；当前语言仅在展开层中通过名称及勾选状态识别。

Popover 采用 C 的单列结构：顶部标题，下方为受控高度的可滚动语言列表；实际注册语言配置总数>5时才在标题与列表之间渲染搜索输入框，总数≤5时直接展示列表，不保留搜索框的空白占位。阈值使用完整配置总数，不使用搜索筛选后的列表长度；总数>5时即使筛选到5项、1项或0项，搜索框也继续显示。每项使用原生语言名称作主信息、辅助名称帮助识别，当前项在固定勾选区域标记；不使用国旗。有搜索时按原生名称和辅助名称筛选，空结果显示提示。当前实际两语言进入无搜索模式，本轮不新增翻译资源。

浮层继续使用 Ant Design `placement="bottom"`，利用标准自动横向移位避让视口边缘并保持箭头指向图标按钮。面板宽度 280px，并按可用视口限制最大宽度；本轮三作用域 320px／390px 已重新验证完整面板与箭头，无搜索布局符合边界。此前 `bottomRight` 角对齐造成的窄屏左侧溢出和固定 4px 偏移已修正并复验，失败只作为历史定位依据。

沿用浅紫主题与低装饰入口，默认、hover／focus／active 和选中状态维持稳定盒模型，边框、背景及阴影遵循本功能纯视觉状态规则。共享语言组件承担统一呈现、搜索、当前项与切换行为，工作空间、企业级、项目级及平台共享头部均已适配。列表来自实际已支持语言配置，可扩展语言数量；当前 `APP_LOCALES`、资源 loaders 及 UI adapters 仅支持 `zh_CN`／`en_US`，本次不凭预览新增语言资源或翻译。已有应用词条、Ant Design、Pro Components、Day.js 与 `<html lang>` 的联动规则继续遵循[国际化设计](../国际化/设计方案.md)。共享账号菜单已收纳改密和退出，切换空间保持独立；打开账号菜单会关闭语言 Popover。

既有[三方案对比图](./ui/language-switch-options.png)、[静态样稿](./ui/language-switch-options.html)及[渲染工具](./工具/language-switch-preview.mjs)作为静态比选历史保留，C 已选定，A／B 不再待选。PNG 为 1500×1207px、250543 字节，已成功解码并目视检查，静态样稿溢出检查为空；每候选 12 种语言仅为示例，C 搜索输入框为 `readonly`。原图只能证明当时静态视觉，本轮[12 场景报告](./测试证据/language-popover.json)与[局部细节图](./ui/language-popover-detail.png)已更新原路径，记录实际 2 语言无搜索的新结果。

### 企业级／项目级与平台共享布局

企业级与项目级共用 [WorkspaceLayout](../../../apps/web/src/layouts/WorkspaceLayout/index.tsx) 及 ProLayout；原账户提示与平铺改密／退出已替换为共享账号菜单，语言入口使用共享 C Popover。本轮将左侧当前空间与切换动作合为导航链接，移除右侧切换按钮；平台共享头部使用同一布局。新导航的企业／项目／平台1440px及企业320px已独立验证当前项、快捷返回、实际进入路由和共享入口；此前结果仍只覆盖原头部。

此前只读检查未找到纯 hover 改尺寸或位移的明确触发，`transition: all` 仅是过渡范围风险，不能认定为用户抖动的确定根因。语言入口固定为 32×32px；本轮无搜索结构、语言切换、打开焦点、各头部逐帧几何和纯 hover 布局计数已重新验证。Popover 打开、关闭和定位属于弹层交互，不能把它们的布局处理与普通按钮 hover 混为同一测量区间。

### 当前空间设计：点击返回卡片选择页

左侧当前空间类型、名称、切换图标及“切换空间”合为一个 Link，点击回 `/workspaces`；入口不带下拉箭头。平台／企业／项目共用 WorkspaceLayout，移除右侧原切换按钮，语言与账户继续复用共享组件。导航 state 携带当前 `accessScopeKey(scope)`；选择页只有与新授权清单匹配时才标记当前项。标题区提供“返回当前空间 + 名称”链接，使用授权清单匹配出的实际入口路由，独立于分页和筛选结果；直接访问或原空间撤权时不默认标记第一项并隐藏快捷返回链接。

卡片沿用半透明白色、约20px圆角、宽松留白与浅紫／浅蓝背景，展示类型、角色、名称、项目所属企业，底部只有一个进入链接；当前卡片固定标记并使用“返回空间”动作。生产每页六项，三／二／一列响应式布局。搜索和企业筛选产生基础清单，据此计算全部／平台／企业／项目计数，再叠加所选类型并分页；企业选项按公司 ID 去重，从企业与项目入口共同提取。`companyName` 可选，同企业有企业入口时以该入口名称为准；仅项目资格时使用已有所属企业名，缺失回退企业 ID，不误用项目名。搜索、类型、企业变化重置页码，刷新保持条件、修正越界页码及失效企业筛选。

数据继续来自 `getWorkspaceState().workspaces` 及现有 workspaces middleware，沿用 `WorkspaceEntry`、`WorkspacesResult` 和 `accessScopeBasePath`；没有新增服务端字段或接口。项目进入原所属企业／项目路由，UI筛选不改变权限。刷新成功保留页面条件；失败沿用既有路由错误边界及重试，旧授权清单按 middleware 清除，页面卸载后重试重新挂载并重置筛选与页码。无授权项保留邀请指引，筛选无结果增加清空条件动作；初次加载保持 PageLoading。图示68项、12页仍是虚构样例，不能写死到生产。

颜色沿用梦幻浅紫主题：主色 #9274CB，文字 #39304F，次级文字 #8C809E，边框 #E5DCF0，背景 #F5F1FB，辅助青色 #74A4B0。正文使用 Microsoft YaHei／Segoe UI，品牌和标题沿用楷体。卡片及入口预留边框与完整阴影结构，状态仅改颜色，不抬升或缩放。[已确认图稿](./ui/workspace-switch-navigation.png)、[HTML](./ui/workspace-switch-navigation.html)、[工具](./工具/workspace-switch-preview/navigation.mjs)与[静态证据](./测试证据/workspace-switch-navigation.json)保留为视觉依据；PNG 2160×2187px，用户已确认，生产截图与交互验证另行归档。

## 4. 交互与实现边界

- 共享账号菜单使用 Ant Design `Dropdown` 的点击触发和菜单能力，右对齐展开；账户信息与作用域角色以非操作区域呈现，不注册为菜单项。语言选择使用已确认的带指向箭头的 `Popover`，两种浮层互斥。
- 菜单项只包含修改密码与退出登录，中间加入分隔线，退出项使用 `danger` 状态。
- 点击修改密码关闭菜单并调用现有修改密码弹窗的 `show()`；不重建表单或改变弹窗提交和关闭方式。入口业务依据见[修改密码设计](../../06.认证与会话/修改密码/设计方案.md)。
- 点击退出关闭菜单并沿用现有登录状态清理与路由跳转；不新增接口或二次确认。
- 账号触发器使用原生按钮，提供可访问名称和展开状态；Enter／Space 可打开，Escape 关闭后将焦点交还账号按钮，点击外部可关闭，由组件库能力与局部状态控制实现，并已通过本地浏览器复验。
- 正常动画与 `prefers-reduced-motion: reduce` 设置均纳入验证；本轮项目减弱动画场景通过，弹层定位、箭头及焦点行为以当前共享组件和本轮证据为准。
- 上一轮语言菜单页面级修正的历史基线：在本页用 Ant Design `ConfigProvider` 为 `LocaleSwitch` 的 Dropdown 配置 `classNames.root = workspace-locale-dropdown`；减弱动画样式仅对 `.workspace-account-dropdown` 与 `.workspace-locale-dropdown` 设置 `transition: none !important`。当时未改共享 `LocaleSwitch`，配置只作用于工作空间页头，修正后的英文场景已重验通过。该结论不作为本轮 Popover 的实现或验收结果，新浮层须重新核对作用标记、过渡和定位。
- 页面处于没有可选工作空间的空态时，页头和菜单继续可用；菜单不得依赖工作空间列表结果决定是否渲染。
- 共享语言入口统一作用于工作空间、企业级、项目级及平台共享头部。完整注册配置总数≤5无搜索时打开聚焦当前项，无匹配则首项；>5有搜索时聚焦输入框。Enter／Space 可打开触发器，列表保留方向键和 Home／End 定位及 Enter／Space 选择；Escape 关闭后归还触发器焦点，外部点击可关闭，点击语言沿用现有联动并收起浮层。有搜索模式关闭重开清空查询，空结果有提示，筛选不改变显隐。当前实际两语言的无搜索行为已通过 12 场景复验，5／6语言边界、筛选至1／0项仍显示及首项焦点兜底由 11 例组件单测覆盖。

## 5. 纯视觉状态与 hover 稳定性

本节是纯视觉状态的实施依据。调整前隔离 Chromium 中 `/workspaces` 两个按钮已预留 1px 透明边框，hover 前后及 30 帧几何无变化；排除卡片浮动动效干扰后，账号 hover 的 `LayoutCount` 增量为 0、`RecalcStyleCount` 增量为 22，未复现用户报告的可见抖动，见[历史基线证据](./测试证据/hover-baseline.json)。当时确认按钮继承 Ant Design 的 `transition-property: all` 为风险并收窄，不能作为用户抖动的确定根因证明。

当前实现已覆盖 `/workspaces`、企业级、项目级及平台共享头部。此前语言阶段[12场景报告](./测试证据/language-popover.json)的33个目标只证明当时结构。本轮[空间报告](./测试证据/workspace-switch.json)独立检查22个头部hover目标，24帧几何稳定、隔离 `LayoutCount` 增量0；卡片12帧检查同样稳定。企业导航曾记录增量1，冻结样式后按原基线定向复测未复现，报告保留先前失败，不把该差异归因于未经证明的代码或环境原因。

正常动画下相关页头按钮的过渡限定为 `color`、`background-color`、`border-color`；本轮项目减弱动画场景的语言入口为 `transition: none`，其余入口仍为颜色过渡。默认背景显式为透明，边框预留固定宽度，hover 使用主题颜色反馈；共享账号和语言样式与各布局入口共同保证稳定盒模型。

默认透明背景不能遮盖组件库的按下反馈。active 仅修改背景与边框颜色，保持同宽边框及原有布局；本轮各入口 hover／focus／active 的 24 帧采样再次确认几何稳定，并保留可见状态反馈。

- 对页头普通 hover 保持布局盒、相邻排布和指针命中区域稳定。排查需要同时比较默认与 hover 的计算样式、逐帧边界和实际浏览器渲染事件；`transform` 不改变正常布局，但仍可能移动视觉与命中区域，形成悬停抖动。
- 边框在默认状态声明固定宽度和样式，需要隐藏时使用透明颜色；状态只改变 `border-color`，不增减宽度、padding、margin、尺寸、字体大小或字重等可能改变排布的属性。
- 仅作显隐的背景先声明透明背景色；阴影先声明与显示状态相同的数量、偏移、模糊和扩散结构并使用透明色，hover 只调整颜色／透明度。背景和阴影变化通常不会改变布局，本条用于统一状态结构和避免不必要的插值变化，不能把增加阴影本身表述为必然触发重排。
- 为纯视觉状态明确列出 `color`、`background-color`、`border-color`、`outline-color`、`box-shadow` 等所需过渡属性；普通页头按钮不采用通用 hover 位移或缩放。避免 `transition: all` 意外覆盖布局或定位属性。
- `opacity`、`transform` 可能由合成处理，实际路径由浏览器决定；减少重排不等于保证只发生重绘，也不等于保证视觉和指针稳定。普通 hover 优先使用颜色反馈，不承诺浏览器完全不重绘或一定走合成。
- 展开／收起、拖拽等确有空间变化语义的交互可作为例外；理由和作用范围须明确，并检查相邻布局、指针连续命中及键盘焦点。弹层进入／离开动画与普通按钮 hover 分别验证。
- 规则已在[前端 AGENTS.md](../../../apps/web/AGENTS.md)的按需表提供入口，正文由[交互状态样式规则](../../../apps/web/.agents/rules/交互状态样式.md)承载；用户指定初始化规则技能的模板已同步相同原则，项目规则和源模板正文 SHA256 一致，技能验证通过。本次只维护资产，不执行跨项目初始化。
