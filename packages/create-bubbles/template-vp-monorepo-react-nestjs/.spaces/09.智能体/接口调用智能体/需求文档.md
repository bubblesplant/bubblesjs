# 通用智能体运行时需求

状态：目标及递进学习方式已澄清，完整设计与技术选型待确认，未实施。从一个对话实例逐步增加能力，最终提炼为可配置、可组合的 Agent 运行时。

日期：2026-11-12。技术建议见[设计方案](./设计方案.md)。沿用本功能原有目录更新现行正文，不另建平行方案。

## 已确认的目标

- 封装一个通用智能体，初始化后可完成各自配置所定义的任务。
- 每个实例支持独立传入 Skills、MCP、大模型接口、备用模型接口、function calling 工具和 system prompt。
- “备用接口”已明确为备用的大模型服务／地址。
- 通过同一套运行机制创建不同用途的实例，避免每个任务重复编写调用循环和接入逻辑。
- 初始化方式类似前端组件传入配置；同一套 Agent 抽象既可以独立执行，也可以注册为其他 Agent 的子代理，不为两种角色维护不同的运行内核。
- 用户认可标识／描述及执行限额；其他建议配置仍在解释与评审中，不能因列入方案而视为全部确认。
- 子代理使用场景包括执行后才知道需要哪些能力、启动几个子任务，以及等待其他子任务完成后继续；不应要求初始化时固定全部子代理及数量。
- 支持执行中打断交互：AI 对任务有多个合理理解、缺少关键条件时，提出问题及候选选项，由用户选择或补充文字，收到有效回答后继续原任务。此能力纳入首期，具体接口与默认值待评审。
- 用户提出学习搭建智能体的取向，已讨论 LangChain 学习路线；具体底层框架仍待最终确认。
- 用户明确采用递进方式：先完成一个普通对话实例，再逐步加入系统／用户提示词、function calling、Skills、MCP、会话、编排、打断交互、子代理，最后封装。
- 当前先落实学习路线与第一个实例的边界，每次增加一种能力并观察运行过程；不一次性生成完整运行时。现有完整方案作为目标设计，尚未进入业务代码实现。

此前“仅为当前工作空间提供查询助手”的理解已被本次澄清替代，不再作为首期范围。产品内助手可以成为运行时的使用方，但不限定运行时用途。

## 递进学习与交付方式

- 教学方式已确认：由用户亲手编写，助手逐步讲解并协助检查结果；不由助手提前生成全部阶段的源码或代替用户完成练习。当前先推进最小对话。
- 围绕同一个后端学习实例演进，每阶段说明新增概念、关键代码、运行方法和可观察结果；后续阶段保留前面已理解的能力，不在入门时引入整套工厂、调度器和配置系统。
- 第一阶段只验证模型调用：读取服务端模型配置，发送一条用户消息，得到并输出模型回复。用户消息本身就是用户提示词，下一阶段再区分系统指令与本次任务，并学习模板。
- Function calling 阶段看清“模型提出调用 → 程序校验并执行 → 将结果交回模型 → 模型继续”的完整过程；Skills 与 MCP 分别在此基础上增加知识加载与外部工具接入。
- 会话阶段明确消息历史及隔离，编排阶段明确步骤与依赖，打断阶段明确选项／回答／续接，子代理阶段再学习独立运行、委派、动态数量与等待结果。
- 主备模型、流式输出、取消、超时与用量限制按对应能力逐步补齐，最终封装时仍需覆盖完整目标，不能因入门拆阶段而遗漏。
- 最后从已验证实例提炼初始化配置和统一调用 API，并用第二个不同配置的实例验证通用性；上文完整首期范围不等于第一课需要一次性交付。

各阶段的练习及通过标准见[设计方案的递进路线](./设计方案.md#首期验证与落地顺序)。当前没有可执行示例或真实模型调用记录，不将路线归档视为完成第一阶段。

## 首期建议范围

- 提供初始化、任务执行、流式事件和资源释放的统一入口。
- 支持每实例 system prompt、主备模型配置、本地 function 工具、MCP 工具与 Skills。
- 支持将本地函数和 MCP 工具交给同一 Agent 调用循环，保留执行来源和权限边界。
- 支持每次任务的独立上下文、可取消执行、超时、最大步骤和错误反馈。
- 区分实例配置、对话 thread 和单次 run，避免多实例及多用户数据相互污染。
- 支持已初始化 Agent 的子代理调用适配；每次委派建立独立子运行，结果返回父运行继续处理。
- 支持根据执行中的任务规划按需启动子运行，记录任务标识、状态和结果，并表达单个等待、并行汇合与结果依赖；模板及允许覆盖的配置范围仍待定。
- 动态委派建议显式启用；已有子 Agent、可复用模板和允许的临时定义均交给同一调度器，不能通过动态配置绕过宿主授权或总预算。
- 支持通过相同工厂配置创建新的独立实例；复用配置或注册为子代理不隐含复制聊天历史和凭证。
- 支持主代理及子代理发起结构化澄清问题，由宿主统一展示；暂停依赖答案的执行路径，保留已完成结果，无依赖的其他子任务可以继续。
- 支持问题、选项、自由文本回答与原运行关联；等待期间不持续调用模型，不因用户未回答、问题超时或连接断开而代替用户选择。
- 以两个不同配置实例验证通用性；首个业务任务、模型和 MCP 服务待选定。
- 可视化配置后台、长期记忆及工作流编排按实际场景另行评估；子代理组合已纳入本次需求，不再列为后续才讨论的能力。

## 配置及关键语义

| 配置           | 用途                             | 必须保留的边界                                 |
| -------------- | -------------------------------- | ---------------------------------------------- |
| system prompt  | 定义实例职责、任务规则和回答要求 | 与平台执行策略分别管理，不授予额外工具权限     |
| Skills         | 提供任务做法、技能说明和参考资料 | 与可执行工具分开；加载文档不等于执行脚本       |
| MCP            | 连接外部能力，发现并调用授权工具 | 连接、凭证和工具范围按实例／请求隔离           |
| 主备模型       | 定义模型来源及失败后的替代顺序   | 验证工具调用等能力兼容，保留已完成工具结果     |
| function tools | 提供带结构化输入的本地可执行函数 | 后端注册与执行，不从普通 JSON 反序列化任意代码 |
| 运行限制       | 控制超时、步骤、重试与取消       | 不因切换模型或工具重试而重置总预算             |

以下为补充配置清单，其中标识／描述及限额已获用户认可，其余配置的细节与默认行为仍待评审：

| 配置             | 用途                                            | 建议默认规则                                               |
| ---------------- | ----------------------------------------------- | ---------------------------------------------------------- |
| 标识与描述       | 定位可复用能力，并说明适用任务，供父 Agent 选择 | 同一目录内名称不能歧义；具体任务使用单独的 runId           |
| 输入与输出契约   | 明确任务参数和结果格式，便于父子组合及业务消费  | 需要结构化结果时校验 schema，失败不冒充成功                |
| 子代理注册与创建 | 提供可复用能力／模板，执行时决定实际启动任务    | 注册列表可选，不预先固定数量；动态创建受授权与总预算限制   |
| 状态与上下文     | 区分运行上下文、对话历史和可写文件区            | 每次子运行隔离，仅显式传入必要上下文                       |
| 执行策略         | 声明允许工具、委派范围和副作用要求              | 具体身份由宿主提供，子代理不因委派扩大权限                 |
| 层级与总预算     | 限制嵌套、并发、整棵调用树的步骤及耗时          | 检查循环调用，主备尝试与所有子运行共同消耗预算             |
| 生命周期与事件   | 控制结果、流式反馈、取消、资源释放和调用追踪    | 父子运行可关联，外部传入资源默认借用而非自动销毁           |
| 用户交互         | 执行中展示澄清问题、候选选项并接收回答          | 暂停后续依赖步骤，校验回答归属，再续接原运行；不得自动代选 |

完整配置清单、建议初始限额、统一结果与协调接口见[设计方案](./设计方案.md)。初始化提供能力配置，单次执行提供 input 及可选的 threadId／context／signal；普通聊天的专用 schema 和连续会话均可不配置。`run` 与流式入口是两种启动方式，观察一次任务的进度不能重复发起任务。

“独有配置”表示实例可持有各自的配置和凭证；在显式授权下可引用相同的只读技能或工具定义，但不得共享不属于同一作用域的运行状态与数据。

## 关键流程建议

1. 初始化时验证配置、解析模型适配器与凭证、建立技能目录、注册本地工具，并按策略连接 MCP／发现工具。
2. 执行时固定当前配置版本，建立独立 run，接收宿主传入的可信调用上下文。
3. 按任务选择并加载技能，模型根据可用工具提出结构化调用。
4. 执行器验证参数和策略，调用本地函数、MCP 或按需启动子运行；子代理接收明确任务并独立执行，调度器按依赖等待结果就绪，再恢复父运行或后续子运行。
5. 遇到影响后续执行的歧义时，AI 发起用户提问，运行时保存续接状态，交由界面展示候选解释；用户选择或补充后，校验回答并恢复对应主／子运行，不新建同一任务或重复已完成工具。
6. 模型请求遇到符合策略的故障时切换备用模型，继续使用已确认的消息和工具结果。
7. 完成、失败或取消时输出明确状态；暂停提问属于非终态，不能当作任务完成清理。实例关闭时释放由其拥有的连接和其他资源。

## 执行中澄清交互

例如用户说“生成本月报告”，AI 可以询问“需要哪种报告？”，展示“销售报告”“库存报告”“综合报告”，并允许输入其他要求。候选项是待用户确认的解释，不是已确定的事实；只有答案会影响任务且无法从现有上下文可靠确定时才提问。

- 首期以单选及自由文本补充为基础；模型生成问题及候选项，界面负责展示，运行时负责暂停、校验与续接。推荐项即使预选也不等于用户提交。
- 主代理、动态创建或预注册的子代理均可提问，问题携带来源运行与交互标识，由宿主统一接收；答案必须回到对应续接点，不能仅追加一条无关联的聊天消息。
- 提问时返回非终态交互信息或流式事件，让界面取回控制权。用户回答后使用恢复入口续接同一个 run；多轮提问和多个子任务的待答问题都应可查询、区分。
- 等待用户的运行释放活跃并发名额，不再执行依赖答案的模型或工具步骤；其他独立子任务仍按预算继续，依赖该子任务的父／兄弟任务继续等待。
- 用户等待采用独立有效期与累计等待上限；整棵调用树仅因用户交互而暂停时，执行时限暂停计量。其他任务仍在执行时继续计量，绝对截止时间和已有预算不因回答而重置。具体默认值待评审。
- 重复回答不能重复恢复；无权限、选项不匹配、过期问题、已完成或已取消运行不能被错误续接。超时或取消应明确结束相应等待，不能作为用户答案。
- 澄清答案只补充任务信息；业务操作授权及写入确认仍按执行策略独立校验。
- 首期在同一服务进程内保存可续接状态，不要求 HTTP 连接一直挂起；进程重启后恢复仍属于后续扩展。不能展示交互的调用方需获得明确的需要用户输入状态或不支持交互的错误，不能自动猜选。

## 权限与数据约束建议

- 模型、MCP、技能目录和工具执行驻留后端，凭证不传入浏览器、模型提示词或公开日志。
- 通用核心接收宿主提供的执行策略与上下文；当前项目通过 NestJS 适配现有 Session、作用域权限和审计，不把具体业务实体写入通用核心。
- Skills、MCP 返回内容和用户输入均不能提高工具权限；本地脚本与 stdio 进程启动属于需明确开放的执行能力。
- 工具定义和工具执行分别处理：能在模型上下文中看见工具，不代表实际执行时可以跳过鉴权。
- 工具凭证、对话、运行记录及可写文件区隔离；MCP 连接不能仅按 URL 全局复用而忽略凭证归属。
- 模型切换不能从头重跑整个任务，避免重复工具副作用。执行结果不明的写操作先查询状态，重试与补偿由工具策略定义。
- 有副作用的工具按用途声明确认、幂等及审计要求；配置不可把已经执行的行为描述为未发生。
- 运行中的任务固定配置版本；会话和权限是否仍有效需要在执行时重新检查，不能因固定版本而冻结授权。
- 交互查询、回答与恢复均检查调用者身份、作用域及运行归属；恢复后工具仍重新鉴权，用户选项不能扩大原授权。问题与答案遵循对话的可见性及数据保留范围。
- 子代理可使用自身配置的模型、技能和工具，但有效执行范围不能超过可信调用者授权及本次委派范围；不自动继承父提示词、全部历史或凭证。
- 父运行取消或截止时间到达时传播到其子运行，不影响同一 Agent 实例服务的其他独立运行；已发生的远端副作用不因取消而自动撤销。
- 父 Agent 关闭时只释放其拥有的资源；调用方传入且被其他 Agent 复用的子代理／MCP 连接，不能被无条件关闭。

## 候选验收标准

以下为方案建议，尚未执行：

- 两个 Agent 配置使用不同提示词、技能、模型和工具，结果及运行状态互不混用。
- 同一 Agent 可独立运行，也可通过调用适配成为其他 Agent 的子代理，原实例不会因此改变角色或共享本轮聊天状态。
- 子代理结果能按约定返回父运行；失败、取消、输出校验失败可明确识别，父子 run 标识与调用链可追踪。
- 相同子代理可被两个父运行复用而不串历史；循环调用、嵌套深度、并发和整树预算受到限制。
- 同一模板可根据运行中的计划创建不同数量的子任务，无需预先列出全部实例；任务 A／B 并行完成后，C 能取得所需结果再执行。
- 等待依据真实任务终态与结果，不靠反复调用模型询问进度；任务先完成再等待也能返回已记录结果，失败、取消、超时和相互等待均有明确处理。
- 等待者释放活跃并发名额，剩余任务能继续执行；父任务结束时清理本次调用树未完成的子任务，不默认产生脱离父任务的后台工作。
- 歧义任务能生成候选选项并暂停，用户选择或自定义回答后接续相同 run；未回答不继续依赖步骤、不自动代选，已成功工具不重复执行。
- 子代理问题能统一展示且答案准确路由；多个待答问题可识别，无依赖子任务继续，重复／过期／越权回答不能错误恢复任务。
- 用户等待不持续消耗模型调用；执行计时、交互有效期、累计等待上限、取消及绝对截止时间按明确规则生效；界面断开后同进程内仍可查询待答问题，重启恢复不作为首期承诺。
- Skills 能被发现并按需加载；实际支持的 SKILL.md 字段、参考文件和脚本边界有明确说明。
- 本地 function 和 MCP 工具均可通过结构化调用完成任务；重名工具有可预测的命名或拒绝策略。
- 主模型发生可恢复故障时按策略切换备用模型，已经成功的工具不会因此重复执行。
- 主备模型不兼容、MCP 断连、技能加载失败和参数错误具有可定位的错误结果。
- 流式输出、取消、超时和步骤限制均有一致事件；取消后不再发起新工具调用，对已发出的远端调用明确标记实际状态。
- 不同用户／作用域不共享聊天历史或 MCP 凭证；同一 thread 并发执行的策略明确。
- 实例关闭与异常退出均能清理其拥有的连接，不误关其他实例仍使用的共享资源。

首期建议以单进程内隔离会话及任务状态完成上述验收。持久会话、跨进程恢复、长期记忆、直接代理消息、可视化配置和后台长期任务属于后续评估项，不因首次引入框架而视为已具备。

## 待确认事项

- 最终底层框架与对外调用形式；本轮提供建议而不锁定依赖版本。
- Skills 是否必须兼容标准 SKILL.md、目录参考文件，以及是否允许运行随附脚本。
- MCP 首期需要远程 HTTP、本地 stdio 中的哪些传输方式。
- 首批模型协议／供应商、备用切换条件及初始能力兼容验证。
- 会话持久化、重启恢复、对话保留期限和首个真实任务。
- 初始化配置仅来自开发代码，还是还需通过可存储的 JSON／管理界面创建实例。
- 子代理调用是否由模型自主选择、代码显式选择，或两者均支持；第一期暂建议委派后返回结果，不默认启用整段对话控制权转交。
- 动态子代理使用预设模板、可覆盖的通用模板或两者并用；直接代理间消息是否首期开放，待评审，不将消息通道视为任务完成保证。
- 子代理的初始上下文、是否保留独立 thread、输出契约、失败策略、最大深度及总预算。
- 相同定义创建新实例时的配置覆盖规则，以及外部传入子代理／连接的所有权和关闭规则。
- 用户交互的正式字段、单次／累计等待时限与次数上限、宿主展示形式；首期建议单选并允许文字补充，多选按实际任务另评。暂停提问能力本身已明确纳入首期。
