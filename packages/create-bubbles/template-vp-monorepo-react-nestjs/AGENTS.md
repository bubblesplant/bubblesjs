## 方法注释

- 前端、后端及共享代码中的每个函数或方法都必须编写 JSDoc（`/** ... */`），只有通过名称和实现一眼就能看出用途的简单方法可以省略。
- 注释应说明实际用途；按需补充关键参数、返回值、异常和副作用，避免只重复方法名或 TypeScript 类型。修改方法行为时同步更新注释。

## 目录说明

- 修改文件前，须从文件所在目录逐级向上查找并阅读相关的 `AGENTS.md`（如存在），并遵循其中的说明。
- 当一个目录下存在多个同级文件，其中两个或以上文件属于同一功能时，必须建立对应的功能子目录，将这些文件统一放入该目录，避免不同功能的文件平铺混放。

## 需求与产物归档

- 当出现新需求、需求澄清或需求变更时，必须先在 `.spaces/` 中定位或创建对应的主题与功能目录，更新现行需求文档并同步受影响的设计、PRD、契约、UI、测试和交付说明，再开始实现；变更直接修改原文档并记录变更，不创建 `v2`、`final`、`最新版` 等平行正文。
- `.spaces/` 是需求与项目产物的唯一正式来源。UI 截图放入对应功能的 `ui/`，测试证据和工具按功能分类归档；不得再使用或重新生成 `artifacts/` 目录。

## 按需规则

根据当前任务匹配下表，在执行相关操作前读取对应规则；命中多项时分别读取。不要预先加载整个 `.agents/rules/` 目录；任务范围变化时补读新命中的规则。

| 适用条件                                                       | 规则文件                              |
| -------------------------------------------------------------- | ------------------------------------- |
| 新增、修改或重构前后端代码                                     | [代码设计](.agents/rules/代码设计.md) |
| 定义或调整前后端接口类型、返回类型，或新增、修改、抽取公用方法 | [共享代码](.agents/rules/共享代码.md) |
| 出现任何新需求、需求澄清或需求变更，或新增／更新需求、设计、PRD、契约、UI、测试与交付产物 | [需求与设计文档](.agents/rules/需求与设计文档.md) |
