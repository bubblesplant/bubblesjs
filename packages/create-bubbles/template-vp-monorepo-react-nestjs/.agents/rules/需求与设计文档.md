# 需求与设计文档规则

## 正式来源

- `.spaces/` 是本项目需求、设计、PRD、技术契约、UI 产物、测试报告和交付记录的唯一正式来源（Single Source of Truth）。完整规则见 [文档规范](../../.spaces/文档规范.md)，目录索引见 [项目空间文档索引](../../.spaces/README.md)。
- 不再使用 `artifacts/` 保存或生成项目产物，也不在其中保留导航副本；历史内容应迁入所属 `.spaces/` 功能目录，生成脚本的输出路径也必须同步迁移。
- 临时目录、聊天记录和代码注释不得保存上述文档的正文副本；聊天内容只能提炼为正式需求、设计、契约或待确认事项。
- 开发、评审、联调和测试引用文档时，必须以 `.spaces/` 中的当前内容为准。

## 分类与目录

- 一级主题目录统一使用 `<序号>.<主题>/` 命名，例如 `.spaces/01.企业级项目级/`；序号用于稳定排序，主题名应能准确概括业务范围。
- 新增、移动、合并或重命名一级主题与主要功能目录时，必须同步更新 `.spaces/README.md` 的目录索引、状态和相关决策链接。
- 同一功能只有一个文档时可直接放在所属主题目录；同一功能存在两个或以上文档、截图或其他产物时，必须建立功能子目录集中管理，例如 `.spaces/01.企业级项目级/组织架构/`。
- 功能目录内优先使用清晰、稳定的名称：`需求文档.md`、`设计方案.md`、`技术契约.md`、`测试报告.md`、`交付记录.md`。不要把文档阶段、日期或人员姓名写入文件名来制造副本。
- UI 原型、截图、标注图和相关说明统一放在对应功能目录的 `ui/` 子目录；文件名应能说明页面或场景，必要时在同目录补充索引说明。
- 跨主题内容应选择一个主归属目录，其余位置使用相对链接引用，不复制正文。

## 新需求与需求变更

- 收到新增、澄清或变更需求时，第一步必须定位并更新对应的 `.spaces/` 主题、功能目录和现行文档；没有目录时按本规则创建。需求、设计和契约同步完成前，不得先开始实现并把文档留到事后补写。
- 新需求应写入对应功能的正式文档，并明确目标、范围、业务规则、关键流程、权限边界、数据约束、验收标准以及仍待确认的事项。
- 需求变更必须直接修改原文档中的现行结论，同时在原文档的“变更记录”中记录日期、变更摘要、影响范围和决策原因；不得仅在文末追加互相矛盾的新结论。
- 禁止创建 `v2`、`v3`、`final`、`最终版`、`最新版`、`新方案` 等并行正文副本。需要保留历史时依赖版本控制；只有确有独立业务语义的方案才可单独建文档，并写明与现行方案的关系和状态。
- 澄清后被废弃的规则应从现行正文删除或明确标注为“已废弃”，不能继续以当前规则的口吻存在。

## 需求、设计与契约同步

- 开发前必须确认需求文档和技术契约已同步到当前决策；涉及接口、数据模型、权限、状态流转或跨端协作时，不得只改实现而遗漏文档。
- 需求文档描述业务目标和验收标准；设计方案描述交互、领域设计和技术取舍；技术契约描述可供实现与联调使用的字段、接口、错误、权限及兼容约束。三者不得互相冲突。
- 需求变化影响设计、契约、UI、测试或交付说明时，必须在同一任务中同步更新所有受影响文档，并检查引用它们的链接和状态说明。
- 尚未确认或尚未实现的内容必须明确标注状态，不得写成已经生效的事实；旧契约与当前决策冲突时，应先修正或标记失效后再据此开发。

## 链接与引用

- 仓库内 Markdown 文档优先使用相对链接，链接目标必须指向 `.spaces/` 内的正式文件或仓库内真实存在的实现文件；移动或重命名文档后必须同步修复所有引用。
- 文档应引用一个权威来源而非复制大段内容。确需摘要时，应标明摘要性质并附正式来源链接。
- 外部链接应说明用途和来源；会失效、需要权限或仅供参考的链接，应在附近注明限制。
- 提交前应检查旧路径、重复正文、失效相对链接、`artifacts/` 残留，以及仍会向 `artifacts/` 输出文件的脚本或命令。

## 对话决策留存

- Codex 对话、评审讨论和口头澄清中形成的有效需求，必须提炼进所属功能的现行文档；跨轮次的重要决策可在同目录维护 `决策记录.md`。
- 不把原始聊天全文保存为项目文档。决策记录只保留日期、结论、状态、原因、影响范围和正式文档链接；后续推翻旧结论时，直接修改原文档并标明替代关系。

## 敏感信息边界

- 文档、截图和示例不得包含真实密码、访问令牌、密钥、Cookie、连接串、私有证书、验证码、个人身份信息或未脱敏的生产数据。
- 账号、手机号、邮箱、企业名称、项目名称和业务数据应使用明显的虚构值或脱敏值；截图入库前必须检查界面、地址栏、终端输出和开发者工具中的敏感信息。
- 需要说明配置项时只记录变量名、用途和获取方式，不记录真实值；敏感配置应由受控的密钥或环境变量机制管理。
