# 交互状态样式

- 新增或修改 `hover`、`focus`、`focus-visible`、`active` 等纯视觉交互状态时，默认保持元素及相邻内容的布局尺寸和位置稳定；状态切换不得仅为装饰而改变宽高、边框宽度或样式、`padding`、`margin`、定位、`display`、字体大小或 `font-weight` 等可能影响布局的属性。
- 边框在初始状态就预留相同宽度和样式，可使用透明颜色；背景、阴影等装饰也应在初始状态定义完整层，并通过透明颜色或独立装饰层的 `opacity` 隐藏。状态变化优先只调整 `color`、`border-color`、`background-color`、阴影颜色或装饰层的 `opacity`，不要在交互时临时增加边框或改变阴影的偏移、模糊半径、扩展半径。
- 背景与阴影的颜色变化通常只需重绘，但阴影可能扩大绘制区域或增加绘制成本；`opacity` 与 `transform` 在合适条件下可能进入合成阶段，不能保证所有浏览器、元素和场景都只发生重绘或合成。
- `transform` 通常不引发布局重排，但平移或缩放仍可能造成可见位置、尺寸变化。页头按钮、导航、菜单触发器等需要稳定对齐的控件，不要仅为悬停反馈添加位移或缩放；有明确产品动效需求时按下述例外处理。
- 过渡必须显式列出需要变化的属性，避免使用 `transition: all` 将布局或浮层定位属性一并加入动画。键盘焦点提示须清晰可见，可使用不占布局空间的 `outline` 或初始状态已预留的装饰层。
- 折叠展开、拖拽、尺寸调整等本身需要改变布局的交互，以及明确要求位移或缩放的动效可以例外；应在相邻注释或相关设计记录中说明实际需求，并验证不会造成非预期的抖动或遮挡。不要以本规则取消必要的交互行为。
- 验证交互前后及过渡中的控件和相邻内容位置、尺寸，覆盖鼠标和键盘触发。若报告抖动或需要确认渲染开销，结合浏览器性能记录或布局测量确认原因，不仅凭 CSS 属性名宣称已消除重排。
